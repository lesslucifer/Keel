E-SEED2.W7 · Opus-only worker policy

The launcher starts workers on opus only, with an effort of medium or high. A new router DEC and project-router record the owner's ruling of 2026-11-09. The shipped keel-router skill stays generic and points at the project's policy.

Requirement

scripts/router-worker.sh spawn|resume accepts only the model opus and refuses any other model with a message naming the opus-only policy. It takes an optional --effort medium|high (default high) and passes it to claude -p as --effort. Any other effort value is refused. After this WU, no tracked file outside docs/work/ and the lessons' history offers a non-opus worker model.

Maps to

Epic E-SEED2.W7 (open point 6, open question 7) · UC-ROUTE, worker modes and launcher (use-cases/router.html) · lessons B7 ("they should use opus 5.5") · amends DEC-31 ("explicit model") and DEC-37 (launcher options).

Expected result

  • router-worker.sh spawn n <wt> <brief> sonnet, haiku, fable and gpt each exit 2 with model must be opus (worker policy, DEC-39). resume refuses the same way.
  • … opus --effort medium and … opus --effort high start a worker. Its argv carries --model opus --effort <level>, the run dir holds an effort file, and the RUNNING line shows effort=<level>. With no --effort, the effort is high. --effort low, max or a missing value is refused. The option combines with --permission-mode in either order, at most once each.
  • The router guard is unchanged. Its launcher shape ([A-Za-z0-9._/ -]+, scripts/router-guard.jq:30) already admits --effort high.
  • git grep -n -i -E "sonnet|haiku|fable" outside docs/work/ hits only lessons.md B7 (history) and the refusal tests in tests/router.rs.
  • The new DEC is in docs/decisions/router.html and the index. project-router "Workers" states opus with medium/high effort. The keel-router skill and its .claude/skills/ mirror defer to "the project's model policy".
