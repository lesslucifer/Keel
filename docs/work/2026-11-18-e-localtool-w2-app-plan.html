The problem

You chose Electron for the app. Nobody has yet said how its parts read keel, git and the worker sessions. One part is tricky: the gate writes a small record when it passes, so the app cannot simply run it to show its result. W2 answers these questions on paper, with a source for every outside fact, before any screen or code depends on them.

Details

How the facts are checked

  • Electron: its official docs (the process model, the security checklist, alerts, updates, signing) and its release schedule. Each fact gets the page's link, the date read and the Electron version it applies to.
  • Claude Code: its official docs (the command line, background sessions, messages between sessions), each with link and date. A fact today's scripts already rely on also cites that script and line, such as the watchdog in scripts/router-worker.sh. The worker never runs claude itself.
  • DeepSeek Harness: its docs, with link and date, or "not checked".
  • keel and git: the code at e00f1ec, by file and line, as in W1. Each path is checked with git cat-file -e e00f1ec:<path>.
  • Three marks per fact: used today (a script relies on it), documented (a dated source says so), not checked. Only the first two back a recommendation.

Tests and checks

Unit and integration: waived. W2 changes only docs/work/, so no code path changes. The range is exempt from test, review and doc notes. Your sign-off still runs.

The checks the worker runs instead, with their raw output in the result's evidence:

  1. Every question answered. Q1 to Q9 each have one recommendation and a why.
  2. Every need placed. W1's needs n1 to n7 each land on a part, or the doc says why not.
  3. Every outside fact sourced. Each has a link and a date read, or is marked "not checked" and backs no recommendation.
  4. Local sources exist. Every repository path cited passes git cat-file -e e00f1ec:<path>.
  5. The app judges nothing. Every command the app would run writes nothing to git, or is named with what replaces it (Q3).
  6. Doc check. keel verify-doc is green on the result.
  7. Scope. git diff --name-only e00f1ec..<tip> lists only docs/work/ files.

Sign-off and merge

  • The WU reaches epic/E-LOCALTOOL as a pull request, opened by the router. Your approval of it signs it (the github tier), and auto-merge merges it.
  • The result report is in the range, so the sign-off attests its bytes.
  • GitHub's flow is still today's flow. W5 plans its retirement; nothing about it changes here.
