E-RGUARD.W3 · The inbox channel

A worker's report wakes the router. No reminder, no schedule.

T3 · WU plan · 2026-11-14 · epic E-RGUARD · WU E-RGUARD.W3 · base epic/E-RGUARD at cd90c16

The problem

On DeepSeek Harness (DSH) a worker cannot message the router, so a finished WU sits in a transcript until a clock or the owner wakes the router. This WU gives the router a file inbox: a worker posts one short report, the router's armed watcher prints it at once, consume is the ack, and the reminder that delivered reports is deleted.

Epic E-RGUARD, W3 · UC-ROUTE-5 (a DSH worker's report) and UC-ROUTE-6 (the posture and its wake).

A report, in steps

  1. The router arms sh scripts/router-inbox.sh watch 6600 as a background command.
  2. A worker runs sh scripts/router-inbox.sh post e-rguard-w3 REPORT "W3 done: tip 1a2b3c4". The file appears at once; the command prints POSTED id=….
  3. The watcher wakes inside its poll, prints the report and its body, and exits 0.
  4. The router runs sh scripts/router-inbox.sh consume <id> and sees CONSUMED.
  5. The router acks the worker with worker_send … "ack <id>", which names the same id.

The work

1 · The script

In short: the prototype from the 2026-11-14 probe, cleaned to repo style and POSIX sh. Five verbs; read-only except the inbox itself.

  • scripts/router-inbox.sh: init · post <from> <kind> <text>… · watch <seconds> · consume <id> · status.
  • The inbox resolves from the git common dir, so a copy in any worktree writes the main checkout's inbox; ROUTER_INBOX_DIR overrides it for tests.
  • No delete verb and no redirect into a system path: the host's auto review denies a script that carries one. Cleanup is the owner's manual move.
  • Junk files and symlinks are skipped and never followed; the header id must match the file name; kind is a closed set.

2 · The test

In short: tests/router_inbox.rs spawns the shipped script through its process boundary, one temp inbox per case. The prototype's 27 checks are the contract.

  • Post, immediate delivery, header plus body, order, timeout, idempotent consume, two concurrent writers.
  • Junk and a symlink skipped, a forged header skipped, a long body bounded, a read-only inbox directory.
  • A killed watcher loses nothing; a symlink in the inbox is refused by consume.
  • Hermetic: ROUTER_INBOX_DIR under tempfile, no network, no repository path.

3 · The rule text

In short: the shipped skill says a worker posts and the router's watcher wakes it; no text may claim a timer is allowed.

  • skills/keel-router/references/worker-ops.md: a new section for the report channel; the wake checklist's fleet half becomes the armed watcher.
  • skills/keel-router/SKILL.md: the transport table's Report row and the "no heartbeat" bullet name the post, the watcher and the ack.
  • skills/keel-router/references/brief-skeleton.md: a worker's report is a post, with the inbox path and the id rule; the .router-ready.<name> marker idea is not used.
  • Both skill trees byte-identical in the same commit.

4 · The decision

In short: one row in docs/decisions/router.html (DEC-57) names the channel, why a push channel beats a poll on DSH, and its limits.

5 · Claude Code

In short: the router guard admits the router's own init, watch, consume and status as plain-word shapes; post stays denied. The router never posts.

A worker posting on Claude Code needs the launcher's sandbox to allow writing the inbox. That widens the bound DEC-46 sets for every worker, so it is out of scope here and is reported as a follow-up.

6 · The config proposal

In short: .keel/config.toml lists each scripts/router-* file in rule_bearing by name. This WU stages one added name, scripts/router-inbox.sh, so a later edit to the channel cannot land unreviewed.

The contract

CommandObservable
initREADY dir=… read=…, exit 0
post <from> <kind> <text>…POSTED id=<epoch>-<random>, exit 0; the body is text or stdin; 4,000 bytes at most
watch <seconds>At once, then every poll: one MSG id=… from=… kind=… age=…s bytes=… line and the indented body, exit 0; TIMEOUT kind=inbox exit 1 at the bound; NO-INBOX exit 2
consume <id>CONSUMED id=… once, then CONSUMED-ALREADY id=…, exit 0; MISSING exit 2
statusINBOX pending=<n> oldest=<id|none> read=<n> orphans=<n>
bad inputexit 2 with a one-line reason, before any write

  • No shipped text claims a reminder, schedule or loop for the router; the report timer is gone.
  • The rule-bearing changes are staged, never committed by this session.
