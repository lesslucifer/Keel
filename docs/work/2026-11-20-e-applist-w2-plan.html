E-APPLIST.W2 · The watchdog's lines

Every five minutes the watchdog also writes down what changed about each worker, and that the router is alive.

WU plan · v1 · 2026-11-21 · T3 · Keel · W2 of the epic plan · its data file sits beside this page

The problem

The app will show each worker and warn you when the router goes quiet. Only the watchdog sees the workers, every five minutes. Today it tells the router and writes nothing down, so the app has nothing to read.

What you get

WhenTodayAfter
A worker changesOnly the router hears itOne line in the update log for that worker
Nothing changes—One short "router alive" line, nothing more
A worker ends—One line removes it
The log cannot be written—The router's message comes exactly as today

How it works

  1. The watchdog wakes. It reads the workers as it does today and sends the router the same message.
  2. It compares each worker with the log's current state: its state, what it waits for, its session, branch, last commit, uncommitted files, last activity.
  3. Worker A made a commit: one line for A. Worker B did nothing: no line.
  4. Worker C has ended: one line removes C.
  5. Last, one "router alive" line. After three silent ticks the app says the router is not heard.
  6. After a router restart the log starts empty, so the next tick writes every worker again.

How you approve

  1. Tests first, written to fail.
  2. One rule file, staged alone: the worker launcher, which holds the watchdog. You commit it with one typed command.
  3. A fresh worker re-checks that file and the tests on your commit.
  4. The result report, the code review, then your sign-off and merge.

How you'll know it worked

  • A first tick writes each worker, then the "alive" line.
  • A quiet tick writes only the "alive" line.
  • One changed worker writes one line; an ended one is removed once.
  • A blocked or broken log leaves the router's message byte for byte as today.
  • Tests, lint and the doc check are green.
