W2 · The doc check runs at the write

The shipped standard tied the doc check to one host's hooks. It now says the check runs at the write on any host, and that a review or a merge is too late. This report says what landed, what deviated, and what proves it.

T3 · wu-result · 2026-11-14 · E-DSH.W2 · wu/E-DSH/w2-doc-check · tip a3c8b69

What landed

Delivered. The rules a host reads now say the doc check runs when a doc is written, on a host with no shell hooks too. The plugin's contract is recorded; its code is not in this repository.

  • After every first-party write or edit of a doc under the docs root, the host runs keel verify-doc <path>. A red doc returns its problem lines with the failed write, so the agent fixes it in the same turn.
  • At turn end the host runs keel verify-doc over all docs and steers the problems back: the turn takes another step instead of closing.
  • Exit 0 is silent, and a draft is silent by construction. Flipping to ready is the checkpoint.
  • The no-substitute rule is stated: a review or a merge is too late and no substitute.
  • The plan skill no longer names one host as the trigger. It says the trigger is the write, and that a host without shell hooks runs the same check through a plugin.
  • The contract is recorded for that plugin: tools/post-execute returns {kind:'block', feedback} after the bytes have landed — it fails the write's result, it cannot prevent the write — and agent/turn-stopping with agent.steer() keeps the turn open.
  • The plugin lives in its own repo in the desktop-dsh project. This repository carries the contract and the install line, not the code.

In a real session, in steps

  1. A worker on a host without shell hooks writes a result doc and leaves out follow-ups.
  2. The bytes land. The plugin's tools/post-execute runs keel verify-doc on that path.
  3. The check exits 1 with missing item "follow-ups". The plugin returns {kind:'block', feedback}, and the write's result becomes a failure carrying that line.
  4. The worker adds the item. The next write exits 0 and says nothing.
  5. If a doc is still red when the turn ends, agent/turn-stopping refuses to close it: agent.steer() sends the problems back and the turn takes another step.
  6. Notes, review and the merge run as before. The merge never checked doc form, and still does not.
