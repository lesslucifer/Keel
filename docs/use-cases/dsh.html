Use cases: DeepSeek Harness

What a Keel project must do for a DeepSeek Harness session: hand it the skills through one shared root, check a doc at the write, give a router its workers and their transcripts, and state the permissions an unattended session runs under.

T2 · use-cases · current truth (updated in place) · 2026-11-14 · Keel · distilled from E-DSH (W1–W3) and its plan

Contract level only: trigger, expected behaviour, what counts as failure. The standard is the skills (skills/); the why lives in DEC-53, DEC-54, DEC-55 and DEC-56. Ids are never reused or renumbered.

UC-DSH · the same rules on DeepSeek Harness

DeepSeek Harness (DSH) is an agent host beside Claude Code. A project holds no DSH-specific file: init plants one shared skill root, the doc check comes from a plugin in the DSH profile, and the router learns the host's transport from one table in its skill.

One shared root for the rules, one write-time check, and a worker the router reads instead of a message.

UC-DSH-1 init gives DSH the skills through one shared root

Triggerkeel init in a repo of any host, then a DSH session in that repo or in a worktree of it.
ExpectedThe six keel-* skills are written once, under .claude/skills. Init then plants .agents/skills as a relative link to ../.claude/skills, so a DSH session's skill catalog lists all six and each load resolves its base directory under .agents/skills/. The link is relative, so a git worktree add checkout carries it and it resolves there too. .agents/ is created when missing; a real .agents/skills directory, a regular file, an unreadable link or a link aimed elsewhere is kept and reported, never replaced; a symlinked or non-directory .agents gets nothing planted, because a relative target resolves only from a real .agents at the repo root. A second run prints unchanged .agents/skills (-> ../.claude/skills). The link rides the first commit: the hand-off's git add names .agents. The hand-off also prints the three DSH profile install lines (Auto Review, worker sessions, doc gate) and says a plugin lives in the DSH profile, never in the project.
FailureA DSH session on an adopted repo with an empty or unreadable skill catalog; init replacing a project's own .agents/skills; a link that resolves in the main checkout and dangles in a worktree; a second run that changes the tree; a plugin file written into the project.

UC-DSH-2 the doc check runs at the write on a host without hooks

TriggerA first-party write or edit of a doc under the docs root in a DSH session, with the doc-gate plugin installed in the profile.
ExpectedDSH has no shell-hook surface, so the plugin runs the same two checks at the same points. On each write or edit, tools/post-execute runs keel verify-doc <path> after the bytes land: exit 0 is silent, and a draft is silent by construction. A red doc returns {kind:'block', feedback} with the problem lines, so that write's result is a failure and the agent fixes it in the same turn. At turn end, agent/turn-stopping runs keel verify-doc over all docs and calls agent.steer() with the problems, so the turn takes another step instead of closing. The check fails the write; it cannot prevent it, and no post-write surface could. A review or a merge is too late and no substitute: the merge reads doc facts, never a document's form.
FailureA red doc's write reported as a success; a turn that closes with a red doc under the docs root; the check treated as a review or merge step; the plugin's code committed into the project instead of installed in the profile; a draft's problems reported as red.

UC-DSH-3 a DSH router's workers and their transcripts

TriggerA router session on DSH that starts, steers, reads or stops a worker.
Expectedworker_spawn starts the worker with the worktree as its workspace, the brief as its prompt and a handle as its name; a session's directory never changes, so the worker stays in its worktree. A follow-up is one worker_send, which runs after the worker's current turn. A subagent is not a worker: it inherits the router's directory and works in the router's checkout, so it is only ever a short read-only check. A worker sends no message; its report is its transcript, read with worker_output at every wake and before every ask, and its claims are verified against git like any other report. worker_list, worker_status (running, idle, ready, stopped) and worker_stop (idempotent; a stopped worker is never revived) give the fleet view, the state and the end. The persona is the worktree's AGENTS.md, the skills through the shared root and the brief: DSH has no project-scoped agent definition to select and no per-worker preset, so the brief carries the goal, the hard rules and the report protocol in full.
FailureWorker work dispatched to a subagent that lands in the router's checkout; a router waiting for a message a DSH worker never sends; a transcript claim relayed without a check against git; a stopped worker revived; a worker started outside its own worktree; a brief that leaves the report protocol out.

UC-DSH-4 permissions for an unattended DSH session

TriggerA DSH session, router or worker, in a Keel project.
ExpectedEvery Keel DSH session runs under Always Auto Review, fixed by the owner: a medium call (an add, a commit, minting a request) runs, a high-risk call is denied, and no approval prompt is offered, so a denial is final. A denial is surfaced with the exact command, never retried, never handed to another session. A worker in a linked git worktree runs danger-full-access because the git directory lives outside it; one in a plain directory runs workspace-write: the workspace root is the bound. The preset is a session fact and settings are user-level, so a project cannot set it and the router passes none per worker. The preset is never the owner's approval: keel mr, a merge, a push and a tag stay the owner's.
FailureA session whose approvals are off with nothing deciding its calls, so every medium call is rejected; a denial retried or laundered to a peer; a worker granted a scope wider than the workspace it was started in; a preset treated as the owner's sign-off; a project trying to pin the preset for its own sessions.
