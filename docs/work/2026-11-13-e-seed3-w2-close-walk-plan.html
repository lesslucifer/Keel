The problem

An epic's last commits carry evidence written for the whole epic. Two checks judge those commits alone, so that evidence looks wrong and they refuse.

  1. After an epic merges into main, pushing its branch is refused.
  2. When a review fix follows the archive commit, the epic gate refuses the archive commit. Today you rewrite its evidence from a separate checkout.

A real case (E-CRCAP)

  1. An epic closes: its archive commit gets the epic's test and doc evidence.
  2. The epic review fails. A fix commit follows.
  3. The epic gate now walks the archive commit as one plain commit. Its doc evidence lists the whole epic's docs, so it is red.
  4. After this WU: the archive commit changes no code and its evidence names the epic's range, so it is judged over that range, and is green.

Terms

WalkThe check that re-judges each commit and merge on a branch. The push runs one over what it sends; the epic gate runs one over the whole epic.
Epic-range evidenceTest and doc evidence written while the commit was the epic's tip, so it covers everything since the epic left main.
Close commitA plain commit judged by its epic-range evidence, as below.

The work

In short: the evidence already names the range it was written for. The walks read that range: when it is the epic's, they judge the commit over the epic, with the checks the epic gate runs on evidence. Review and sign-off stay at the merge into main.

  1. B23, landed work: the push of an epic branch skips a plain commit already on main. It landed through a gated epic merge.
  2. B23, the pushed tip: a plain commit whose evidence names the epic's range, pushed as an epic branch's tip, is judged over that range: 1·notes, 2·manifest (the e2e layer) and 6·doc-note (the doc list and archive lineage; the tracked-doc layout stays the epic tip's, since a commit before the archive still tracks working docs).
  3. B20, inner commits: in both walks, a plain commit that changes no code and carries epic-range evidence is judged the same way. A commit that changes code stays a commit.
  4. The rule that tells the two kinds of evidence apart: every test or doc note on the commit names, as its base, where the commit's branch left main, and that is not the commit's parent.
  5. keel-workflow §4's check 7 row and §7's pre-push row say so. Rule-bearing: your keel mr commit.
  6. DEC-18 and UC-GATE-3 are amended at the epic close, with the wording this WU's result records.

Details

A plain first-parent commit on an epic branch that carries epic-range test and doc notes is judged by checks 1, 2 and 6 over the epic's range, in the push walk when it is the pushed tip and in both walks when it changes no code; a push of an epic branch skips plain commits already on main; every other plain commit is judged as a standalone commit, as before.
