Three setups you did not expect no longer change what the gate or the tests see. Each has a guard and its regression test.

T3 · WU result · 2026-11-14 · Keel · branch wu/E-SEED3/w3-odd-setups off epic/E-SEED3 99f72e8 · WU plan · epic E-SEED3 plan, block W3

What happened

Delivered as planned. A push that inherits an index path leaves your real index alone. A WU signed off or verified by a bare commit id is measured against the epic its branch holds, or refuses and asks for the target; it is never a guess of main. No test spawn reads your global or system git config. One thing changed from the brief: no owner sign-off commit is staged, because no rule-bearing path changes here (see Deviations).

Recommendation: the epic close applies those amendments and the two keel-workflow rows in one owner keel mr commit.
  • B10 is proven at the spawn, not by running a whole keel fixture under a hostile config. The guard spawns git through tests/common with a hostile ~/.gitconfig and a hostile GIT_CONFIG_SYSTEM and asserts neither is read; the whole suite then runs under the same isolation. A repository's own config still applies, which the fixtures rely on.

Distillation

Nothing lands in T1/T2 at this WU. The E-SEED3 close takes this wording.

  • UC-NOTE-1 (docs/use-cases/workflow.html), appended: "A target is read from the branch a tip sits on. A tip that names no local branch - a bare commit id, HEAD on a detached checkout - is resolved from the branches that hold it, or refused; the writer is unaffected because it always writes on HEAD's branch."
  • UC-GATE-2 (docs/use-cases/workflow.html), appended: "A WU tip given as a bare commit id is measured against the epic branch a local wu/<e>/… branch that holds it names, else the one local epic/<e> branch that holds it; no holder, or two epics, is a refusal whose fix line asks for --target. The gate never guesses main for a bare id."
  • DEC-15 (docs/decisions/workflow-gates.html), appended to Choice: "A tip that names no local branch (a bare commit id, HEAD on a detached checkout) is resolved before the naming rule: the epic of a wu/ branch that holds it, else the one epic/ branch that holds it; no holder or more than one epic refuses, asking for --target. main is never a guess for a WU. The note writer needs no such resolution: it always writes on HEAD's branch (owner ruling 2026-11-14, E-SEED3.W3)." Rejected, added: "taking the first holder git prints; falling back to main when the tip is an ancestor of main; searching remote-tracking branches, since the checkout cannot measure what it does not have."
  • DEC-41 (docs/decisions/workflow-gates.html), appended to Choice: "The push check's scratch git worktree add and worktree remove strip GIT_INDEX_FILE, so a hook that pushes, or a shell that exported it, can never have the pushed tree written into the caller's real index; keel's other git calls keep it, as above. Every test spawn in tests/common also sets GIT_CONFIG_GLOBAL=/dev/null and GIT_CONFIG_NOSYSTEM=1, so the suite reads no developer global or system config (B10); a repository's own config still applies." Rejected, added: "stripping the config selectors from keel's own calls (they select a scope, not a repository)."
  • keel-workflow §1, the "Branch names carry the target" bullet: append "A tip that names no local branch (a bare commit id) has no name to read: the gate takes the epic of a local wu/<e>/… branch that holds it, else the one local epic/<e> branch that holds it, and refuses asking for --target when none or more than one epic holds it. It never falls back to main."
  • keel-workflow §4, the keel verify-dod wu <tip> block's comment: # target from the branch name, else main becomes # target from the branch name; a bare tip's holder branches, or a refusal; --target overrides.
