E-APPLIST.W5 · Read, watch and alert

The app learns what git and the router say, keeps it current, and alerts you at your desk.

T3 · WU plan · 2026-11-22 · Keel · its data file, 2026-11-22-e-applist-w5-plan.yaml, sits beside this page · the epic: E-APPLIST plan · the design: local-app.html

The problem

The router already writes what waits on you to its update log, and git holds the sign-offs and merges. The app reads neither. It cannot alert you, and the list screens have nothing to show.

What you get

  • A macOS alert for each alert the router sends. Never the same one twice, even after a restart.
  • Clicking it, or a Keel link from Telegram, opens the app on that work unit.
  • The app knows when the router has been silent for 15 minutes.
  • Everything the list needs, kept current within about a second.

How it works

  1. The app reads your project's branches, sign-offs, merges and worktrees from git. It only reads.
  2. It reads the router's update log line by line. A gap, a router restart or a half-written line each has one fixed rule.
  3. It watches git and the log for changes, waits a second for the burst, then reads again. Once a minute it reads anyway.
  4. Each new alert line becomes one macOS alert. The app records it first in its own folder, so it never shows twice.
  5. A Keel link is accepted only in one exact shape. Anything else is refused and opens nothing.

What it makes

  • The reader, the watcher and the alerter in the app's core, each tested without Electron.
  • One new question the window can ask ("what is the current view?") and one new signal ("it changed").
  • The browser view's sample data for both.

The list itself, its screens and Open are the next part. Nothing is packaged.

How you'll know it worked

  • With the app run from source, an alert line shows one macOS alert. Its click opens the window.
  • After quitting and starting the app again, the alert does not come back.
  • The tests drive the real router script on a temporary project: restarts, gaps, silence, git changes and a refused link.
  • Keel's usual checks run those tests on every push. Nothing was built for testing.
