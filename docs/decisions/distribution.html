Decisions: distribution and adoption

Why Keel is one CLI that carries its own rules, how a project adopts it, and how Keel itself is run.

T2 · decisions · append-only · 2026-11-08 · Keel · DEC-1 – DEC-12 · distilled from E-SEED (seed plan Q1–Q14, rulings R1–R25, W5–W7 open points)

Append-only. A reversal marks the old record superseded by DEC-m and adds a new one. "Lineage" names where the decision was first made (E-SEED seed plan question, rulings-log row, WU open point; the working docs are archived out of git, history keeps them) or the Trawler decision it ports.

DEC-1 · One project-agnostic Rust CLI, extracted from Trawler

ContextTrawler's epic → WU → commit workflow (notes, gates, review, sign-off, distillation) was hard-wired to one Rust repo (cargo xtask, fixed paths). Each new project would otherwise copy it by hand and drift.
ChoiceKeel (~/Documents/proj/misc/Keel, public GitHub repo) is a Rust port of the xtask code and its tests, with every Trawler/cargo assumption moved into .keel/config.toml. One profile, every gate (the collapse rule covers small work). Test counting by per-extension adapters (Rust, TS/JS, Python, Go) plus a config regex. Trawler itself moves onto Keel in a separate Trawler epic after Keel's first release; E-SEED changed no Trawler file.
ConsequencesThe config and the test adapters are the only per-language surface.
LineageE-SEED Q1, Q2, Q5, Q7, Q13, Q14.

DEC-2 · The rules ship inside the binary; no Claude Code plugin

ContextE-SEED Q4 first put the adopting project's rules in a Claude Code plugin's skills. That meant a second install step, a second version (plugin skills against the binary's gate) and rules the project does not control.
ChoiceThe skills are embedded in keel (include_str!, one list in src/init.rs) and keel init writes them into the project's .claude/skills/keel-*, committed and versioned with the project's gate. Never user-level ~/.claude/skills. Skill directories carry a keel- prefix (avoids the built-in code-review collision); source directories have the same names as install directories. project-router stays unprefixed and project-owned.
RejectedPlugin / marketplace distribution (original Q4). Symlinking Keel's own .claude/skills/keel-* to skills/ (untested whether Claude Code loads symlinked skills).
ConsequencesKeel's repo holds its skills twice (skills/ source, .claude/skills/ copy); a self-hosting test fails when they drift.
LineageR25 (reverses Q4); W7 v2 open points 9, 10, 15. Supersedes the plugin-based W7 plan (orphaned branch worktree-agent-a6381e6d3c5019ecc).

DEC-3 · init never clobbers; skill upgrades ask per file

ContextUC-INIT-1 requires idempotence and never overwriting an edited file without asking, while a re-run init is also the upgrade path for skills.
ChoiceProject-owned files (config, AGENTS.md, .codex/hooks.json, project-router): create if missing, otherwise keep and report. keel-* skill files: missing → created; differing → one [y/N] prompt per file on every run, TTY or not; end of input = N (keep, print "differs", exit 0); -f/--force overwrites without asking. Files no longer shipped or added by the user are reported as extra, never deleted. AGENTS.md is outside the upgrade flow (Claude Code only for now). .gitignore lines are appended, never rewritten.
RejectedA three-tier --yes/--no/TTY design; a .keel/skills.lock to tell hand edits from upstream updates (possible later, backlog B7); non-zero exit when a prompt cannot be answered.
ConsequencesCI and scripts must pass -f to update skills.
LineageW6 open point 4; W7 v2 open points 2–5, 14; R25 (5).

DEC-4 · One AGENTS.md as T0; skills only in .claude/skills

ContextTrawler kept CLAUDE.md plus .agents/skills symlinks for Codex (Trawler DEC-52).
Choiceinit writes a single AGENTS.md as the T0 file, no CLAUDE.md (Claude Code 2.1.277+ reads AGENTS.md when no CLAUDE.md exists; Codex reads it natively); it warns when a CLAUDE.md exists. Skills live only in .claude/skills: no .agents/skills symlink, no Codex skills parity. .codex/hooks.json is still written as a real file calling the installed scripts (unguarded, as the template has it).
RejectedThe .agents/skills → ../.claude/skills symlink: Claude Code does not read .agents/skills/ (docs plus a live test).
LineageQ8 (changed from the proposed default); R18; W6 open points 1, 5; W7 v2 open point 16; Trawler DEC-52.

DEC-5 · Harness hooks are merged into settings.json, guarded, fail-open

ContextWithout a plugin, the PostToolUse/Stop doc-verification hooks must come from the project's own .claude/settings.json, which may already hold user settings (Keel's own has the router agent and a permission whitelist).
ChoiceA JSON merge, never an overwrite: a hook group is appended only if its exact command is absent anywhere under that event; invalid JSON is left untouched with a warning; key order kept (serde_json preserve_order, pulls in foldhash). Each command is guarded: it runs <git-common-dir>/keel-hooks/verify-doc-* only if present, else exits 0. The scripts themselves exit 0 when keel is not on PATH; git hooks fail closed instead.
ConsequencesA committed settings file is inert until keel hooks install runs; a missing binary never breaks a session (making the harness hooks loud is a one-line change).
LineageW7 v2 §3, open points 8, 11; W5 open point 2.

DEC-6 · Install channels and the binary name

ContextQ3: adopters get prebuilt binaries plus cargo install, and init prints the install line. The crates.io name keel is taken by an unrelated crate; the npm package keel (keel.so) also installs a keel binary.
ChoiceToday: cargo install --git https://github.com/lesslucifer/Keel, the only hint the CLI prints (never cargo install keel). Planned: GitHub Releases, shell installer, npm @lesslucifer/keel and a Homebrew tap from one cargo-dist config (deferred, backlog B1). No crates.io publish. The binary stays keel: the PATH collision with keel.so is an accepted risk, stated in docs/install.html.
LineageQ3 (refined by R25); R25 (3), (4); W7 v2 open point 12.

DEC-7 · Unix only

ChoiceNo Windows support and no Windows work unit: the CLI uses Unix permissions, sh -c and #!/bin/sh hooks.
LineageSeed plan non-goals; owner ruling 2026-11-08 (W7 v2).

DEC-8 · Bootstrapping: the policy lands once, ungated

ContextAfter init, pre-commit refuses commits on main and the merge gate refuses a target with no committed config, so the config can land neither directly nor by merge. Keel had the same problem for itself.
ChoiceFor adopters, init prints a one-time git commit --no-verify -m "keel init" on main. For Keel, E-SEED ran on branches without gates and W7 was the last ungated merge, carrying Keel's own init output; the owner then installs the hooks (install, push, keel init, refused-commit probe, keel mr setup). Rollback: git config --unset core.hooksPath.
ConsequencesE-SEED's own seams carry no notes, so its epic gate needs walk_waivers on the record.
LineageQ12; W6 open point 3; W7 v2 open point 1.

DEC-9 · Config defaults and Keel's own policy

Choicecode_paths defaults to ["src/", "tests/"]; check commands are detected per language, otherwise a command that fails ("a gate that passes on nothing would be worse"). [paths] worktrees (default .claude/worktrees/) is gitignored by init so git add .claude cannot sweep in agent worktrees. The docs skeleton is directories only (no index docs: an htmldoc needs a server-minted id; no .gitkeep: a tracked T3 file). Keel's own rule_bearing adds skills/, templates/, .keel/, .claude/skills/, .claude/settings.json to the default, so init on Keel reports kept .keel/config.toml by design.
LineageW6 open points 12, 13; W7 v2 open points 7, 13.

DEC-10 · Docs: HTML only; plans do not gate dispatch

ChoiceProject docs are HTML via htmldoc, never markdown (AGENTS.md and skill files are infrastructure). Every WU gets a plan doc for the record and for distillation, but a worker is dispatched once the doc exists and dependencies are met; the owner reviews plans and results asynchronously through htmldoc comments. Owner rulings during an epic go into an append-only rulings log and then into this KB at close.
RejectedA per-WU plan-review gate before dispatch (tried early in E-SEED, then dropped).
LineageQ6; seed plan "Per-WU process".

DEC-11 · What the extraction left out

ChoiceDeferred to later optional work: the design pack (design flow, component design, design-review, gate check 9; tied to a React registry), tally --fleet and debug serve (the fleet block stays optional on cr/v1), the Secure Enclave signer (any ssh-agent key signs). Never: CI as a gate (a signal only, Trawler DEC-83), legacy schema readers.
LineageQ9; seed plan non-goals and Trawler inventory.

DEC-12 · Repo conventions: worktrees, and nothing unclosed on main

ChoiceThe main repo folder always stays on main; epic work happens in separate worktrees. No T3 doc, epic plan, or anything from an unclosed epic ever lands on main: an epic reaches main only at close, after its T3 docs are distilled and archived, as one epic merge. A file in another worktree is referred to the owner by full absolute path, never a relative link.
ConsequencesEpics landing in sequence conflict on .claude/settings.json and .gitignore; take the settings that hold the router config and re-run keel init on top.
LineageR1; R17; owner ruling 2026-11-08 (W7 v2 open point 6); W7 v2 open point 19.
