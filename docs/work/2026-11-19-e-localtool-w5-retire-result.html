P1 · The flow's pieces, and how the revert undoes them

In short: 68 files differ between main before the flow and main now. Five merges brought them, and nothing else landed on main in between.   • Decisions and use cases are not reverted. They are marked replaced, so their history stays. The two reference docs lose their GitHub parts.
  • Order inside the epic: settings first (row 14), or no push of main works. Then the code. Then each open epic merges main in.

Point 4 · Does keel re-check a past sign-off by its tier?

Yes, in two places. No open work unit reaches either. What would strand the open epics is plainer: keel as it was on 15 November refuses the github line and the github tier outright.

  1. On a push of main or an epic. verify-dod range (src/gate.rs range, line 720) judges the sign-off of each work-unit merge new to GitHub again, by the merge's first parent's signer list and the tiers in the checkout's config (src/mr.rs manual_review, line 791). Merges already on GitHub are skipped. Every approval-signed merge of the open epics was made on GitHub, so all are skipped.
  2. In the epic's walk. The walk (src/gate.rs walk, line 425) reads a work unit's sign-off only when that unit's review failed or is missing, to take an approval's cover (approval_cover, line 903). E-LOCALTOOL's W1 to W4 change only docs, so they need no review. E-DOCSPLIT's two code units, W2 (7cca9ff) and W3 (71bafcf), each carry a PASS review. The gate run today on both epic tips prints no walk failure and no "covered by the approval" line (Evidence).
  3. Nowhere else. The sign-off check judges only the merge at hand, never an earlier unit's.
  4. The real risk. At 8d48a44, src/mr.rs parse_roster (line 40) calls github: 5499546 lesslucifer malformed: a second word after the name. And line 73 refuses github in [mr] tiers as an unknown tier. Both open epics carry both, from main, until they merge main in. A work unit's own checkout carries them until it merges its epic. Each keel mr confirm or verify-dod that reads them would stop.

So the revert keeps keel reading the tier and the line (keep 3): no approval can sign, since the writer, the workflows and check 8's approval path are gone. The plan's exception was "keep reading past approvals". The code read shows no gate path needs that today, so only the reading of the line and the tier name is kept. Epic 2 removes it once both open epics are on main.
