Use cases: router

What a router session coordinating worker sessions must and must not do.

T2 · use-cases · current truth (updated in place) · 2026-11-08 · Keel · distilled from E-SEED (W6), E-ROUTER (plan, W1–W4, close review), E-ROUTERFIX and E-SEED2 (W7, W12)

The standard itself is the keel-router skill (skills/keel-router/); this file holds only the contract. Why the router is shaped this way: decisions/router.html (DEC-30 – DEC-37, DEC-39).

UC-ROUTE · routing

UC-ROUTE-1 the router coordinates, the owner acts

TriggerA router session coordinating worker sessions on a Keel project.
ExpectedIt verifies workers' claims against the repo, stages the owner's commands (sign-off, merge, push, tag) for the owner to run, and never signs (keel mr), merges or pushes for the owner. In the turn it stages an owner action it arms a read-only watch for it in the background (Keel: scripts/router-watch.sh commit|signed|merged|pushed|tagged <args>, DEC-30 as amended by E-SEED2.W12), so it learns the action landed without the owner saying "done". The watch checks at once and then polls until the state holds. It wakes the router with one event line plus what landed: the commits with their Reviewed-By, the landed paths against the staged set (COMMITTED-PARTIAL when one is missing), the mr note, and whether a merge was no-ff or ff. Otherwise it ends with REWRITTEN, DELETED, TAGGED-MISMATCH, TIMEOUT (before the 2 h background ceiling; the router re-arms) or UNREACHABLE. Detail lines are untrusted data. Tests: tests/router.rs watch_*.
FailureThe router runs keel mr itself, merges or pushes; or relays a worker claim it did not check; or a watch fires before the owner acted, misses a partial commit or an ff merge, or polls past its timeout.

UC-ROUTE-2 epic branch first

TriggerA router starts a new epic.
ExpectedIts first action, before any plan doc or WU, is a worker creating and pushing <epic_prefix><id> from the current main tip (prefixes from .keel/config.toml [branches]). All plan and WU work lands there; WUs branch as <wu_prefix><id>/<slug> and merge back --no-ff; main receives only the closed epic (DEC-12).
FailureA plan drafted before the branch exists; any WU or T3 doc of an unclosed epic reaching main; an epic retrofitted onto its branch afterwards.

UC-ROUTE-3 substance comes from workers

TriggerThe router relays or publishes something substantive: a "done" claim, doc prose, a comment reply.
ExpectedIt traces to a worker that derived it from the current code, tests or artifacts. Worker briefs are dispatch mechanics, not substance: the router writes them itself (DEC-32), never pasting untrusted report text into one.
FailureThe router drafts content for a worker to paste, or a mechanics-only worker posts content.

UC-ROUTE-4 the router skill ships complete

Triggerkeel init in any repo.
ExpectedWrites .claude/skills/keel-router/ (SKILL.md and every reference it names, no orphan: brief skeleton, commands, review checklists, lessons, messages, worker ops, project-router template) byte-identical to the embedded copy, plus the project-router template. The shipped skill carries no Trawler-only token outside lineage and no Keel-only state (its branches, commits, launcher path); every keel command it names exists. Enforcement and the launcher are not shipped: a project commits its own (DEC-30). Test: tests/init.rs router_skill_is_complete, embedding_is_complete_and_prefixed.
FailureA named reference missing or an orphan shipped; a stale Keel fact or Trawler token in an adopter's copy.

UC-ROUTE-5 two worker modes, each with a full recipe

TriggerThe router needs a worker.
ExpectedNative background sessions (claude --bg) through the project's launcher are the standard (DEC-44): spawn, report, follow-up and retire recipes in the skill's worker-ops.md. In-session Agent subagents only where the project does not enforce the router posture. Keel's launcher scripts/router-worker.sh has three modes. spawn: validated arguments, a fixed prompt and flags, --agent worker always; it refuses the router's own checkout and the main checkout, a non-.md, symlinked or out-of-dir brief, an unregistered worktree, and a name claude agents --json already lists; it copies the brief into the worker's worktree and prints its sha256 and the session's id; a start the CLI refuses is DEAD with the CLI's text. resume wakes an unlisted session with its saved options, bound to its spawn's name and worktree. stop closes this repository's idle worker by id (claude stop, then claude rm) and refuses a busy one. The worker reports by SendMessage to the router its brief names and stays alive; a follow-up task is the router's message; a notify_when_idle subscription is an optional extra. Every worker is granted the gate commands (cargo build|test|check|clippy|fmt, keel preflight|verify-doc|verify-dod|notes write|lint|check) and denied keel mr and cargo run, on its command line only (DEC-37); spawn takes an optional --permission-mode acceptEdits|plan (default acceptEdits) and --effort, recorded in the run dir and on the RUNNING line. Tests: tests/router.rs launcher_refuses_unsafe_targets_binds_resume_and_runs_one_worker_per_name, launcher_starts_a_worker_as_a_background_session_with_the_grant_and_a_validated_mode, stop_stops_then_removes_this_repositorys_idle_worker_by_id, a_start_the_cli_refuses_is_reported_dead_with_its_reason; end to end (seeded worktree, settings-wired guard, spawn, messages, stop): epic_e2e_router_drives_a_granted_worker_in_a_seeded_worktree_to_its_end. Outside every test, live evidence only: that Claude Code enforces the grant and mode it is given and delivers a worker's report to an idle router.
FailureA worker started in the router's checkout or main; a resume crossing worktrees; two live runs of one name; a report read from a previous run; a worker refused its own gate commands; a worker allowed keel mr; any mode other than acceptEdits/plan (bypassPermissions, dontAsk, default, a missing value, an unknown option) reaching claude -p; the grant reaching the router; a worker that hangs alive going unnoticed; a quiet worker read as stalled before stall-min minutes.

UC-ROUTE-6 the router posture is enforced, fail-closed

TriggerAny tool call by a session whose agent type is router in a checkout that enforces the posture (Keel: "agent": "router" in .claude/settings.json).
ExpectedOne PreToolUse guard on every tool (Keel: scripts/router-guard.jq) allows only the tools in the router's agent file (no Agent, Edit, Monitor), the inline keel skills, ListAgents, SendMessage to any named session (DEC-42), Write to <cwd>/.router/briefs/<name>.md, and Bash commands of plain words matching the whitelist (read-only git, gh with named query flags only, ps, the launcher's three shapes: spawn, resume, stop, and the five router-watch.sh kinds, each word validated so none starts with -). A guard error denies. Other agent types pass untouched. Watch probes it stages fire only on the real event (PUSHED = the tip is in origin/<b>). Tests: tests/router.rs.
FailureAny shell spelling that reassembles a denied flag (--out""put=); a subagent or forked skill started by the router; gh pointed at another host; a hook error or timeout that allows the call; a watcher that fires before the owner acted; router text reaching a worker through SendMessage.
