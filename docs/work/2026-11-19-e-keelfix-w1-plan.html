E-KEELFIX.W1 · Commits follow the committed rules

A commit is judged by the rules the branch has committed, never by an edit sitting in the folder.

T3 · WU plan · 2026-11-19 · E-KEELFIX.W1 (K9) · branch wu/E-KEELFIX/w1-k9 off epic/E-KEELFIX at b80e9c9 · epic plan, W1 · your ruling: every epic open point on its default (2026-11-19)

The problem

Your commits are checked by the rules file in the folder, committed or not. A worker can loosen that file, leave the edit uncommitted, and commit past the real rules. So you check the file by hand before each rule-file commit.

What changes for you

WhenTodayAfter
You make a rule-file commitThe folder's rules run; you check them firstThe branch's committed rules run; nothing to check
A worker edits the rules and does not commitIts commits follow the editIts commits follow the committed rules
A new repository's first commitThe folder's rules runThe staged rules run, and one line says so
No rules committed or stagedThe folder's rules runThe commit is refused; the fix line says to stage them

Example: a worker loosens lint

  1. The committed rules run a lint that refuses the word BAD in code.
  2. The worker edits the folder's rules to a lint that always passes. It does not commit the edit.
  3. It commits code holding BAD.
  4. Today the commit lands. After W1 the committed lint runs and refuses it.

Terms

TermMeaning
Rules file.keel/config.toml: main's name, the code paths, the lint command, the rule files, the accepted signer tiers
Committed rulesThe rules file as committed at the branch's tip (HEAD)
Staged rulesThe rules file as added with git add, not yet committed
BootstrapA commit on a branch with no committed rules yet: the staged rules judge it

The work

With the folder's .keel/config.toml edited and not committed, the pre-commit hook, the commit-msg hook and keel mr commit apply the rules committed at HEAD: the lint command, the code paths, main's name, the rule files and the signer tiers. Only when HEAD commits none do they apply the staged file, with one bootstrap line on stderr; with neither, the commit is refused.

Part 1 · One loader for the commit level

In short: a new loader reads the rules file from HEAD, else from the index, never from disk. The two commit hooks and keel mr commit get it. Every other command keeps the folder's file.

  • src/main.rs, beside load_config_at_head (line 114): fn committed_config(head: Option<String>, staged: Option<String>) -> Result<(String, bool), String>, pure: HEAD's text when there is one (the staged text is then never used, even when it differs); else the staged text, flagged as a bootstrap; else the refusal keel: commit refused - neither HEAD nor the index holds .keel/config.toml, so no committed rules judge this commit with fix -> git add .keel/config.toml (or run keel init to create one).
  • src/main.rs: fn load_config_committed(repo): git show HEAD:.keel/config.toml; only when that fails, git show :.keel/config.toml. The index read is the one git is committing, a temporary one for git commit -a, as staged_code reads it (the git helper keeps GIT_INDEX_FILE). On a bootstrap it prints keel: HEAD commits no .keel/config.toml - bootstrap: the staged .keel/config.toml judges this commit, the signer list's wording. A parse error names its source (at HEAD or staged) and never falls back.
  • src/main.rs run(): ["hook", "pre-commit"] (line 649) and ["hook", "commit-msg", file] (line 650) take load_config_committed. A new arm ["mr", "commit", ..] above ["mr", rest @ ..] (line 657) passes it to mr::run.
  • Unchanged: pre_commit's body; its merge-by-hand branch keeps load_config_at_head, which has no bootstrap. mr setup, mr confirm, lint, check, verify-dod, preflight, notes write, verify-doc and hook pre-push keep load_config (epic open point 4).
  • src/mr.rs: no logic change. commit and commit_msg read mr.tiers and rule_bearing from the Config they are given. commit_msg's doc comment names HEAD's committed rules.
  • No task branches: nothing waits on anyone outside this WU.

What you will know after W1

  • With the folder's rules file edited and not committed, a code commit runs the committed lint and is refused while it is red.
  • A rule-file commit with no trailer is refused when only the folder's file drops that path from the rule files; with a listed trailer it lands.
  • A commit on main is refused when only the folder's file renames main.
  • keel mr commit --as a signer that only the folder's widened tiers accept is refused and commits nothing; a signer under the committed tiers lands.
  • A first commit with no committed rules runs the staged file's lint and prints the bootstrap line.
  • A commit with the rules file neither committed nor staged is refused, naming git add .keel/config.toml.
  • cargo test, cargo clippy and keel check are green.
