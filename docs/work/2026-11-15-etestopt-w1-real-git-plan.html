The problem

On macOS, the git most paths name is a launcher. It looks up the real git, then starts it. In a worker's sandbox it also prints an error about a cache file it may not write. Twelve router tests compare git's output exactly, so that extra line fails them. The launcher also adds about 3 ms to each of the 22,600 git calls in a run.

Terms

Launcher (xcrun shim)/usr/bin/git on macOS: a small program that finds the developer tools' git and starts it.
Real gitThe git program the launcher would start, in Xcode or the Command Line Tools.
Test PATHThe list of directories every program a test starts searches for git, keel and the rest.

The work

In short: the shared test helpers find the real git once per test program and put a directory holding only it first on the test PATH. Every test that builds its own PATH starts from that one. Keel's own code does not change.

  1. Finding the real git. tests/common/mod.rs asks the PATH's git for its --exec-path once (a OnceLock). The real git is <exec-path>/../../bin/git, else <exec-path>/git. That covers Xcode, the Command Line Tools, Homebrew and Linux layouts without naming any of them. When git cannot be run, or neither file exists, or the file is the git the PATH already names, the test PATH is the inherited one, unchanged.
  2. A directory with only git. Putting Xcode's own usr/bin first would also shadow its python3, make and dozens more. So the helper links the real git into target/tmp/real-git/git (link then rename, so parallel test programs never see a half-made link) and puts that directory first.
  3. One test PATH. common::path() returns it; common::cmd sets it on every spawn; common::path_with(dir) puts a test's own directory (keel's, a shim's) in front of it. Every std::env::var("PATH") in the test files becomes one of these.
  4. The guard. In the style of every_test_spawn_strips_gits_env: outside tests/common, no test reads the process PATH, and no test sets PATH from a string literal. The one literal today (/usr/bin:/bin, a hook run with no keel on PATH) goes through a helper that keeps the real git first.

Details

Every process a test starts, directly or through keel, a hook or a router script, resolves git to the real git the inherited PATH's git runs from (found through its --exec-path) when that differs from the PATH's git, and to the inherited PATH's git otherwise; keel's production code is unchanged.
