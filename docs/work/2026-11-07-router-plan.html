E-ROUTER — the router skill, properly ported and invokable

Keel's second epic: finish moving Trawler's router role (router-agent + the generic half of trawler-router) into Keel's router plugin skill, fit it to how Keel's router actually works today, and prove it loads as keel:router from the plugin.

Draft v1 · 2026-11-07 · Keel · T3 epic plan · branch epic/E-ROUTER · status: draft, open questions await the owner

Intent

A Keel adopter who asks Claude to "be the router" over several worker sessions should get the full, battle-tested router discipline from Trawler — owner-attention rules, verify-before-relay, staged owner commands, watchers, worker briefs, independent review — expressed in Keel's own commands and installed by the Keel plugin. E-SEED.W6 copied the generic skill almost verbatim, but it dropped the reusable half of trawler-router, still assumes Trawler's operating model, and the plugin that would expose it is not on main yet.

Process point: this epic runs on the real branch model from its first commit. epic/E-ROUTER was cut from origin/main at 0557ba2 and pushed before this plan was written; this plan is its first commit; every WU branches as wu/E-ROUTER/<slug> off it and merges back with --no-ff; nothing lands on main until the epic closes. E-SEED had to be retrofitted into epic/E-SEED; this one must not be.

Use-case requirements

Extends E-SEED's UC-ROUTE-1 (a router verifies worker claims, stages the owner's commands, never signs, merges or pushes for the owner).

IDContract
UC-ROUTE-2When a router starts a new epic, its first action — before any plan doc or WU — is creating and pushing <epic_prefix><id> from the current main tip. All plan and WU work lands there; WUs branch as <wu_prefix><id>/<slug>; main only receives the closed epic.
UC-ROUTE-3Every substantive thing the router relays or publishes (a "done" claim, doc prose, a comment reply) traces to a worker that derived it from the current code, tests or artifacts. The router never drafts content for a worker to paste, and a mechanics-only worker never posts content.
UC-ROUTE-4Installing the Keel plugin exposes the router skill (keel:router); every reference file it names exists and every keel command it names exists; keel init writes the project-router template next to it.
UC-ROUTE-5The router can run its workers either as in-session subagents (Agent + SendMessage) or as headless sessions, and each mode has a spawn, verify-alive, brief, report and retire recipe.

Expected result

  • skills/router/ holds the generic role plus three recovered references (brief skeleton, commands, review checklists), all in Keel's terms, with no Trawler-only token (xtask, trawler, tauri, Trawler ports) outside the lineage evidence in lessons.md.
  • The skill describes Keel's router as it actually runs (Q2, Q3) and carries UC-ROUTE-2 and UC-ROUTE-3 as rules with their incident lineage.
  • Keel's own .claude/skills/project-router/SKILL.md is filled with Keel facts and true against .keel/config.toml.
  • A test proves UC-ROUTE-4 from the repo; a scratch-repo try proves the plugin install shows keel:router.
  • No Trawler file changes; no new keel CLI command.
