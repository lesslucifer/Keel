Outcome

Delivered against the requirement. src/review.rs counts rounds from the reviewed cr notes on the branch's own first-parent line (one rev-list, one notes list, one cat-file --batch). keel preflight wu|epic prints review round n of N with its scope (the whole range in rounds 1–2, the code since the last reviewed commit from round 3) and refuses with 0·review-cap a round past the cap, a round 5 or later after a round with no blocker, and an unreadable earlier note. keel notes write cr stamps round and scope, takes --findings, --refuted, --nits and --fleet (counts from the findings), writes a fix-PASS (--fixes) only where the schedule allows, and writes the cap's WAIVED with the tool's reason through W1's one waiver writer. The cap is [review] max_rounds in the target's committed config, default 5. keel mr confirm's history tags each round, its scope and each fix-PASS with the files it changed. Every cr note read is plumbing (a notes ref git cannot list is an error, never "no note"), and notes::doc_paths reads rev-list | diff-tree. The skill text (keel-code-review, keel-workflow, keel-router's brief rows) and the [review] template comment landed in the owner's keel mr commit 9659ad9.

Deviations

  • Epic plan amended: the writer takes the round's lists (plan, router item 1). The skill's jq step could not run in a review session, so keel notes write cr takes the four lists. This changes the epic plan's "no CLI change" line for that step.
  • Epic plan amended: a fix-PASS on a fix-PASS (plan open point 7, independent text review round 1). The epic plan's W2 block and open point 13 refuse any fix-PASS on top of another. That now holds only when code changed since the newest fix-PASS. A later commit that changes no code path (the result report, the owner's skill commit) gets a fix-PASS for the same round where the schedule allows one, so a docs-only tip never costs a round or ends in a waiver. A docs-only commit after a failed round still gets no PASS.
  • A second code fix from round 4 ends in the owner's waiver (plan open point 8, text review rounds 2 and 3). The writer's refusal, and since round 3 preflight's 0·review-cap on that tip, name the owner's waiver, never a round that preflight would refuse. review::no_code_since is the one rule shared by next_round and fix_pass.
  • W1's --verdict WAIVED --reason kept as built (plan open point 2). The skill uses only the reasonless cap form.
  • Three independent text-review rounds (router, on the installed keel per epic open point 11; no fix-PASS or WAIVED note written): round 1 issue I and nit 6; round 2 issue I1; round 3 PASS with nits, nit 2 (the plan quotes the epic plan verbatim) and nit 4 (preflight names the owner's waiver) fixed.
  • The skill mirrors were written by the owner, not the worker: the worker sandbox cannot write .claude/skills/.
