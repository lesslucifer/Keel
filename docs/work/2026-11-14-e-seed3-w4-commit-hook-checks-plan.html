The problem

A commit that breaks the formatter or clippy lands today: the commit hook only keeps main merge-only. A merge finished by hand also lands with no evidence, because git never runs the merge gate for it.

The commit hook runs keel lint when the staged diff touches a code path, and with a merge in progress it runs the gate pre-merge-commit would have run, so a code commit that fails lint and a hand-finished merge without evidence are both refused.

A real case, step by step

  1. On wu/E-SEED3/x you commit a change under src/ that leaves a line unformatted.
  2. git commit runs pre-commit. The staged diff touches src/, so the hook runs keel lint; the formatter check fails.
  3. The commit stops; nothing is recorded. The staged changes stay in your index.
  4. You run the formatter and commit again. Lint passes, the commit lands.

Terms

Staged diffWhat the index holds, which is exactly what the commit will record.
Code pathA path under code_paths in .keel/config.toml; an empty list means every path is code.
Merge gateWhat pre-merge-commit runs: keel verify-dod hook, judged by the target's committed policy.
Hand-finished mergeA conflicted merge you complete with git commit; git does not run pre-merge-commit then.

The work

In short: the hook gets one decision table and one new staged-diff read. Tests go through the real installed hooks in scratch repos.

  • src/main.rs: pre_commit takes the decision "merge in progress, main without a merge, or any other commit"; a merge runs the gate, a non-merge commit on main is refused, any other commit runs lint when the staged diff lists a code path.
  • src/main.rs: a staged_code helper reads git diff --cached --name-only -z -- <code_paths> — git pathspecs, the same scope the gate binds (UC-GATE-5), and the hook's own index for git commit -a.
  • tests/cli.rs: integration through the real hooks in scratch repos (list under Details).
  • Rule text, staged for one owner keel mr commit: skills/keel-workflow/SKILL.md §7's hook table, DEC-17 and DEC-29 in docs/decisions/workflow-gates.html, UC-GATE-1 and UC-GATE-2 in docs/use-cases/workflow.html.

Details

Expected

A commit whose staged diff touches a code path runs keel lint and is refused when lint is red; a docs-only commit runs no lint. A conflicted WU merge finished with git commit into an epic is refused without evidence and accepted with it, and the same by hand into main runs the epic gate instead of the merge-only refusal. A normal commit on main is still refused.

Test plan

Unit (src/main.rs): the decision table — a merge routes to the gate on any branch including main, a non-merge commit on main routes to the refusal, any other commit routes to the lint check.

Integration (tests/cli.rs, real installed hooks, scratch repos, no network):

  • A code commit with red lint is refused and the change stays staged; a green one lands, and lint ran for both.
  • A docs-only commit lands with an always-red lint command, so no lint ran.
  • git commit -a of a modified tracked code file runs lint through git's temporary index.
  • A conflicted WU merge finished by hand into an epic is refused on 1·notes, then accepted after the notes and sign-off are written on the WU tip.
  • A conflicted merge finished by hand into main runs the epic gate (1·notes), never the merge-only refusal.

Runs: cargo test --test cli; the router watch tests are red in parallel in this sandbox only (backlog R43), so the full suite runs cargo test --test router -- --test-threads=1. No waiver.

Out of scope

  • Running tests at commit (open point 4 stated lint only).
  • Linting a clean merge into an epic; that is pre-merge-commit's path and changes no behaviour here.
  • The Codex hooks, native SSH signing and Cargo.lock currency rows of B7 (epic non-goals).
