W3 · The DSH router's worker recipe

A router on DeepSeek Harness now has a recipe. It starts a worker in a worktree, steers it, reads its report from the transcript, and stops it. Claude Code's recipe is unchanged.

What landed

Delivered. The router skill teaches a DSH worker session beside the Claude Code one, and the project template asks a project which host it runs on.

  • One transport table, dated 2026-11-14. One row per mechanism and one column per host: dispatch, follow-up, report, fleet list, status, stop, permission preset. The DSH cells name worker_spawn, worker_send, worker_output, worker_list, worker_status and worker_stop. The table says to re-check the host's tool list, because DSH's worker tools are new.
  • A report that is not a message. A DSH worker never messages the router. Its report is its transcript: the router reads it with worker_output at every wake and before every ask, and verifies its claims against git like any other report.
  • Subagent is not worker. A DSH subagent inherits the router's directory, so it works in the router's checkout. A worker is the session worker_spawn starts in the worktree it names; that directory never changes. Worker work goes to worker_spawn; a subagent is only for a short read-only check.
  • The persona. On DSH it is the worktree's AGENTS.md plus the skills plus the brief. There is no project-scoped agent definition to select and no per-worker preset to pass; the brief travels as worker_spawn's prompt and must carry the goal, the hard rules and the report protocol in full.
  • The preset. Always Auto Review, fixed: a medium call (an add, a commit, minting a request) runs, a high-risk call is denied, and there is no approval path — a denial is final. A worker in a linked git worktree runs danger-full-access since the host plugin a93dff2; one in a plain directory runs workspace-write.
  • The honest gap. DSH has no shell-hook surface, so nothing enforces the router's tool whitelist or its Bash shapes until a guard plugin exists; the skill is the only guard. The router must hold itself to the whitelist, say that enforcement is missing, and never treat the gap as licence to do the work itself.
  • Template slots. The project-router template gained a "Harness and permissions" block: the harness, the permission preset, and where the brief lives.
  • Claude Code is intact. Its launcher, modes and table rows are as they were; the description no longer claims the skill is Claude Code only, and it now names DSH workers too.

The recipe, in steps

  1. The router calls worker_spawn with the worktree as the workspace, the brief as the prompt, and a handle as the name.
  2. The worker runs; the router keeps its own checkout. A follow-up is one worker_send, queued after the worker's current turn.
  3. The worker finishes and sends nothing. The router reads worker_status and then worker_output, at each wake and before each ask.
  4. The router checks the transcript's claims against git, then ends the worker with worker_stop — idempotent, and a stopped worker is never revived.

The router acts on the worker, never the reverse: the worker's only output is its transcript.
