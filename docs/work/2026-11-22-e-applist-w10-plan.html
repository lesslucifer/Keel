E-APPLIST.W10 · The app moves to pnpm

One package tool for the app, the one you chose: pnpm.

T3 · WU plan · 2026-11-22 · Keel · its data file, 2026-11-22-e-applist-w10-plan.yaml, sits beside this page · the epic: E-APPLIST plan

The problem

The app installs and runs with npm. You ruled on 2026-11-22 that it must use pnpm. Until it moves, every command you run for the app says npm, and the tests insist on npm's lockfile.

What you get

  • In the app folder: pnpm install, pnpm start, pnpm test:main and the rest. No npm.
  • The same package versions as today, to the last digit.
  • One pnpm version, written in the app's package file. Yours from Homebrew already matches.

How it works

  1. pnpm turns today's npm lockfile into its own, with the same versions. The npm lockfile goes.
  2. pnpm lays the packages out flat, as npm did. The app builder needs that to package the app.
  3. pnpm refuses package install scripts you have not approved. One package has one; it ships its binary ready, so its script stays off.
  4. The tests that checked for npm's lockfile now check for pnpm's. A new test checks the lockfile holds exactly the pinned versions.
  5. Comments and open backlog notes that say "npm run" say "pnpm" instead. Past results stay as written.

What it makes

  • The pnpm lockfile and a small pnpm settings file in the app folder.
  • The updated checks and one new one.
  • This part added to the epic plan, as a change you ruled after W5.

Keel's own checks run no package tool, so no rule file changes. Nothing is packaged.

  • The app folder has a pnpm lockfile and no npm lockfile.
  • A fresh pnpm install finishes with no warning about refused scripts.
  • The four app checks pass under pnpm: main tests, window tests, lint, type check.
  • Keel's usual checks still pass and still install nothing.
