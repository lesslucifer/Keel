E-SEED.W3 — Merge gate

keel verify-dod, keel preflight, the dod/v1 receipt, and the pre-merge-commit and pre-push hooks. These refuse a merge or a push when the evidence W2 writes is missing, stale, or does not match the diff.

v1 · 2026-11-07 · Keel · T2 WU plan · epic: E-SEED · status: ready (dispatch does not wait on sign-off; the owner reviews asynchronously)

Requirement

W2 writes test/v1, doc/v1 and cr/v1 notes, but nothing reads them back yet. Until something does, a merge is not gated on any of it. This WU builds the reader: a gate that a --no-ff merge has to pass, an epic gate that re-checks every seam so a fast-forward or --no-verify merge cannot slip through, and a dod/v1 receipt written on green.

It builds on what is already merged: W1's Config, git(), check() and hooks_install(), W2's note structs and notes::store, and the binding hash W2 already puts on cr/v1. The port follows Trawler's xtask/src/gate.rs, lib.rs (verify-dod modes and the hook entry), preflight.rs and .cargo-husky/hooks/pre-{merge-commit,push}. It keeps their structure but drops the cargo calls, Trawler's paths and the design-pack checks.

2·manifestcommit · wu · epicThe test note lacks the layer for its level (commit → unit, wu → integration, epic → e2e; counted or waived), or any note's identity tip is not the commit it is attached to (for example, a note copied over by git notes copy).

4·review-basewu · epiccr.base ≠ current merge-base of tip and target (the target moved since the review).
5·diff-bindingwu · epiccr.code_diff_hash ≠ hash of git diff base tip -- code_paths. This is the same function W2's writer uses, moved into one shared helper.
6·doc-notecommit · wu · epicA doc under docs.root changed in the range but is not listed in doc/v1 paths, or paths lists a doc the range doesn't touch. No tier check (see open point 1).
7·walkepicA first-parent seam in base..tip fails its own gate. A 2-parent merge is checked as a WU (tip = parent 2, target = parent 1). A plain commit is checked as a commit (target = its parent). An octopus merge is always red. Seams that are already landed history (parent 2 reachable from parent 1 or from the target, i.e. a back-merge) are skipped. A failure is reported as 7·walk·<inner id>.
  • Modes, following Trawler's verify-dod:
    • wu <tip> [--target R]: target is --target, otherwise epic/<e> when the tip is wu/<e>/…, otherwise branches.main. (Both prefixes are now configurable; see open point 5.)
    • epic <tip> [--target R]: target defaults to branches.main.
    • commit <sha>: target is sha^.
    • hook: the tip is MERGE_HEAD, or the GIT_REFLOG_ACTION rev, because pre-merge-commit fires before MERGE_HEAD exists. Target = HEAD, and the level comes from HEAD's branch. Two or more merge heads are refused. Merging landed history back into an epic is skipped.
    • range <old> <new>: checks each first-parent plain commit as a commit. This is what pre-push runs.
  • Range resolution is shared with the writer. keel notes write now resolves its range with the same target rule (--target flag, then wu/<e>/ → epic/<e>, then main). Before this WU it always measured from branches.main, so a WU's cr.base would never equal the merge-base the WU gate computes against its epic. Trawler uses one resolver for both for exactly this reason. A commit-level note is written with --target HEAD^.
  • Docs/infra exemption (UC-GATE-5). A range is gated when any changed path is under code_paths. Otherwise it is exempt from checks 1–6: no test, cr or doc evidence is demanded, and no receipt is written, as in Trawler. So "infra" means "everything outside code_paths" by default; an optional infra_paths glob list can narrow it (open point 2). This is Trawler's own rule (is_gated = any code path), with Keel's config in place of Trawler's hard-coded prefixes. An empty code_paths makes every path code. The gate never silently exempts everything, and this matches W2, whose cr hash covers the whole diff when code_paths is empty. In the code, the exempt early return comes after a marked slot where W4's check 8 (mr/v1) and W8's tier layout will go. UC-GATE-5 never exempts those two. The epic walk runs even on an exempt epic, because each seam judges its own diff.
  • walk_waivers: an optional list on the epic tip's cr/v1 note, "walk_waivers": [{"seam": "<sha or prefix>", "why": "<reason>"}]. This is Trawler's shape and location. A seam sha is matched by prefix in either direction, and a blank why never waives. A waived seam is printed as waived and does not block. The tip's own checks still run. A red seam's fix line names the exact git notes --ref=cr edit step and warns against --no-verify. The field is added to CrNote with #[serde(default)], so existing notes still parse. It is not written by notes write cr: it is an on-the-record manual edit, as in Trawler.
  • dod/v1 receipt: written to refs/notes/dod on a green, non-exempt wu/epic/hook run. It holds the identity block (tip, base, branch, committer, timestamp), level, checks (the receipt names of the checks that level ran), and diff_hash (blob hash of the full base..tip diff). W2's schema-only DodNote gains level and checks. commit and range write no receipt, as in Trawler.
  • keel preflight wu|epic <tip> [--target R]: run before a review starts. It fails under 0·tree when the checkout is not on the tip, has uncommitted tracked changes, or fails keel check. It then runs only checks 1 and 2 against the test note. It doesn't ask for cr or doc notes, because the review is what writes them. An exempt diff passes with no notes. It writes nothing.
  • Hooks (added to keel hooks install; both fail closed when keel is missing, like pre-commit):
    • pre-merge-commit → keel verify-dod hook. On an epic → main merge it also runs keel check on the merged tree after the gate is green (Trawler DEC-74).
    • pre-push → keel hook pre-push <remote>, reading git's refspec lines on stdin. It runs three steps. (1) check push: every pushed tree is proven, by keel check in place when it is the clean HEAD's tree, otherwise in a scratch worktree at that sha. (2) range check: verify-dod range remote_sha local_sha for updates to branches.main or epic/*. New branches and deletions are skipped. (3) notes sync: git push --no-verify <remote> refs/notes/*, because a plain git push never sends notes refs, so evidence would stay on one machine. A failed sync only warns, as in Trawler.
  • Refusals print one block per failure in Trawler's format, FAIL <check id> <what> followed by fix -> <fix>, and exit 1.

Maps to

UC-GATE-2 (a --no-ff merge is refused unless every required note is present, parses, and is bound to the exact diff; green writes dod/v1) · UC-GATE-3 (the epic gate re-walks every first-parent seam; a fast-forward or --no-verify merge turns it red; only a walk_waivers entry with a reason overrides one seam) · UC-GATE-5 (docs/infra-only diffs are exempt from test, cr and doc evidence) · UC-DOC-3 (partially: "every changed doc is accounted for in doc/v1"; "no T3 doc is tracked at an epic tip" is W8).

Explicitly not this WU

  • keel mr, mr/v1 writing or reading, check 8, the .mr-allowed trust store, and the commit-msg Reviewed-By trailer: all W4. No check here needs mr/v1 yet.
  • T0–T3 tier classification, tier-layout validation, and the "no tracked T3 doc at an epic tip" rule: W8.
  • Trawler's design-pack checks (9·design, components·unbuilt, 6·run-closed, 6·retirement-order) and its 3·review-nits (cr/v1 has no nits list yet). dod list and tally recording.
  • Trawler's machine-refusal paths in its gate0 (Keel's keel check), and per-worktree hook drift detection (hooks::refusal).
  • No changes to Trawler, the seed plan, or the W2/W5 plan docs.

Expected result

Per the epic plan, each check has a red fixture that prints the expected check id → fix block, and a green fixture. A seam smuggled in by fast-forward is red at the epic gate. In practice: a real git merge --no-ff of an unblessed WU into its epic is refused by the installed hook, the same merge passes once notes are written and leaves a dod/v1 receipt on the WU tip, and a push syncs notes refs to the remote.

Test plan

New tests/verify_dod.rs, following tests/cli.rs: a temp git repo, the real keel binary, and notes written through keel notes write. Tampering is done by editing the note JSON in place.

  • Green WU + receipt: a blessed wu/e/a → verify-dod wu exits 0. The dod/v1 note parses, with level, checks and tip. preflight wu is green on the tip.
  • 1·notes: the cr note is missing → red, and the output names 1·notes with a fix -> line. The preflight on a tip with no test note is red too.
  • 2·manifest: a WU test note with only a unit layer → red.
  • 3·review: --verdict FAIL → red.
  • 4·review-base: cr.base edited to another sha → red.
  • 5·diff-binding: cr.code_diff_hash edited → red.
  • 6·doc-note: a doc changed by the WU and dropped from doc/v1 paths → red.
  • 7·walk: an epic with one green --no-ff seam passes. A second WU merged by fast-forward (its code commit has no notes) turns the epic red with 7·walk·1·notes. A walk_waivers entry for that seam on the epic's cr note turns it green and marks it waived.
  • Exemption: a docs-only WU with no notes is exempt and writes no receipt.
  • Hooks end to end: after hooks install, a git merge --no-ff of an unblessed WU into its epic is refused. Once the WU is blessed, the merge lands and the WU tip carries dod/v1. Pushing to a bare remote delivers refs/notes/*. A push of an epic carrying a noteless code commit is refused by the range check.
