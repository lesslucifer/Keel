E-GHFLOW2.W3 · Your approval is the sign-off

When you approve a pull request on its head commit, a workflow from main writes the same sign-off note your typed command writes.

Ready v1 · 2026-11-15 · T3 · WU plan · Keel · epic plan: 2026-11-15-eghflow2-plan.html (archived; git show 738c795:docs/work/2026-11-15-eghflow2-plan.html)

The problem

You sign every WU and epic with a typed keel mr confirm at your Mac. GitHub already shows the diff, the report and an Approve button, on your phone too, but approving changes nothing. And the typed command trusts its checkout's git links before it runs git (backlog e-router-v2 R50).

Example

  1. W5's worker finishes. The bot pushes wu/E-GHFLOW2/w5-try-it and opens its pull request into the epic.
  2. The checks turn green. You read the diff and the report on your phone and press Approve.
  3. GitHub runs "Keel sign-off request" from the pull request; it does nothing but finish.
  4. Its end starts "Keel sign-off" from main. That reads the pull request and its reviews from GitHub, builds keel from the epic, and writes mr/v1 as github 5499546 with your review's id, link and commit.
  5. It pushes the note and sets keel/sign-off green. The router's next push brings the note to your Mac first.

The work

A pull-request approval by an id the base's committed roster lists under the github tier, on the pull request's exact head commit, makes the writer (run from main, with keel built from the base) write an mr/v1 note that keel verify-dod accepts; any other review writes nothing; and keel mr refuses, before any git call, a checkout whose git links git did not make.

  1. The github tier (src/mr.rs). The roster parses github: <numeric id> <login>; github joins the known tiers. A typed confirm by an id listed only as github is refused: that tier signs by approval.
  2. mr/v1 gains review: {id, url, commit}. Check 8 for a github signer: the note carries a review whose commit is the tip and whose link is that review's on this repository's pull request; everything else as today (base, diff, report, waiver).
  3. keel ci sign-off: the writer's core. It reads GitHub's list of the pull request's reviews from a file, keeps the newest APPROVED one on the tip by an id the target's committed roster lists under github, and writes the note through the typed confirm's own path (sign last: checks 1–7 green). No such review: exit 3, nothing written. A waiver or a roster change in the range is refused: those are W7's comments, or the typed sign-off.
  4. The epic report as a note. keel notes write report <path> stores an epic-result doc's exact bytes as refs/notes/report on the tip. A sign-off may attest it as refs/notes/report; check 8 re-hashes the note.
  5. Two workflows. "Keel sign-off request" on pull_request_review: no permissions, no checkout, one step that only finishes. "Keel sign-off" on workflow_run of it, so main's file runs: it checks out main, runs scripts/ci-sign-off.sh, which builds keel from the pull request's base, never runs head code, pushes refs/notes/mr and sets keel/sign-off. Token: contents and statuses write, pull-requests read.
  6. Notes from GitHub reach the Mac. router-gh.sh push fetches GitHub's notes refs and merges them into the local ones before it pushes them, and pushes refs/notes/report too.
  7. R50. Before any git call, keel mr finds its checkout's .git and checks it as router-gh.sh does: a main git dir has no commondir; a linked admin dir sits under worktrees/, holds commondir = ../.. and a gitdir naming this checkout back; no config.worktree in either.
  8. G5's W2 test nits in tests/suite/router_gh.rs and router_gh_args.rs: the App key made once per run; a fixture HOME that the script accepts under any TMPDIR; the dash test covers slot 0 and the --base word.

Observable from this WU alone, hermetically (the workflows run live only after landing 2):

  • A recorded approval by a listed id on the head, fed to scripts/ci-sign-off.sh with a fake GitHub, writes mr/v1 (tier github, the review's id, link and commit), pushes it to origin and posts a success status; keel verify-dod is green.
  • A COMMENTED review, an approval on an older commit, or one by an unlisted id writes nothing and posts a pending status.
  • A code commit after the approval turns check 8 red; an edited report note turns an epic's check 8 red.
  • keel mr in a checkout whose admin dir holds a config.worktree or a wrong commondir is refused and runs no git.
  • router-gh.sh push brings a note GitHub holds into the local ref before it pushes.

Test plan

Integration (tests/suite/sign_off.rs, new; tests/suite/mr.rs; tests/suite/router_gh.rs): a scratch repo, a bare origin and the existing fake curl standing for GitHub's API, with recorded review payloads.

  • The writer script: listed approval on the head → note, push, success status, gate green; COMMENTED, older commit, unlisted id → nothing written, pending; checks 1–7 red → nothing written, failure status naming it; a base with no github-tier keel → refused.
  • keel ci sign-off and check 8: a code commit after the approval is red; a note whose review commit or link is wrong is red; a typed confirm by a github-only id is refused; an epic signed with the report note goes green, and editing the note turns it red.
  • R50: keel mr refuses a config.worktree in the admin dir or the git dir, a commondir other than ../.., a gitdir naming another checkout, and a commondir in a main git dir, with a git on PATH that records any call: none is made. A clean linked checkout signs as today.
  • The lock test (tests/suite/keel_gate.rs): the request workflow's trigger, empty permissions, no checkout, no expression in a run line; the writer's workflow_run trigger on the request workflow only, its three permissions, its pinned checkout of the default branch with no credentials kept, no head ref anywhere, one call of the script, event values through env only.
  • router-gh.sh push: GitHub's mr note on another tip appears locally after the push; a conflicting note keeps the local one; the report note is pushed.

Unit (src/mr.rs, src/notes.rs, src/main.rs): the roster line (generated lines, a non-numeric id, a bad login); the review pick (generated review lists: only an APPROVED review on the tip by a listed id is ever chosen, the newest); the review field's link check; the admin-dir rule on fabricated paths.

Red first for each behaviour: each test is run failing before its code lands.

Details

Rule-bearing files this WU stages for one owner keel mr commit, after the worker's commits: .github/workflows/keel-sign-off-request.yml, .github/workflows/keel-sign-off.yml, scripts/ci-sign-off.sh, scripts/router-gh.sh, .keel/config.toml ([mr] tiers gains github).
