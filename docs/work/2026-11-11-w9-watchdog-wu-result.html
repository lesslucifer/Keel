E-ROUTER3.W9 · The watchdog reports every worker — result

One background session per router, on Haiku, sends the router one message every 5 minutes with a sentence per live worker; code marks idle workers DONE and blocked or long-quiet ones STUCK.

Result · 2026-11-11 · Keel · plan 2026-11-11-w9-watchdog-wu-plan.html (v4) · DEC-45

Outcome

Delivered against the requirement, with the plan v4 design. scripts/router-worker.sh watchdog start <router-name> starts watchdog-<router-name>: claude --bg --setting-sources local --agents '<inline agent>' --agent watchdog --model haiku --tools SendMessage CronCreate --allowedTools SendMessage CronCreate --strict-mcp-config --autocompact 100k --settings '<two hooks>', in the router checkout. Its first turn schedules tick every 5 minutes with CronCreate; each turn's prompt hook runs watchdog facts <router-name>; the session's only tool hook is the router guard run with --arg watchdog_to <router-name>. watchdog stop is W10's stop path on the watchdog's name; facts stops the watchdog once the router is unlisted. The router's name reaches the session only inside the two hook commands.

The live run passed end to end: two real workers, one idle without a report and one blocked on a permission prompt, and two watchdog reports reaching the router, each naming one DONE and one STUCK (permission prompt) worker, the second from the native schedule with a red doc in the router checkout.
