Decisions: workflow gates

Why the notes, the merge gate, the human sign-off, the code review contract and the doc tiers are the way they are. Check here before "fixing" anything that looks deliberate.

T2 · decisions · append-only · 2026-11-08 · Keel · DEC-13 – DEC-29, DEC-40 · distilled from E-SEED (W2–W8 open points, rulings R2–R24)

Append-only. A reversal marks the old record superseded by DEC-m and adds a new one. Check ids (1·notes … 8·manual-review) are the ones src/gate.rs prints.

Notes

DEC-13 · Schemas start at /v1, with no legacy readers

ContextTrawler's gate kept a reader for every schema it ever shipped (cr/v2…v5, design data inside cr/v3).
ChoiceEvery Keel note (test, doc, cr, mr, dod) starts at /v1, shares one identity block (tip, base, branch, committer, timestamp) and has no legacy readers. Until a release, a schema is changed in place (doc/v1 paths became changes). The identity has no epic/WU ids: the epic and WU are inferred from branch names, and 2·manifest only checks that each note's tip is the commit it sits on.
ConsequencesA note copied onto another commit is caught; a note meant for a different WU on the right commit is not.
LineageSeed plan; W2 scope; W3 open point 10; W8 open point 10.

DEC-14 · Evidence is derived from the tree, bound by git hashes

Choicekeel notes write computes range, identity, tiers and test counts itself; the agent supplies only a judgment (JSON on stdin for test, flags for cr). The cr binding is the git blob hash of git diff base tip -- code_paths, one shared function for writer and gate. Writing from main (an empty range) is refused.
Rejectedsha256 (diff_sha256): a new dependency for no gain while git's own object hash binds the tip anyway (hardening in backlog B7).
LineageW2 open points 1–3; Trawler DEC-44.

Merge gate

DEC-15 · One range resolver; configurable branch prefixes

ChoiceThe note writer and the gate resolve the target the same way: --target, else <wu_prefix><e>/… → <epic_prefix><e>, else branches.main. branches.epic_prefix / wu_prefix default to epic/ / wu/ and drive hook level detection and the pre-push range check. Merges into other branches are ungated.
ConsequencesA WU's cr.base equals the merge-base its WU gate computes against the epic (it never could when the writer measured from main).
LineageW3 open points 5, 6; R4.

DEC-16 · The docs/infra exemption, and what it never covers

ChoiceA range is gated when any changed path is under code_paths (empty = everything is code). Otherwise it is exempt from test, cr and doc evidence and writes no receipt. Optional infra_paths globs can only narrow the exemption. Never exempt: check 8 (sign-off), the epic tracked-doc layout, and the lineage of a T3 doc the range archives (an archive commit is always docs-only, so exempting it would make the distillation check unreachable).
RejectedA config flag to exempt archive commits.
LineageW3 open points 2, 3; R3; R24; W8 open point 7; Trawler is_gated.

DEC-17 · keel check: where trees are proven

ChoiceRenamed from "gate0" to check everywhere (keel check, [check], keel-check-green), with no compatibility for [gate0]. It runs at preflight, on the merged tree of an epic → main merge, and on every pushed tree; a WU → epic merge checks notes only. Results are cached by tree content. The pre-commit hook only enforces merge-only main and runs no lint.
ConsequencesTwo WUs green alone but red together are caught at the epic's preflight, its merge into main, or a push, not at the second WU merge. A non-HEAD pushed tree is proven in a scratch worktree whose cache is discarded.
LineageR2 (option a: spec reworded to match code); R5; W3 open point 8; W6 open point 9; Trawler DEC-74, DEC-11/54 (cache).

DEC-18 · The epic walk and walk_waivers

ChoiceThe epic gate re-verifies every first-parent seam. A red seam is overridden only by walk_waivers: [{seam, why}] hand-edited onto the epic tip's cr note (git notes --ref=cr edit), matched by sha prefix, blank reason never waives. The epic tip itself is not walked (its epic-level checks cover it) and no rule restricts what the epic tip may be.
RejectedA CLI flag for waivers; a rule that the epic tip must not be a code commit.
LineageW3 open points 4, 7; R6; Trawler's walk.

DEC-19 · Notes sync is push-only

Choicepre-push pushes refs/notes/* (a failed sync only warns). Nothing configures a notes fetch: a fresh clone runs git fetch origin 'refs/notes/*:refs/notes/*' by hand. Fetch setup in init is deferred (backlog B6).
LineageW3 open point 9; R7.

Human sign-off

DEC-20 · Trust model: a local roster; "signed" means a listed key signed

Choice.mr-allowed lives at the worktree root, untracked (git-ignored via .git/info/exclude); every reader refuses while it is tracked, and the fix is to delete it and rebuild with keel mr setup. Tiers email / username / key, configurable via [mr] tiers (default all three). If an identity has any key entry, its notes must carry a verifying signature, whatever tier the note claims. Identities are limited to [A-Za-z0-9@._+-].
Accepted limitationAny process with SSH_AUTH_SOCK or filesystem access (including an AI agent) can sign with a loaded key or add itself to the roster. "Signed" proves a listed key signed this exact change, not that a human reviewed it. A passphrase-protected key is assumed and recommended; it only helps while the key is not loaded into ssh-agent.
LineageQ10; R8 (security review H1); W4 open points 1, 4, 5, 16; Trawler DEC-9, DEC-10.

DEC-21 · The signature payload

Choicessh-keygen -Y sign -n keel-mr over a versioned text: keel-mr/v1, level, base, tip, change hash (blob hash of the full diff), report path, report hash. Hashes are git object ids. The key comes from git config keel.signingkey (never user.signingkey). mr confirm self-verifies against the roster before writing. The verifier recomputes base, tip and change from the repo and trusts only the signed report hash, re-checked against the report's bytes.
RejectedTrawler's bare change_hash\nreport_sha256 (replayable onto another commit, range or level); sha256 via a new crate.
LineageW4 open points 2, 3, 6, 10; Trawler DEC-10.
AmendedBy DEC-40 (E-SEED2.W2): payload keel-mr/v2, the report lines only when a report is attested, change and report hashes sha256:<hex> via the sha2 crate, reversing the "sha256 via a new crate" rejection above.

DEC-22 · Sign last, strictly; check 8 at the boundary only

Choicekeel mr confirm refuses unless the tip passes checks 1–7 for its level (the epic walk included), so a human is never asked to sign a tip the merge would refuse. Check 8 runs in gate::run() on every top-level wu/epic run, never inside verify(): the walk re-enters verify() per seam and must not re-judge old seam sign-offs (the roster is local and mutable). Check 8 runs at pre-merge-commit only, not pre-push. The report is --report or the single changed *-result.html; reworking that is deferred (backlog B2).
LineageR10; R11; R13 (security review H4); W4 open points 8, 9, 11, 17; Trawler DEC-27, DEC-9/10 (boundary-only).
AmendedBy DEC-40 (E-SEED2.W2): the report is found by its data-artifact role under [mr] report; the *-result.html rule is gone. Correction found in W2: "pre-merge-commit only, not pre-push" is stale - pre-push also runs check 8 for every merge seam not already on the remote branch (the code is the truth); DEC-40's old-note exposure depends on it.

DEC-23 · The merge boundary judges by the target's policy and untracked hooks

Contextpre-merge-commit runs with the incoming branch already in the working tree. A branch could rewrite .keel/config.toml (H2) or ship a no-op .keel/hooks/pre-merge-commit that git would run for its own merge.
ChoiceThe hook loads the config from HEAD:.keel/config.toml (the target's committed policy; no committed config → refuse). Empty merge heads on a gated branch are refused (H3). Hooks are written to <git-common-dir>/keel-hooks/, untracked, with an absolute core.hooksPath; the hooks are thin exec keel … shims, so drift is small.
ReversesTrawler DEC-72 ("git runs the tracked hooks", relative tracked core.hooksPath, plus a guard refusing a checkout whose hooksPath is not its own). Keel did not carry that guard over; coexistence with other hook managers is settled by the amendment below.
LineageW4 open points 14, 15, 19; R14; commit 0412b3c.
Amended (E-SEED2.W2): coexistenceKeel runs alone, never alongside another hook manager. keel hooks install refuses (exit 1, changes nothing) when the effective core.hooksPath (any scope) is not Keel's canonical keel-hooks path, or, with none set, when <git-common-dir>/hooks/ holds any entry not ending in .sample; it names what it would replace, and --force replaces it. A re-install over Keel's own path is a no-op refresh; install and guard D compare paths component-wise with one test, so a trailing / is still Keel's path. keel init writes its files, then stops on that refusal; its -f never implies --force. Guard D (a DEC-72-style guard, UC-GATE-6): keel preflight and keel verify-dod wu|epic fail 0·hooks while core.hooksPath is unset or not Keel's; keel check only warns; verify-dod hook|range|commit skip it (they run from Keel's own hooks, or inside the walk).
Rejected (coexistence)Chaining the other tool's hooks (re-imports branch-controlled code into the gate); refusing only a foreign value and warning on an unset one (misses a clone where hooks were never installed). Cost accepted: a hook manager switched on later is caught at the next preflight or gate command, not when it happens.
Lineage (amendment)E-SEED.W9 plan open point 5 (options B + D); E-SEED2.W2 plan open question 5, choices C, D, E, G; owner ruling 2026-11-09; Trawler DEC-72 (guard).

DEC-24 · Rule-bearing commits: a trailer, not a signature; known gaps accepted

ChoiceA commit touching rule_bearing needs a listed Reviewed-By trailer (keel mr commit); the WU's mr/v1 signature covers the whole diff. Native git commit -S signing is deferred (backlog B7). rule_bearing entries ending in / are prefixes, others globs.
Accepted gaps(1) Permanent, not scheduled: the commit-msg hook reads rule_bearing from the working-tree config, so a transient uncommitted edit lets a rule-bearing commit land without a trailer, and nothing downstream re-checks trailers. (2) git commit --amend sees only newly staged changes; cherry-picks are checked like any commit.
LineageR9; R16; W4 open points 7, 12, 21; Trawler DEC-9.

ChoiceNot triaged or tracked further: the report holding their details is unavailable, and the owner accepted the risk.
LineageR15; W4 open point 20.

DEC-40 · The result report is a configurable, role-found receipt; sign-off hashes are SHA-256

ContextThe sign-off always attested one report, inferred from a changed *-result.html: a project with no reports could not sign, a report with another name was missed, and an archived epic report was not found. The hashes were git SHA-1 blob ids.
Choice[mr] report = "required" | "optional" | "none" in the target's committed config, one policy for both levels, default required. The report is the doc whose root data-artifact carries the level's role (wu-result, epic-result; a collapsed doc counts for both), or --report. WU candidates: html under docs.root changed in base..tip and present at the tip; an epic adds untracked docs under docs.root, ignored ones included (docs/.archive/), except a report already attested by an mr/v1 note on a commit the base contains (an earlier, merged sign-off's). Several candidates are refused with the list; none under required is refused before signing (FAIL / fix, no note); none with --report is refused. Check 8 reads the policy from the cfg it is given (HEAD's at the merge hook): required with no report in the note is red; a report in a note is re-hashed whatever the policy. The report is evidence like the notes: mr/v1 and dod/v1 both name it, nothing new replaces dod/v1. Payload keel-mr/v2, with the report lines only when one is attested. mr/v1 change_hash and report_hash are sha256:<hex> over the same bytes as before (diff text as git returns it; the report blob at the tip; the raw local file for an epic), via the sha2 crate. Note schemas stay mr/v1 and dod/v1, changed in place.
RejectedA per-level policy (the table form can be added later without breaking the string form); narrowing epic candidates by name or by a new epic-id attribute (new markup is rule-bearing skill text, and a tip given as a sha names no epic); bounding them by file mtime against the base's commit time (cp -p and touch move it, and it differs per machine); requiring the epic report to be touched in base..tip (it is written straight into the untracked archive, never committed); never auto-picking an untracked report (every epic would need --report); git hash-object for SHA-256 (git 2.50 has no --object-format there) and shell tools (differ by platform); SHA-256 for cr/v1 and dod/v1 bindings (unsigned, and changing them stales every in-flight cr note).
ConsequenceNo legacy reader (DEC-13): a pre-W2 mr/v1 note is red wherever a W2 binary re-verifies it - verify-dod wu|epic, the merge hook, and pre-push for an unpushed merge seam. Already merged and pushed seams are not re-judged. Owner rule: sign, merge and push each WU with the same installed keel; re-sign a WU signed but unmerged when the installed binary crosses W2. Past epics' reports stay in docs/.archive/ but drop out of the lookup once their sign-off is merged into the base, so the epic sign-off finds this epic's report without --report. Ceiling: an earlier report whose sign-off is not in this checkout's refs/notes/mr (signed elsewhere and not fetched, or under none), or whose merge into main is not yet in this epic's base (epic close merges main in first), still counts, so the lookup lists it beside this epic's and asks for --report; with no report of this epic's, it alone would be picked. An unmerged signed epic's report is never excluded.
LineageE-SEED.W9 plan (never started); R11; W4 open point 3 (backlog B7); E-SEED2.W2 plan open questions 1–4, choices A, B, F; owner ruling 2026-11-09.

Code review

DEC-26 · Review scope, nits and modules

ChoiceA standalone code commit gets no review of its own; the epic review covers it (Trawler DEC-51 not restored). Nits and the fleet bill are added to the cr note by the code-review skill's jq step only; no CLI flag, validation or disposition check will be built. [review] modules globs define a module for the altitude finder (each * match is one module) and [review] rubric points at an optional project-local rubric; only the skill reads [review]. The shipped rubric holds dimensions, severities, principles P1–P5 in general form and the DEC-50 corpus numbers as lineage; project instances go in the project rubric.
LineageQ11; R20 (superseded by R22); R21; R22; W6 open points 6, 7, 8, 11; Trawler DEC-50, DEC-51.

Documentation

DEC-27 · Doc tiers by config globs; archiving needs lineage

ChoiceTiers come from [docs.tiers] globs (default: Trawler's layout under docs.root, design-rules dropped), matched T3 → T2 → T1 → T0 so a broad glob never hides a working doc. "Archived" means deleted in the range and absent at the tip; the local copy in gitignored docs/.archive/ is not checked. An archived T3 doc needs distilled_to: T1/T2 docs tracked at the tip (not necessarily changed in the same range), or "none: <why>". A doc matching no glob is red. The doc set includes T0 files, so an AGENTS.md edit needs a doc note. Only verify-dod enforces this; verify-doc has no range or tip.
RejectedA per-doc data-tier tag (a T3 doc could relabel itself to escape archiving). Trawler's t2_waived and distills sentence (judgment text the gate can only check for non-emptiness).
LineageW8 open points 1–9, 11; R23; Trawler documentation-system (DEC-29 retired set).

DEC-28 · verify-doc: drafts fully silent

ChoiceA draft (or status-less) governed doc is silent on its checklist and its relative links, unlike Trawler. Checklists are keyed by data-artifact; collapsed roles need the union. The Codex apply_patch payload parsing in verify-doc-post is ported from Trawler, not verified against Codex docs (backlog B7).
LineageW5 open points 3, 4; Trawler DEC-4.

DEC-29 · Conflicted merges are handled by the workflow, not the CLI

ContextFinishing a conflicted merge with git commit never runs pre-merge-commit. On main pre-commit refuses it; into an epic it lands ungated until the epic walk re-checks the seam.
ChoiceThe workflow skill says: resolve conflicts by merging the target into the work branch first, so the gated merge is clean. Porting Trawler's MERGE_HEAD branch in pre-commit is a possible follow-up (backlog B7).
LineageW6 open point 10.
