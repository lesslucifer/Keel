E-SEED.W6 — Skills + init

The plugin's five skills (workflow, plan, code-review, distill, router), a project-router template, and keel init, which wires a fresh repo of any language to all of it.

v1 · 2026-11-07 · Keel · T3 WU plan · epic: E-SEED · depends on: W4, W8 · status: ready (dispatch does not wait on sign-off; the owner reviews asynchronously)

Requirement

An adopting project runs keel init once and gets the config, the T0 instructions file, the Codex compatibility files, a docs skeleton and the git hooks; from then on the plugin's skills tell every agent session how to plan, test, review, distill and route work, naming only keel commands that really exist.

The skills are ports, not new designs. Each one is the Trawler source rewritten against what W1–W5 and W8 actually built: Trawler's cargo xtask calls become keel calls, hard-coded paths become .keel/config.toml keys, and behaviour Keel does not have (design pack, gate0 merge|push subcommands, --defer-gate0, cr/v2–v5 readers, the setup wizard) is dropped rather than described.

What keel init does

StepRule
Write each filemissing → created · byte-identical → unchanged · different → kept and reported, never overwritten (UC-INIT-1). No prompt: agents run init non-interactively.
.keel/config.tomldefaults from the seed plan's config table, plus [docs.tiers] spelled out and a [review] section for the skill. check.lint/test detected from Cargo.toml / pyproject.toml (or setup.py, requirements.txt) / package.json / go.mod, else a command that fails with "set check.lint". branches.main = master only when that branch exists and main does not.
AGENTS.mdthe T0 block (AI-first, conventions, testing, workflow, docs tiers, skill pointers). If CLAUDE.md exists, a warning: Claude Code reads it instead of AGENTS.md.
Codex parity.agents/skills → ../.claude/skills (symlink) · .codex/hooks.json (a real file) calling the installed verify-doc-post / verify-doc-stop scripts
project-routertemplate copied to .claude/skills/project-router/SKILL.md, placeholders left for the project to fill
docs skeletondirectories docs/use-cases/, docs/decisions/, docs/work/; docs/.archive/ appended to .gitignore if absent
hooksruns keel hooks install (hooks in the git common dir, core.hooksPath absolute)
hand-offprints: keel on PATH or the install line (Q3), the bootstrap commit, and keel mr setup --as <you>

Maps to

E-SEED · UC-INIT-1 (init writes config, T0, Codex files, hooks; idempotent; never overwrites an edited file) · UC-REV-1 (the code-review skill judges only code_paths and writes a cr/v1 bound to their diff hash; verified blockers and importants fail it; nits are recorded with a disposition) · UC-ROUTE-1 (the router skill verifies worker claims, stages the owner's commands, never signs, merges or pushes).

Explicitly not this WU

  • .claude-plugin/plugin.json, hooks/hooks.json, marketplace entry, binary distribution: W7.
  • A worked project-router skill with real facts: only the template.
  • CLI changes beyond keel init (and dropping "coming soon" from the no-config message). Gaps found while porting are listed as open points, not fixed.
  • No change to Trawler, Trawler-prorelease, the seed plan or earlier WU plan docs.

Expected result

Per the epic card: running keel init twice in a fixture repo produces the same tree, the config it writes loads, and an edited config survives a second run. Every keel <command> named in any skill file exists in run()'s dispatch, and no skill names cargo xtask. cargo build, cargo test and cargo clippy --all-targets are clean.

Test plan

New tests/init.rs (integration, the real binary in a temp repo, same style as tests/cli.rs):

  • Idempotent: init twice; a snapshot of the tree (path, file bytes, symlink target; .git excluded) is identical. core.hooksPath is set, and keel verify-doc loads the written config.
  • Never overwrites: edit .keel/config.toml, run init again: the edit is still there and the output says it was kept.
  • Skills name real commands: every keel <word> in skills/**/*.md has a matching first-word arm in run() (parsed from src/main.rs), and no skill mentions cargo xtask.

Unit layer waived: init is file writes plus one detection table, fully covered at the integration boundary. E2E stays with the epic (W7).

Open points for the owner

#PointDecided here
1Where the skills live.skills/ at the repo root, which the seed plan's expected result already names next to .claude-plugin/ and hooks/. Templates init embeds live in templates/ (and the router's references/project-router-template.md), pulled in with include_str!, so the binary carries them.
2The shape diagram lists a "skill init".Not written: keel init (the CLI) does the work and the workflow skill tells an agent to run it. If W7 wants a /keel:init entry point, it is a three-line skill that runs the command.
3Bootstrapping deadlock. After init, pre-commit refuses commits on main, and the merge gate refuses a merge into a target with no committed .keel/config.toml. So the config can land neither directly nor through a merge.init prints a one-time bootstrap: git add … && git commit --no-verify -m "keel init" on main. It is the policy landing, with nothing yet to gate. Alternatives: init commits itself, or installs hooks only once the config is committed. Owner call.
4"Never overwrite without asking" in a non-interactive CLI.A differing file is kept and reported; there is no prompt and no --force. The user deletes the file to take the new default. Exception: .gitignore gets docs/.archive/ appended when the line is missing (additive, never rewritten).
5Codex files. Trawler symlinks .codex/hooks.json → .claude/settings.json. In Keel, Claude's harness hooks come from the plugin (W7), so a project .claude/settings.json would fire them twice..codex/hooks.json is a real file that calls the scripts keel hooks install put in the git common dir. Its matcher (Write|Edit|apply_patch) and payload shape are Trawler's best effort and not verified against Codex docs. .agents/skills → ../.claude/skills shows Codex only the project-local skills (project-router); the plugin's skills reach Codex only once W7 picks a path (vendor or symlink to the plugin install).
6Nits and the fleet bill have no field in cr/v1, and keel notes write cr takes only verdict, blockers and importants. UC-REV-1 wants each nit recorded with its disposition.The skill writes the note with keel notes write cr, then adds nits and fleet to the JSON (one jq rewrite), the same hand-edit route walk_waivers uses. The gate's serde ignores unknown fields, so nothing breaks; but nothing checks a nit's disposition either (Trawler's 3·review-nits). Porting that check is a small CLI follow-up.
7"Module" for the altitude finder (Q11).New [review] modules = ["src/*"]: each glob's * match is one module, and a test file counts as the module it tests. [review] rubric = ".keel/rubric.md" points at the optional project-local rubric. Only the skill reads [review]. The CLI ignores unknown keys, so a typo there is silent.
8Rubric split.skills/code-review/rubric.md ships the dimensions, the severity rows, principles P1–P5 stated generally, and the exclusions. Trawler's per-principle instances (bodies, CA keys, tokio threads) and the DEC-50 corpus numbers belong in a project's own rubric file. The numbers are kept once, as lineage, so "more coverage" cannot quietly re-buy the retired dimensions.
9Found while porting: pre-commit runs no lint. Trawler's pre-commit ran lint. Keel's installed pre-commit only refuses commits on main, so keel lint exists but no hook calls it. keel check still runs at the merge into main and on every push.The workflow skill describes the real hooks. Whether pre-commit should call keel lint is a one-line follow-up for the W1 area. Owner call.
10Found while porting: a conflicted merge skips the gate. Finishing a conflicted merge with git commit never runs pre-merge-commit. On main, pre-commit refuses it outright (main is merge-only). Into an epic, it lands ungated until the epic walk re-checks the seam. Trawler's pre-commit ran the merge gate when MERGE_HEAD existed.The skill says: resolve conflicts by merging the target into the work branch first, so the gated merge is clean. Porting Trawler's pre-commit branch is a CLI follow-up.
11Standalone code commits owe no review in Keel. Trawler DEC-51 demanded a cr on them. Keel's commit level checks notes, manifest and doc-note only.The skill states the real rule. Restoring DEC-51 is a gate change, not W6.
12Docs skeleton is directories only.No index docs: an htmldoc doc needs a server-minted id, and init stays offline. No .gitkeep either, because a tracked docs/work/.gitkeep is a T3 file that would turn the epic layout check red. Git does not track empty directories, so the skeleton is a local convenience.
13Default check commands.Detected for Rust (cargo clippy --all-targets -- -D warnings · cargo test), Python (ruff check . · pytest -q), Node (npm run lint · npm test) and Go (go vet ./... · go test ./...). Anything else gets a command that fails with "set check.lint" / "set check.test in .keel/config.toml", because a gate that passes on nothing would be worse. code_paths defaults to ["src/", "tests/"] everywhere, with a comment to adjust it.
14mr setup hand-off.Printed, not run: it needs the human's identity and key, and an agent must not register itself.
15Router lessons provenance.references/lessons.md keeps Trawler's "what happened → rule" lines nearly verbatim, ports and tools included. They are the evidence behind each rule, and the rules themselves are generic. Only the session id and cargo xtask mentions are generalised.
16Command-existence test depth.The test checks the first word after keel against run()'s arms. Sub-words (mr confirm, notes write cr) are not checked. They are few and were checked by hand against mr.rs / notes.rs.
