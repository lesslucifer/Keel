B9 · Strip GIT_INDEX_FILE in check_push's scratch path proposed: E-SEED3

Pre-existing; found by the E-SEED2.W13 review r2 verifier. B13 · Check 8 passes when an archived epic report is missing proposed: E-GATEFIX blocker, waived once for the E-SEED2 close

FindingWhen an epic's attested report is untracked or archived (docs/.archive/) and the local file is missing or unreadable, src/mr.rs report_hash returns Ok(None). manual_review's match has three arms: Ok(Some(h)) if h != hash (red), Err (red) and a catch-all _, which returns Ok(Some((path, hash))). So check 8·manual-review passes without re-hashing anything. src/gate.rs then copies that report and hash into the dod/v1 receipt as attested, although nothing was verified on this machine. Editing an archived report turns check 8 red (tests/mr.rs), but deleting it turns check 8 green. That breaks the stated contract: the comment above the match says "an attestation is never ignored", and DEC-40 says a report in a note is re-hashed whatever the policy.
OriginPre-existing on main 0dad93f: report_hash already returned Ok(None), and the arm was _ => Ok(()). E-SEED2.W2 rewrote that match and widened the gap into the new dod/v1 receipt. Found by the E-SEED2 epic review (one round, epic tip e184f1e, correctness finder; a fresh verifier confirmed it and raised it to blocker).
WaiverOwner ruling 2026-11-10, one time, the E-SEED2 close only: the blocker is waived, not fixed, and the epic's cr/v1 records PASS by this waiver. keel notes write cr takes only the verdict and counts, so the waiver lives here (and in the archived E-SEED2 epic result), not on the note (see B12). Until the fix lands, an archived epic report must stay on disk at its path until the epic merges, because the gate would not notice it missing. Since E-CRCAP a waiver like this one is recordable as WAIVED (UC-REV-2); this note stays as it was written.
Fix sketchA missing or unreadable local report is red at check 8, with a fix -> line naming the path. Regression test first: delete an archived epic report after mr confirm, and verify-dod epic turns red on 8·manual-review, writing no dod/v1.
Review nits (same round, not fixed)(1) src/mr.rs report_candidates runs one git show <tip>:<path> per changed .html, deleted paths included, at sign-off; one git cat-file --batch or a --diff-filter=d pre-filter would do. (2) src/main.rs hook_conflicts / hooks_problem_of call a stale Keel core.hooksPath (the repo was moved or renamed) "another tool's setup". The refusal is the DEC-23 contract and --force is the documented recovery, but the message is wrong for that case.

B14 · The check cache ignores HEAD and MERGE_HEAD proposed: E-GATEFIX

Findingsrc/main.rs tree_key keys the keel check green cache on the working tree's hash plus the lint and test commands only. A test whose result depends on HEAD or on a merge in progress can reuse a green verdict cached for the same tree under another HEAD.
HistoryOn 2026-11-10 the owner's merge of epic/E-SEED2 into main (0dad93f) was refused: the pre-merge-commit keel check failed self_hosting_clone_is_gated_and_init_is_a_noop. The test cloned the committed HEAD, which was still main's, while the build embedded the merged skills/. So every merge that changes a shipped skill failed, though skills/ and .claude/skills/ agreed on both branches. E-SEED2.W14 fixed the test: the clone now takes the source's index, the merged result. The regression test is self_hosting_check_passes_mid_merge_of_a_skill_change. The cache did not cause that failure, because the main checkout ran fresh. Owner ruling 2026-11-10: every code review of W14 and of the E-SEED2 re-gate is waived, and their cr/v1 PASS records the waiver, not a review (see B12; since E-CRCAP such a waiver is recorded as WAIVED, UC-REV-2).
Fix sketchAdd HEAD and MERGE_HEAD (when present) to the cache key. Regression test: the same tree under two HEADs runs the check twice.
Second refusal (E-SEED2.W15)The re-gated merge was refused again, in the hook's keel check. Six tests/mr.rs fixtures failed with git rev-parse epic/E-SEED2^{commit}. Git exports GIT_REFLOG_ACTION="merge epic/E-SEED2" to its hooks. A fixture's own git merge keeps an inherited value, and the fixture's keel then reads it (src/gate.rs) as its merge source. W14's mid-merge test ran cargo test by hand, outside the hook, so it could not catch this. W15 fixes it: keel's child spawns and the tests' common::cmd strip GIT_HOOK_ENV (the reflog action, editor, author and committer variables). That real merge then exposed five tests/router.rs fixtures that read Keel's config through HEAD, the W14 class again; cargo's stop at the first failing binary had hidden them. They now read the file from disk or use common::self_clone. Both fixes were proven by the real git merge --no-ff epic/E-SEED2 in a scratch clone with hooks installed. The owner waived every review. Lesson: a gate fix is done only when the real merge, through the real hook, passes in a scratch clone.

B20 · An epic-close archive commit becomes a walked seam when a review fix follows proposed: E-GATEFIX

The close writes the epic's doc note (with --distill) on the archive commit while it is the tip. A fix after the epic review makes that commit a plain first-parent seam, and the walk gates it as a standalone commit: its note, written for the epic range, is red there (6·doc-note), and keel notes write writes only on HEAD, so the note can be rewritten only from a checkout of that commit. Fix direction: run the epic review before the archive commit, or let keel notes write take a commit (--tip) for a standalone note, or have the walk accept an archive commit whose note covers the epic range.
