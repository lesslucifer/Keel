Follow-ups

  • A review worker can still write through Bash. The Write tool is denied, but cat > file in the sandboxed shell is not, and sh -c 'git commit …' would pass the deny list. Closing this would take a review-specific sandbox that denies writes to the worktree, while the target/ that keel check needs stays writable. That is a candidate backlog row next to R10.
  • A finished review worker's row read state: blocked with status: idle and no waitingFor. W9's facts would call it STUCK, not DONE. Worth a check in W5 or W7.
  • A host outside the sandbox makes a worker wait (blocked · sandbox request) until the command's own timeout. The brief asks for timeouts, and the watchdog reports a wait.
  • The full cargo test run under the sandbox was not probed; only --no-run was.
  • W7: the e2e covers worktree add, a --review spawn and worktree remove.
  • htmldoc: the server does not know the ids of docs/decisions/router.html and docs/backlog/e-router-v2.html, so neither has a snapshot (as in W9).
