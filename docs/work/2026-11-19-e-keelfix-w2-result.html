What happened

The one exception: words after keel hook <name> are git's, never help, so a push to a remote named -h is still gated. verify-dod, preflight and notes write refuse an argument they do not know, exit 1, before anything is read or written. Deviations from the plan

  • The strict option reader lives in src/notes.rs (notes::args_problem), shared by gate::opts and notes::known_args. The plan gave the gate its own parser. The existing guard cli::the_target_grammar_is_written_once_in_notes refuses the --target form outside src/notes.rs, so the gate's first version failed it. gate::opts now returns only whether to write the receipt; the target is still read by target_of, unchanged.
  • One line in main(), not two: help::exit_if_asked(); reads the arguments, prints and exits. src/main.rs changes by that line and mod help; only.
  • The notes writer's refusal reads keel notes: refused - notes write doc: unknown argument '--distil', with the kind's usage on its fix -> line. The plan wrote unknown argument '<a>' for notes write <kind>; same content.
  • A test fixed before green: no_receipt_runs_the_whole_gate_and_writes_nothing expected the dry run's output to be the gate's plus one line. The gate prints wrote refs/notes/dod on … last, so the dry run's output is the gate's with that line replaced by no receipt written (--no-receipt). The test now asserts that.
  • Open point 6 reversed (review round 1, B1): help on the hook commands is limited to keel hook alone (or with help before hook). Git runs keel hook pre-push "$1" with the remote's name, and a remote may be named -h or --help; reading that as help skipped the whole push gate. Every word after a hook's name is now git's.
  • A flag's value is never another known flag (review round 1, I2). notes write doc --distill --target --target epic/x passed the strict check, then the flag-by-flag readers took --target as the target. notes::args_problem now refuses such a value, so both readings agree.
  • A guard that each dispatched command has its own usage (review rounds 1 to 4): the test every_dispatched_command_has_its_own_usage reads the whole program's production code and fails closed. A command keel dispatches must have its own help row, and every row must lead to a dispatched command. A shape the guard cannot read is an error, "unreadable dispatch at file:line", never skipped.
    • Read: every module main.rs declares and every module those declare (mod, pub mod, pub(crate) mod), each cut at #[cfg(test)] + mod tests.
    • Understood, in a dispatcher (run(), gate::verify_dod, gate::preflight_cmd, mr::run, notes::write, notes::known_args): slice-pattern arms (wrapped | [..] => lines too), let, if let and matches! patterns, args.first() == Some(&"w"), and string arms. A pattern nested under => match <name> { is placed under its arm's words.
    • Refused anywhere: a declared module it does not read; a slice pattern holding a word outside every dispatcher; Some([, Ok([, Err([, @ [ or @ ( with a word.
    • Refused by default in an argv reader (a dispatcher, or any fn with an args, rest, flags or paths parameter of type &[&str]). Every literal word is refused unless one of three things holds:
      • it is read: a slice pattern's leading word, a string arm's head, or w in args.first() == Some(&"w");
      • it is a plain value: not in an arm's head or guard, not in a let pattern, not inside matches!, not next to == or !=, and not inside Some(, Ok(, Err( or a comparing method;
      • it is on a reviewed line.
      So a word bound then compared in a guard, Some("x") in an arm or an if let, a tuple arm, a word after a binding, a const, tuple or nested element, and a [ with no ] are each refused.
    • Reviewed exceptions: nine lines that compare a word yet select no command (a git ls-tree line, mr setup's key-type prefixes, mr confirm's level, tip and tier, the cr writer's verdict, help's own hook check).
    • Known limit: a word reaching a dispatch through a function that is not an argv reader, such as gate::level_of, whose levels are values, not commands.
    One command list driving both dispatch and help was the review's preferred fix; it would mean rewriting run(), which W1 and E-DOCSPLIT edit and which the plan leaves alone.
  • Open point 2: W1 had not landed in epic/E-KEELFIX when W2 was built, so run()'s top and init usage lines stay literals; src/help.rs holds equal copies, kept equal by each_usage_error_prints_the_help_text.
