What happened

Delivered as planned. With no setting, a review runs at most 3 rounds: round 1 reads the whole work, round 2 only the fix, and round 3 runs only after a round-2 blocker. Three settings in the rules file of the branch the work merges into change that shape. A wrong setting is refused when it is committed and when a review starts.

The main case, as the tests run it

  1. Round 1 reads the whole work and finds a blocker.
  2. After the fix, the tool announces "review round 2 of 3", scoped to the fix alone.
  3. Round 2 finds one medium finding and no blocker.
  4. After the next fix, the tool refuses round 3: "review round 3 runs only after round 2 found a blocker". It names the way on: record the fix without a new round.
  5. That record is written. The merge check reads it as a pass and waits only for your sign-off.
  6. On the epic, a commit setting more whole-range rounds than the cap is refused by the commit hook.

These steps run through the real tool and hooks in the tests. A separate scratch run was blocked by the sandbox.

Differences from the plan

  • A wrong setting already landed blocks the review, never your sign-off. The sign-off's round list then uses the defaults and says so.
  • A refused setting names its own fix: correct the rules file on the branch the work merges into.
  • A second decision record had a sentence naming only the cap. It now names all three settings.
