The problem

Your rule-file commit runs whatever rules sit in that folder, committed or not. So you check the folder's rules file by hand before each one. A worker could also loosen its own folder's rules and commit past them. Separately, keel writes when you only asked: a gate run always leaves a record, and a help request can write a note, a record or even a sign-off. The planned desktop app needs both fixed. This epic fixes them now, while they are small.

Example: a worker loosens its rules

  1. The committed lint refuses a code change.
  2. The worker edits its folder's rules to skip lint and does not commit the edit.
  3. Today its commit lands. After W1 it is refused by the committed lint.
