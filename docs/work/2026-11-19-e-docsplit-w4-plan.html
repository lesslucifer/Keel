The problem

The check now reads a data file, and the sign-off finds the report through it. The skills still teach one HTML page full of tags nothing reads. An agent that follows them writes a result the sign-off cannot find.

After W4, the skills and AGENTS.md teach a page plus a data file, and name no old tag; keel init ships an example pair the check passes.

How you approve

  1. You comment; the worker answers. You tell the router "W4 approved". The build starts once W3 is in the epic.
  2. The worker edits and stages everything it can. It cannot write the second skill copy, .claude/skills/.
  3. The router gives you one command: it copies the skills, fixes one router-skill line, and commits. You read the staged diff, then run it.
  4. Tests, a code review, the result. Your approval of the pull request signs W4.

How you'll know it worked

  • keel init in an empty repo writes the example pair, and the check passes it.
  • No skill names an old tag; keel-plan names every field the check needs.
  • The two skill copies match.
  • All tests pass; the check over all docs is green.

Tests: unit, the embedded list holds the pair. Integration, keel init writes the skills and the pair, and the pair is green. End to end, the installed hooks pass it.
