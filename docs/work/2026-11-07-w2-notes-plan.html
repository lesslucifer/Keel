E-SEED.W2 — Notes

Versioned git-notes schemas and keel notes write, derived automatically from the tree rather than hand-typed by the agent.

Draft v1 · 2026-11-07 · Keel · T2 WU plan · epic: E-SEED · status: draft, awaiting owner sign-off

Requirement

Keel needs a tamper-evident record, attached to commits, of what testing and doc work actually happened — so the merge gate (W3) and manual review (W4) have something to check instead of trusting a claim. This WU builds the schemas and the one write path (keel notes write); it does not build the gate that reads them back (W3) or the signer flow (W4).

Builds on E-SEED.W1, already merged to main: the keel binary, .keel/config.toml loading (Config struct, load_config()), the git()/repo_root() helpers, and the command dispatch in run(). This WU extends that dispatch, it doesn't replace it.

Note on provenance: a worker already built and tested this WU once; it was reverted off main (not deleted — the commits are still reachable in history at 1b79099) because it shipped without this plan doc being reviewed first. This plan describes that same design so you can approve, amend, or reject it before it's re-merged. Nothing below is hypothetical — it's a description of working, tested code, pending your sign-off.

Scope

  • Schema structs (serde → JSON), one per kind: test/v1, doc/v1, cr/v1, plus mr/v1 and dod/v1 defined as structs only (no write command — those belong to W3/W4).
  • A shared identity block on every note: tip, base, branch, committer (Name <email>), timestamp. (Trawler's notes carry epic/WU ids too; cut here since nothing in W2 reads them — later WUs can add fields without breaking /v1 readers, since nothing exists yet to break.)
  • Range: git merge-base <branches.main> HEAD → HEAD. Refuses to run if HEAD already is the merge-base (nothing unmerged to note).
  • Storage: git notes --ref=<kind> add -f on the note commands HEAD → refs/notes/{test,doc,cr}, one JSON line per note. Ref naming matches Trawler.
  • keel notes write doc: records which paths under docs.root changed in the range. No tier classification — that's W5's job, this WU just lists changed paths.
  • keel notes write test: reads a JSON judgment on stdin, e.g. {"unit":{"files":[...],"covers":"..."},"e2e":{"waived":"..."}}. Layers are unit/integration/e2e; unknown keys rejected. Refuses when: a claimed file wasn't touched in the range; a claimed file is missing at the tip; a claimed file has zero detected tests; the file's type has no counting adapter and no config fallback; a layer has both files and a waiver; a layer has files but no covers sentence; the judgment claims no layer at all.
  • Test counting adapters, by file extension: Rust (#[test]/#[tokio::test] lines), TS/JS (it(/test(/.each(), Python (def test_), Go (func Test). Anything else falls back to a config regex ([tests] table: adapter to force one adapter repo-wide, or pattern for the regex fallback). This is deliberately a flat per-extension table, not a per-file override — a polyglot repo leaves adapter unset and relies on extension detection.
  • keel notes write cr --verdict PASS|FAIL [--blockers N] [--importants N]: refuses PASS with blockers/importants above zero. Flags only, no findings detail or fleet data — W2 has no code-review agent to wire up yet.

Maps to

UC-NOTE-1 — "notes write derives the range, the identity, the doc tiers and the test counts from the tree. It refuses a judgment the diff contradicts."

Explicitly not this WU

  • keel verify-dod, merge gate logic — W3.
  • keel mr, signer flow — W4.
  • keel verify-doc, doc tier classification — W5 (parallel, separate WU-plan doc).
  • No changes to Trawler. No changes to docs/work/2026-11-07-seed-plan.html.

Expected result

Per the epic plan: notes written on a fixture tip parse back (round-trip), and a judgment claiming a test layer the diff has no tests for is refused.

Test plan

  • Round trip: write test/doc/cr notes on a fixture tip, read them back via git notes show, assert they parse and match.
  • False claim refused: a judgment naming an untouched file, and one naming a touched file with zero detected tests — assert both are refused and no note is written.
  • CR gate: PASS with --blockers 1 is refused.
