The problem

You chose to read in your browser and sign in your terminal; the app only alerts and links out. Today you find the doc yourself and type the sign-off from memory or from the router's message. With GitHub's flow gone, there is also no pull-request page to read the code on. W4 designs, on paper, what each waiting item opens, what command it hands you, and how the app knows you acted.

How you approve it

  1. You read this plan and comment, or tell the router it is fine.
  2. The worker reads the code and W1 to W3, and writes one result doc. It opens with a picture.
  3. The router tells you it is ready. You open it in your browser and comment.
  4. The router opens a pull request into the epic. You approve it on GitHub. Your approval is the sign-off, and auto-merge merges it.

Terms

Waiting itemOne thing that needs you: a plan to approve, a result to sign, a merge, a rule-file commit, a question.
Hand-offWhat the item gives you: a doc to open, a command to copy, or both.
Done-signalWhat the app sees in git once you acted, such as your sign-off on the tip. Then the item leaves.
DiffThe code changes of a work unit or an epic.

A plan approval has no command: it stays a message to the router, and the item says where to send it.
H4The done-signalWhat the app sees in git once you acted: your sign-off on the tip, the merge on the epic, your trailer on the commit. Each is read with W2's read-only commands. Where no git sign exists, such as a plan approval or an answer to a question, W4 says how the item leaves.
H5The diffThree places compared: your terminal, your editor, and a static page the app makes. Same yardsticks for each: nothing new to learn, a large diff stays readable, a worker's text cannot run, it works without the app. One recommended.
H6The mockupThe macOS alert, and one item's buttons and command, as static HTML. Only the hand-off part: W3 owns the list screen around it.

Details

Where the facts come from

  • Commands: keel's code at cf4c752. The sign-off's usage text is in src/mr.rs (confirm l.607, commit l.581, the mr usage l.1346). The order sign, then merge, is in skill keel-workflow (the sign-off table) and in skill project-router (the sign-off sequences). The worker reads them; it never runs keel mr.
  • Items and jobs: W1's result (the jobs table, needs n1 to n10). Reads: W2's result (the commands that write nothing, the bridge). Screens: W3's plan or result, as far as it has landed.
  • Docs in the browser: skill htmldoc (open from disk, comments by the doc's id, ?diff=latest) and DEC-69 on epic/E-DOCSPLIT (a short page plus a data file).
  • Diff tools: each tool named is one already on your Mac or in today's scripts, or marked "not checked".

Tests and checks

Unit and integration: waived. W4 changes only docs/work/, so no code path changes. The range is exempt from test, review and doc notes. Your sign-off still runs.

The checks the worker runs instead, by a script in a scratch folder, with raw output in the result's evidence:

  1. Every item covered. Each W1 "a button" job (j9, j10, j12, j22), each must or should need that waits on you (n1, n2, n3, n6), and each item the epic's W4 and W3 blocks name (plan, result, rule-file commit, question, failed gate, merge conflict) has a row, or a line saying who acts instead.
  2. Every command real. Each copied command's subcommand and flags appear in keel's usage text at cf4c752 (src/mr.rs), or are plain git. The order matches the skills' sign-off sequence.
  3. Every value checked. Each placeholder in a command names its source and its check, such as a full commit id or a branch name of the expected shape.
  4. Every done-signal read-only. Each is read by a command on W2's list of commands that write nothing.
  5. The diff compared. Three places, the same yardsticks, one recommendation.
  6. Local sources exist. Every repository path cited passes git cat-file -e cf4c752:<path>.
  7. Doc check. keel verify-doc is green on the result.
  8. Scope. git diff --name-only cf4c752..<tip> lists only docs/work/ files.

Sign-off and merge

  • The WU reaches epic/E-LOCALTOOL as a pull request, opened by the router. Your approval of it signs it (the github tier), and auto-merge merges it.
  • The result report is in the range, so the sign-off attests its bytes.
  • GitHub's flow is still today's flow. W4 designs the hand-off for after it; nothing about today's flow changes here.

Overlap

  • E-DOCSPLIT (DEC-69) will split each plan and result into a short page and a data file. W4 only states which one opens: the page. This plan uses today's format. No shared file.
  • W5 owns the task merge (W1 point 2), the backup push (j23) and keel's GitHub commands. W4 links to those questions and answers none.
