E-SEED.W4 — Manual review

keel mr setup|commit|confirm, the local .mr-allowed trust store, an ssh-keygen -Y signature on every WU and epic tip that verifies offline, gate check 8·manual-review, and the commit-msg Reviewed-By check.

v1 · 2026-11-07 · Keel · T2 WU plan · epic: E-SEED · depends on: W3 merge gate · status: ready (dispatch does not wait on sign-off; the owner reviews asynchronously)

Requirement

W3's gate proves the machine evidence (tests, docs, a bound review). Nothing yet proves that a human read the result and said yes. This WU adds that sign-off. A WU or epic tip cannot merge without an mr/v1 note from a signer the local owner trusts. The note attests the exact change and the exact bytes of the result report. For a key-backed signer it carries an SSH signature that anyone can check offline with stock ssh-keygen. A commit that edits the rules the agent works under needs a Reviewed-By trailer from a listed signer.

This is a port of Trawler's xtask/src/mr.rs, its check 8 in gate.rs (check_manual_review / check_attested_report), the commit-msg hook, and the decisions behind them: DEC-9 (SSH signature against a key entry), DEC-10 (mr always at WU tips, attests the result report, .mr-allowed leaves git, commit check narrows to rule-bearing files, boundary-only enforcement) and DEC-27 (sign last). It drops Trawler's interactive wizard, the Secure Enclave signer, the FIDO2 key generation, and native gpgsig commit signing (see open point 7).

Sign and verify. The verifier never trusts a hash written in the note: it recomputes base, tip and change hash from the repo and only takes the report hash from the note, which the signature covers and which is re-checked against the report's bytes.

The .mr-allowed trust store

A plain text file at the worktree root, one entry per line. It is local and never committed. keel mr setup adds .mr-allowed to .git/info/exclude, and every reader refuses to run while the file is tracked, because a trust store that a branch can rewrite trusts whoever wrote the branch. To share it into new worktrees, list it in .gitworktreecopy.

# comments and blank lines are ignored
email: owner@example.com
username: vuluu
key: vuluu ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... optional-comment
TierLineWhat it proves
emailemail: <identity>Nothing cryptographic. The identity is listed, so a note or trailer naming it counts. Anyone who can write a note can forge it. Kept for Trawler parity and low-ceremony projects.
usernameusername: <identity>Same as email; only the label differs.
keykey: <identity> <keytype> <base64> [comment]The identity's mr/v1 notes must carry an SSH signature that verifies against one of its listed public keys. Any key OpenSSH can sign with works: an ssh-agent key, a file key, a FIDO2 sk- key.
  • Identities are restricted to [A-Za-z0-9@._+-]. That keeps them out of allowed_signers pattern syntax (*, ?, ,, !, quotes), since an identity is written as a principal there. A malformed line is a hard error that names the line number. It is never skipped silently.
  • Key wins. If an identity has any key entry, its notes must be signed, even if it is also listed under email or username. The tier written in a note is informational only. The gate derives authority from the roster, so a weaker claimed tier does not get around the signature (Trawler DEC-9 rule, which Keel also applies to notes; see open point 4).
  • Configurable tiers (Q10). New optional config key [mr] tiers = ["email", "username", "key"] (that list is the default). Lines whose tier is not in the list authorise nothing. A project that wants only unforgeable sign-off sets tiers = ["key"]. Adding a future tier means adding code for it plus one list entry; the <tier>: … line format does not change. An unknown tier name in the config is an error.

The signature

The signed bytes are a fixed, newline-terminated text with one field per line:

keel-mr/v1
level: wu|epic
base: <merge-base sha>
tip: <tip commit sha>
change: <git blob hash of `git diff --no-color --no-ext-diff base tip`>
report: <report path>
report_hash: <git blob id of the report's exact bytes>
  • Signed with ssh-keygen -Y sign -n keel-mr -f <keel.signingkey>, payload on stdin. A .pub path signs through ssh-agent. A private-key path signs directly.
  • Verified with ssh-keygen -Y verify -f <allowed_signers> -I <signer> -n keel-mr -s <sig>. The allowed_signers file is generated per check from the signer's key entries only. It is written into the git dir and deleted afterwards. No network, agent or private key is needed: verification works offline.
  • This is Trawler's scheme (DEC-10: a signature over the change hash plus the report hash, namespace-separated) made stricter in three ways. The tip sha and base sha are inside the signed bytes, so a signature cannot be replayed onto another commit or another range. The level is inside. A header line versions the format. The namespace keel-mr stops a Keel signature from being accepted as a git commit signature (git namespace) or anything else.
  • Hashes are git object ids (via git hash-object / git rev-parse) rather than Trawler's shasum -a 256. That needs no new dependency or external tool and matches W2's code_diff_hash. The tip binding relies on git's object hash in any case (see open point 3).

Commands

CommandDoes
keel mr setup --as <id> [--key <path>]Refuses a tracked .mr-allowed and makes sure the file is git-ignored (.git/info/exclude). With --key, it reads the public key (<path> if it ends in .pub, else <path>.pub), appends key: <id> <pubkey> (idempotent), sets git config --local keel.signingkey <path>, then proves the key can sign: a probe payload is signed and verified against the roster, which catches an empty ssh-agent or a missing private half. Without --key, it adds an email: (identity contains @) or username: entry, or just reports the tier if the identity is already listed. A tier outside mr.tiers is refused.
keel mr commit -m <msg> [--as <id>]Commits the staged changes with Reviewed-By: <tier> <id> appended as a trailer, after checking that <id> is listed. --as may be omitted when the roster holds exactly one identity.
keel mr confirm <wu|epic> [<tip>] [--as <id>] [--target R] [--report P]Tip defaults to the current branch. Target follows the gate's rule (--target, else wu/<e>/… → epic/<e>, else main). Steps: (1) the signer must be listed. (2) Sign last (DEC-27): the tip must already pass the gate's checks 1–7 for that level (notes present, PASS, bound to this diff, doc note complete, and for an epic the walk). Any FAIL is printed in the gate's own format and nothing is written. (3) The report is --report, else the single *-result.html under docs.root changed in the range, else refuse. For a WU the report must be tracked at the tip; an epic report may be an untracked local file (it is archived by then, Trawler DEC-3/10). (4) A key-backed signer signs the payload, the signature is self-verified against the roster before anything is written, and the mr/v1 note is stored. An identity-tier signer gets an unsigned note.
keel hook commit-msg <file>Installed as the commit-msg hook by keel hooks install. If the staged diff (--no-renames, so moving a rule-bearing file out also counts) touches a rule_bearing path, the message must carry a Reviewed-By trailer whose identity (last token) is listed. Merge commits are skipped: their content was already authorised on the branch (Trawler parity). Fails closed when keel is missing.

rule_bearing entries ending in / are prefixes, like code_paths. Other entries are globs, where * and ? stay within one path segment and ** crosses segments. So the example ["CLAUDE.md", "docs/*.html"] means T0 plus flat T1, as in Trawler's is_rule_bearing.

mr/v1 note

JSON in refs/notes/mr on the tip, using the shared identity block like the other notes. Fields: tip, base, branch, committer, timestamp, level, signer, tier, report, report_hash, change_hash, and sig (the armored SSH SIGNATURE, present only for a key-backed signer). W2's schema-only MrNote gains these fields.

Check 8·manual-review

This check runs at the top level of every wu/epic verify-dod run (direct and through the hook) and is red on the first cause found. Each cause has its own sentence and its own fix (Trawler E-GATETRUTH.W3):

Red whenCatches
No mr/v1 note on the tipNo sign-off, or a tip amended after signing (git notes stay on the old commit)
The note does not parse or declares another schemaA hand-mangled note
The note's tip ≠ the tip, its level ≠ the gate level, or its base ≠ the current merge-baseA note copied onto an amended commit, a WU note reused for an epic, or a target that moved since signing
The note's change_hash ≠ the recomputed hash of base..tipA diff that changed (on every tier, including unsigned ones)
.mr-allowed is tracked or malformedA trust store a branch could rewrite
The signer is not listed (under an accepted tier) in this checkout's roster; the message names the roster pathAn unlisted signer. The roster is per-checkout by design, so this is distinct from a bad signature (Trawler DEC-10)
The signer is key-backed and the note has no sig, or ssh-keygen -Y verify fails over the recomputed payloadA forged plain note for a key identity, a forged report_hash, a signature by an unlisted key, or any field drift
The report's bytes now hash differently from report_hash. WU: the blob at the tip, which must be tracked. Epic: the blob at the tip if tracked, else the local file if present, else the signature alone attests it.A tampered report
  • Never exempt. UC-GATE-5's docs/infra exemption still skips checks 1–6, but check 8 runs after them in gate::run, so a docs-only WU or epic still needs its sign-off. W3 left its slot in verify(). Check 8 is wired one level up in run() instead, because verify() is re-entered by the epic walk for every seam, and the walk must not re-judge seam sign-offs (next point). verify() stays checks 1–7, which is exactly what mr confirm needs for sign-last.
  • Boundary-only (Trawler DEC-9/10). The epic walk never re-checks a WU seam's mr/v1. The roster is local and mutable, so re-judging old seams would turn authorised history red after a key rotation, and on every fresh clone. The WU's sign-off was judged when its merge hook ran, and the epic tip's own check 8 always runs.
  • The dod/v1 receipt's checks list for wu/epic gains manual-review. Commit level (verify-dod commit, range, pre-push) does not run check 8. This matches Trawler's own scope (open point 17).
  • Policy from the target, not the merged tree. The pre-merge-commit hook reads .keel/config.toml from HEAD, the target's tip before the merge commit exists. A branch cannot change the rules that judge its own merge (open point 14). If the hook cannot tell which branch is being merged, it refuses the merge (open point 15).

Maps to

UC-MR-1 (every WU and epic tip needs an mr/v1 from a listed signer that attests the result report's bytes. It is signed last: mr confirm refuses while test, doc or cr evidence is missing. A key-backed signature verifies offline) · UC-MR-2 (a commit that touches a rule-bearing path needs a Reviewed-By trailer from a listed signer) · UC-GATE-5 (the half that never exempts the human sign-off).

Explicitly not this WU

  • T0–T3 tier classification and the epic tracked-doc layout: W8.
  • Trawler's setup wizard and identity picker, the Secure Enclave signer (trawler-signer, gpg.ssh.program), FIDO2 key generation, and the macOS Touch ID prompt text. Users create keys with plain ssh-keygen and point mr setup --key at them.
  • Native git commit -S signing of rule-bearing commits, and verifying those signatures at pre-push (open point 7).
  • Fetching or syncing .mr-allowed between machines. It is local by design.
  • No changes to Trawler, the seed plan, or the W2/W3/W5 plan docs.

Expected result

Per the epic card: with a throwaway test key, mr confirm followed by a real git merge --no-ff through the installed hook is green and leaves a dod/v1 receipt. A tampered report, an amended tip, an unlisted signer, and a confirm before the cr note are each red, either as a refused confirm that writes nothing or as FAIL 8·manual-review with a fix -> line. A commit that touches a rule-bearing path without a listed trailer is refused by the commit-msg hook, and keel mr commit gets it through.

Test plan

New tests/mr.rs, in the same style as tests/verify_dod.rs: a temp git repo, the real keel binary, and an ed25519 key with no passphrase generated by ssh-keygen in the temp dir. SSH_AUTH_SOCK is removed so the test never reaches a real agent. Lean, following Trawler's suite/mr.rs:

  • Green: mr setup --key → bless (test/doc/cr) → mr confirm wu writes a signed note → git merge --no-ff with hooks installed lands and writes dod/v1.
  • Confirm before cr + unlisted signer: with only test and doc notes, confirm is refused and writes no note. After cr, confirm --as ghost is refused and writes no note. After a valid confirm, dropping the signer's key line from .mr-allowed turns check 8 red, naming the roster.
  • Tampered report + amended tip: forging report_hash in the note → signature red. Changing the tracked report and amending → no note on the new tip → red. Copying the old note onto the amended tip → red (tip mismatch). Each is 8·manual-review with a fix line.
  • commit-msg: a commit touching docs/rules.html (rule-bearing) without a trailer is refused. The same change goes through via keel mr commit, and a non-rule-bearing commit is untouched.

tests/verify_dod.rs is updated: every green path now signs (identity tier, set up in the fixture), and the docs-only test asserts that an exempt WU is red on 8·manual-review until signed, then exempt-green (the UC-GATE-5 rule).
