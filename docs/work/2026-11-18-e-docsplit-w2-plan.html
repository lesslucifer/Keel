E-DOCSPLIT.W2 · The check reads the data file

keel verify-doc checks each plan's and result's data file, and checks the page only for what you read: links, diagram labels, length.

WU plan · v1 · 2026-11-18 · T3 · Keel · W2 of the epic plan · page shape and fields from the W1 inventory (DEC-69)

The problem

DEC-69 moved each plan's and result's checklist from tags in the page to a data file beside it. The check still reads the tags, so a wrong data file passes silently, and no page has a length limit.

After W2, keel verify-doc on either file of a ready plan or result is red, naming the field, when its data file misses, empties or misspells one, and red with the count when its page is over its cap; a draft is silent, and page tags are not read.

What it changes, per file

  • src/verify_doc.rs: reads the data file: its role's fields present and not empty, unknown fields named, a draft silent, WU ids and dependencies resolving, a one-part epic needing both roles. The page keeps links and labels, gains its cap, loses the tag scan.
  • src/main.rs: the write hook and the no-path run take .yaml too; either file checks the pair.
  • Cargo.toml: yaml-rust2 becomes a runtime dependency.
  • docs/decisions/workflow-gates.html: Amended rows on DEC-10 and DEC-52.
  • The task: scripts/ci-gate.sh checks changed data files on GitHub; templates/config.toml sets caps by path.
  • The DSH doc plugin: unbuilt (backlog D1), so nothing changes.

Tests

  • Integration, tests/suite/verify_doc.rs: a missing or empty field is red and named; a misspelt one is named; a draft is silent; a page over its cap, or an epic top over 300, is red with the count; old tags are not read; links and labels unchanged; W1's example data files green.
  • Unit: the fields per role, the caps, the hook's file filter.
  • End to end: W2 starts the epic's tests/suite/docsplit_e2e.rs: the installed hooks refuse a data file missing a field, and pass it fixed. W3 extends it.
