E-ROUTER3.W8 · Router and worker scope; worktree and environment limits — plan

Who does what between the router, a worker, a review worker and the owner, and the limits every worker's session, worktree and shell run under. Each limit names where it is enforced and the test that holds it.

Requirement

A worker started by scripts/router-worker.sh spawn loads the project's settings only and no MCP server, runs its shell inside a sandbox that can write only its worktree, the repository's git dir without its config and hooks, and cargo's cache, and carries one fixed deny list on its command line; the launcher ignores inherited GIT_* variables, refuses a worktree without the worker persona and a name whose launch is in progress, records the worktree's branch at spawn and reports its drift at stop, removes that session's brief copies at stop, lets only a --review worker write the cr note, and creates and removes worktrees for the router (worktree add|remove <branch>); and DEC-46 records every agenda item of the epic plan's W8 block as decided, deferred or rejected.

  R->>L: spawn author into that path

  R->>L: spawn reviewer --review, same path
  V->>R: cr note written, verdict
  R->>L: stop reviewer

  O->>O: signs, merges, pushes
  R->>L: stop author

One WU. The router creates and removes the worktree through the launcher; the author never reviews its own diff; the owner alone signs, merges and pushes. A FAIL verdict goes back to the live author as a message, and the next round gets a fresh reviewer.

The worker session after W8

Spawn argv, in this order (new parts in bold):

claude --bg -n <name> --model <m> --effort <e> --agent worker --setting-sources project,local --strict-mcp-config --settings <sandbox JSON> --allowedTools <grants> --disallowedTools <denies> --permission-mode <mode> <prompt>

The prompt's first action gains one check: env | grep ^GIT_ must print nothing, else the worker reports it and stops.

PartValue
Sandbox JSON (built with jq -n; <git> = the worktree's absolute --git-common-dir)sandbox.enabled: true, autoAllowBashIfSandboxed: true, allowUnsandboxedCommands: false · filesystem.allowWrite: <git>, ~/.cargo (the worktree is writable as the working directory) · filesystem.denyWrite: <git>/config, <git>/hooks, <git>/keel-hooks, <git>/info, ~/.cargo/bin · filesystem.denyRead: ~/.ssh, ~/.claude/channels · network.allowedDomains: htmldoc.wfomobile.com, crates.io, index.crates.io, static.crates.io, github.com
Grants (--allowedTools)Today's eleven cargo and keel commands, unchanged. Inside the sandbox every other shell command runs without a prompt. A --review worker also gets keel notes write cr.
Denies (--disallowedTools, each as Bash(x) and Bash(x *))Kept: keel mr, cargo run. New: keel init, keel hooks, cargo install, cargo publish, cargo login, git push, git config, git update-ref, git symbolic-ref, git stash, git notes, git switch, git checkout, git rebase, git worktree add, git worktree remove, git worktree move, git worktree prune, git -C, git --git-dir, git --work-tree, claude, scripts/router-worker.sh. Every worker but a review worker: keel notes write cr. A review worker: the tools Edit, Write, NotebookEdit and git add, git commit.
What the two layers areThe sandbox is the bound: it holds whatever the command line looks like. The deny list states intent and gives a refusal with a reason instead of a silent failure; a wrapper (sh -c, a cargo test runner) passes it, as DEC-37 and backlog R10 already say.

Launcher changes

ModeAfter W8
every modeFirst line after set -eu: unset $(git rev-parse --local-env-vars), so no inherited GIT_DIR, GIT_WORK_TREE or GIT_INDEX_FILE steers the launcher's git or reaches a session it starts.
spawn … [--review]Refuses a worktree with no .claude/agents/worker.md, naming the file and the fix (merge the base branch that carries it), before any run dir or brief copy exists. Takes a per-name lock (mkdir .router/runs/.lock-<name>, removed on every exit) around the live check and the start; a held lock refuses with the path. Records branch, brief-copy and review in the run dir. RUNNING gains branch=<b>. A detached worktree is refused.
resumeSame lock. Refuses when the worktree's branch differs from the spawn's recorded branch.
stopAfter claude rm: removes every brief copy recorded for that session (each must be a real directory named .router-brief.XXXXXX directly under the session's worktree), and adds drift=<branch now> to STOPPED when the worktree left the spawn's branch. Another session's copy in the same worktree stays.
worktree add <branch><branch> is epic/<E> or wu/<E>/<slug> (plain words, no ..). The base is not an argument: an epic branch is cut from main, a WU branch from epic/<E>, which must exist; an existing branch is used as it is. The path is not an argument: <main checkout>-<branch without its prefix, / as ->, a sibling of the main checkout, which must not exist. Runs git worktree add and prints WORKTREE path=… branch=… base=… tip=…. The prefixes are Keel's (epic/, wu/, main) and a test holds them equal to .keel/config.toml [branches].
worktree remove <branch>Finds the worktree that has <branch> checked out. Refuses the launcher's own checkout and the main one, a session listed with that directory (or an unreadable session list), a dirty tree (git --no-optional-locks status), and a branch that is not an ancestor of its base (not merged: the owner decides). Then git worktree remove, never --force; the branch stays. Prints REMOVED path=… branch=….
guard and settingsOne more alternative in bash_ok: scripts/router-worker\.sh worktree (add|remove) (epic|wu)/[A-Za-z0-9._/-]+, and the deny text names it. Two allow entries in .claude/settings.json. --review already fits the spawn shape.

Expected

  • With the stub claude, spawn starts one claude --bg in the worktree whose argv holds, once each and in the callout's order, --setting-sources project,local, --strict-mcp-config, and a --settings value that parses as JSON with exactly the sandbox keys, paths and hosts of the session table for that worktree's git dir; it holds no user or local source, no --mcp-config, no --add-dir; its deny list is the session table's; its prompt names the GIT_ check.
  • With --review, the argv grants keel notes write cr and denies Edit, Write, NotebookEdit, git add and git commit; without it the argv denies keel notes write cr. --review given twice or with a value is refused.
  • Run with GIT_DIR, GIT_WORK_TREE and GIT_INDEX_FILE naming another repository, every mode behaves as without them and that repository is unchanged.
  • spawn into a worktree without .claude/agents/worker.md exits non-zero naming the file and the fix, starts no session and leaves no run dir and no brief copy.
  • While .router/runs/.lock-<name> exists, spawn and resume of that name are refused with its path and start nothing; after a RUNNING, a DEAD, an UNLISTED and a refused launch no lock is left.
  • RUNNING carries branch=. After stop, the session's brief copies are gone and another session's copy in the same worktree is still there; with the worktree moved to another branch, STOPPED carries drift= and resume is refused.
  • worktree add epic/E-X creates <main>-E-X on a new epic/E-X at main's tip; worktree add wu/E-X/w1-a creates <main>-E-X-w1-a on a new branch at epic/E-X's tip; an existing branch is checked out as it is; each prints WORKTREE path=… branch=… base=… tip=…. Refused with a named reason: any other branch shape, a WU whose epic branch is missing, an existing path, a branch checked out elsewhere, extra arguments.
  • worktree remove wu/E-X/w1-a removes that worktree and keeps the branch, printing REMOVED path=… branch=…. Refused with a named reason: a dirty tree, an unmerged branch, a session listed in that directory, an unreadable session list, the launcher's own checkout, the main checkout, a branch checked out nowhere.
  • The guard allows the router scripts/router-worker.sh worktree add|remove <epic or wu branch> and denies every variant; every allow entry of .claude/settings.json maps to a shape the guard admits; every earlier guard case decides as before.
  • Probes P1 to P4 are recorded with their results, and the live run shows a sandboxed author committing and writing a doc with no prompt, a review worker writing the cr note, and the worktree created and removed by the router.
  • DEC-46 lists all 22 points with their status; UC-ROUTE-2, 5 and 6, the backlog and the epic plan say the same; the keel-router skill and its mirror are byte-identical.

No real claude, no network, no model; no test waits on time (the instant sleep shim for the listing waits); git runs through the suite's hermetic(). The fixture repository gains a committed .claude/agents/worker.md and, for the worktree modes, an epic/E-X branch. What Claude Code does with the flags (the sandbox, the sources, the prompts) cannot be hermetic: the tests pin the argv byte for byte and the probes and the live run prove the behaviour.
