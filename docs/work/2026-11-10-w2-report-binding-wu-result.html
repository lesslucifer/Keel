E-SEED2.W2 · Report binding and hook coexistence — result

Outcome

Delivered against the requirement in the plan. Plan r2 was approved on 2026-11-10. Open questions 1–5 ran on their defaults and choices A–I were applied as written. Every item in the plan's expected list holds at this tip:

  • [mr] report = "required" | "optional" | "none" is read from the target's committed config, with required as the default. Keel's own .keel/config.toml does not set the key.
  • The report is the doc whose data-artifact carries the level's role (wu-result or epic-result), whatever its file name. --report overrides the lookup. The -result.html suffix filter is gone.
  • A missing required report is refused at keel mr confirm and no note is written. At the merge it is a named 8·manual-review failure with a fix -> line. A WU that sets its own policy to none is still judged by the target's committed policy.
  • The payload is keel-mr/v2. Its change_hash and report_hash are sha256:<hex>, and both report lines are left out when no report is attested. The cr/v1 and dod/v1 bindings stay git blob ids (choice B).
  • dod/v1 carries report and report_hash when the verified sign-off attested a report.
  • keel hooks install refuses a foreign core.hooksPath or non-sample .git/hooks entries unless given --force. keel init writes its files and then stops on that refusal.
  • Guard D: keel preflight and keel verify-dod wu|epic are red as 0·hooks while core.hooksPath is unset or not Keel's. keel check warns but keeps its exit code.

Operational rule for the owner

  1. Sign, merge and push each WU with the same installed keel. The merge hook runs whichever keel is first on PATH. A note signed by a pre-W2 binary is red when a W2 binary verifies it, at verify-dod wu, at the WU merge hook, or at pre-push of an unpushed merge. W2 itself is signed and merged with the pre-W2 installed binary, and that is consistent.
  2. After upgrading to a W2 binary, re-sign every signed WU that is not yet merged with keel mr confirm. At this tip W7 (35d2782) has no mr note.
  3. Run keel hooks install in any checkout where it is missing. With a W2 binary, preflight and verify-dod wu|epic refuse as 0·hooks while core.hooksPath is unset or foreign. A checkout with another hook manager needs --force, and that drops the other tool's hooks.
