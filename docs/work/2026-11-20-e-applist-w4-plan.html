E-APPLIST.W4 · The app's frame

The app's locked-down shell, its settings, one project, a signed build and one test alert. It shows no work yet.

The problem

The alert and the list need an app to live in. That app reads worker-written text, so it must be closed to it from day one. And nobody knows yet whether a free signature lets macOS show its alerts.

What you get

  • Keel.app on your Mac, built from this repository.
  • One screen: your project, and where keel, git and claude are.
  • A "Send a test alert" button, which settles whether you need Apple's paid membership.

How it works

  1. The window can only ask the app's core for six named things, such as "add a project" or "send a test alert". Anything else is refused.
  2. The window never sends a path or a command. A folder or a program is chosen in a macOS dialog the core opens.
  3. The core runs git with fixed lines, no shell and git's risky settings off.
  4. It reads your PATH once from your login shell, because git's hooks call keel by PATH.
  5. Settings and the project list live in the app's own folder. Nothing is written inside a project.

What needs you

  1. One typed rules commit, once the app's first tests exist, so the usual checks also run them. The worker sends you the exact line.
  2. At your Mac, at the end: build, install and open the app; add Keel; send the test alert.
  3. Only if no alert shows with either free signature: decide Apple's membership.

The worker does the rest in its sandbox. It cannot open apps, show alerts or use your keychain. A refused download comes to you with its exact command.

What it makes

  • The app's code and tests in the app folder; the build setup.
  • Tests that run on Node alone, so the usual checks install nothing.

How you'll know it worked

  • The app opens, finds keel, git and claude, and says its PATH came from your login shell.
  • Adding Keel lists it; its folder and git status are unchanged.
  • The test alert shows, or the result names the signature that failed and asks you.
  • The usual checks run the app's tests, with nothing installed.
  • Tests prove refusals: an unknown request, a stranger's request, free text, and an inherited git setting.
