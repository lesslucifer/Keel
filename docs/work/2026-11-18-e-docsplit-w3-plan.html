E-DOCSPLIT.W3 · Sign-off, pull request and archive read the pair

The sign-off, the pull request page and the archive find a doc through its data file, and treat page and data file as one doc.

WU plan · v1 · 2026-11-18 · T3 · Keel · W3 of the epic plan · after W2 · its data file sits beside this page

The problem

W2 moved each doc's role into a data file. Three readers still look for it in the page: the sign-off picking the result report, the pull request's doc table, and the archive. A result written the new way is not found, and archiving a pair takes two lineage lines.

After W3, the sign-off, the report note, the doc note and the pull request's doc table read a doc's role, status and title from its data file; a page and its data file archive under one --distill; a page tag alone makes no report.

How you approve

  1. You comment here; the worker answers. You tell the router "W3 approved"; the build starts.
  2. Two rule files go as a task pull request into the W3 branch. You merge it on GitHub.
  3. W3 reaches the epic as a pull request. Your approval signs it; auto-merge merges it.

What it changes, per file

  • src/mr.rs: the report is the page whose data file carries the result role; two are refused, naming both. The sign-off by approval uses the same rule.
  • src/notes.rs: the report note checks the data file and keeps the page. One --distill covers a pair; a page archived without its data file is red.
  • src/verify_doc.rs: reads a data file's role; the page-tag reader goes.
  • The task, rule-bearing: scripts/router-gh.sh builds the doc table from data files; templates/config.toml's report comment.
  • docs/decisions/workflow-gates.html: Amended rows on DEC-27 and DEC-40.

Tests

  • Integration: keel mr confirm wu finds the report through its data file and refuses two; one --distill archives a pair and the epic gate is green; the pull request body reads the data file. Old fixtures become pairs.
  • Unit: the pair matcher, a data file's role, the shared lineage.
  • End to end: tests/suite/docsplit_e2e.rs goes on to the sign-off, the merge and the close.

How you'll know it worked

  • A WU's sign-off names its result page, found through the data file.
  • An epic closes with one archive line per doc, and its gate is green.
  • A pull request page shows each doc's role, status and title from its data file.
