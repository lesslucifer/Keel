The problem

Today your flow is spread over a dozen scripts, the keel tool, git and GitHub. Nobody has listed every job they do for you. If the app is designed without that list, it will miss a job, or do one twice, or start judging work that only keel may judge. So before any screen is drawn, W1 lists the jobs and your needs, and you approve both.

How you approve it

  1. The worker writes one doc: the jobs table and your ranked needs.
  2. The router tells you it is ready. You open it in your browser, as any doc.
  3. You comment where you disagree. The worker answers and fixes the doc.
  4. The router opens a pull request into the epic. You approve it on GitHub. Your approval is the sign-off, and GitHub merges it.
  5. The router then starts the next three steps: the app's parts, its screens, and the hand-off to your browser and terminal.

Terms

JobOne thing the flow does that you would notice, such as "tells you a worker is stuck". A script with three jobs gets three rows.
Taken overThe app does the job itself, in place of today's piece. Only plumbing: watching, alerting, listing.
A buttonThe job stays where it is. The app gives you a button that opens its doc or copies its command.
Left aloneThe job stays as it is. The app may show its result.
DroppedA GitHub flow piece that goes away. The row names what covers it on your Mac. A later step of this epic plans the removal.

In short: read the code at 92611ac, write the table, rank the needs, and check the table against the code both ways. The result report is the deliverable: one doc for you, and your approval signs exactly its bytes.

  • The jobs table. One row per job: what it does for you, the file and function or line it lives in, where its state lives (a git note, a ref, a file under .router/, a background session, the htmldoc server, GitHub), whether that state is per project or per Mac, and its mark.
  • The pieces it covers (from the epic plan): the gate (keel verify-dod, keel check, the git hooks keel hooks installs); the notes; the sign-off (keel mr confirm, keel mr commit); the router guard and the file guard; the launcher router-worker.sh and its watchdog; router-inbox.sh; router-watch.sh; notify-owner.py; the keel verify-doc hooks; htmldoc's comments and versions; the GitHub pieces (the five flow workflows, ci-gate.sh, ci-sign-off.sh, auto-merge, router-gh.sh, router-gh-watch.sh, tasks, the conflict watch, pages-build.sh and Pages, gh-settings-check.sh); and release.yml and the backup push, which stay.
  • Two rules the marks obey. A job that judges (the gate, the notes, the sign-off) is never taken over: the app judges nothing (epic point 2). The terminal keeps working without the app, so no job is marked taken over if that would make the app required for it.
  • Your needs. Each need is ranked must, should or later, and names the job rows it rests on. It starts from your words: notifications at the desk, Telegram when away, the fleet dashboard, what waits on you, the local gate and merge, many projects. The rank is my proposal until you approve it.
  • Candidate use cases for the app (UC-APP-*), a line each, marked draft. They are recorded only when an implementation epic plans them.
  • What W1 does not do: design screens (W3), pick how the app reads keel (W2), design the hand-off (W4), or plan GitHub's retirement (W5). A row may point to the WU that takes it.

Details

Tests and checks

Unit and integration: waived. W1 changes only docs/work/, so no code path changes. The range is exempt from test, review and doc notes. Your sign-off still runs.

The checks the worker runs instead, with their raw output in the result's evidence:

  1. Sources exist. For every source path in the table, git cat-file -e 92611ac:<path> succeeds.
  2. Nothing missed. Every file under scripts/ and .github/workflows/, every keel subcommand in keel --help, every hook in .claude/settings.json and every git hook keel hooks installs has a row, or is named "no job for you" with why.
  3. Every piece covered. Each piece in the epic plan's W1 block and its "What today's flow does" table has a row.
  4. Marks obey the rules. Each row has exactly one mark. No judging job is marked taken over.
  5. Needs traced. Each need names a job row or your words, with their date.
  6. Doc check. keel verify-doc is green on the result.
  7. Scope. git diff --name-only 92611ac..<tip> lists only docs/work/ files.

Sign-off and merge

  • The WU reaches epic/E-LOCALTOOL as a pull request, opened by the router. Your approval of it signs it (the github tier), and auto-merge merges it.
  • The result report is in the range, so the sign-off attests its bytes.
  • GitHub's flow is still today's flow. W1 only lists it; nothing about it changes here.

Overlap

  • E-DOCSPLIT redesigns plan pages into short pages and data files. W1 uses today's format. No shared file.
  • E-GHSETUP stays paused. W1 reads none of its files.
