E-SEED2.W8 · Worker watchdog — result

The launcher gained wait <name> [<stall-min>], which the router runs as a background Bash command so that the command's exit wakes the router. Its integration test passes. Only one thing is still unconfirmed: whether that wake-up actually reaches an idle router session.

T3 · WU result · 2026-11-09 · Keel · branch wu/E-SEED2/w8-worker-watchdog · plan W8 WU plan · wake-up unconfirmed

Outcome

Delivered, with a deviated design. The router's brief replaced the plan's design. The plan had a separate router-watch.sh driven by a watchdog worker that pushes to Telegram. The brief asked for a wait mode in scripts/router-worker.sh, which the router runs directly with run_in_background: true. That mode is built:

  • router-worker.sh wait <name> [<stall-min>] (default 15) blocks while the worker named by .router/out/<name>.pid is alive. It uses the same predicate as the launcher's one-live-run check, now the shared live(). It prints exactly one line and exits 0:
    • EXITED name= pid= out= when the worker exits.
    • STALLED name= pid= idle=<m>m since=<newest file> when two things hold on two consecutive polls: the worker has no <shell> -c child (that is, no Bash-tool command is running), and none of its session transcripts has changed for at least the threshold. That means the main <session>.jsonl and every <session>/subagents/*.jsonl.
    Bad input exits 2. The command only reads files. It never writes <name>.out.
  • The router guard (scripts/router-guard.jq) now also allows scripts/router-worker.sh wait <name> and scripts/router-worker.sh wait <name> <digits>.
  • tests/router.rs covers both of these. All 7 router tests pass (cargo test --test router).

Checked against the live machine, using read-only probes from inside this worker:

  • The transcript path encoding is right. The path is ~/.claude/projects/<worktree with every non-alphanumeric character → ->/<session>.jsonl. The --session-id that the launcher passed this worker names exactly the .jsonl file that grows on every turn.
  • Subagent turns are written to <session>/subagents/agent-*.jsonl. The main transcript stays untouched while a subagent runs. The review found this; see Evidence.
  • A real headless worker has a long-lived MCP child: the Telegram plugin's bun. So "no child process" could never be true for a real worker. The stall probe therefore ignores that kind of child and counts only <shell> -c children. On this machine those are /bin/zsh -c source …/shell-snapshots/…, which is how a Bash tool command runs.

Verified by the integration test, against a real stub process:

  • wait blocks while the worker runs and returns EXITED only after its pid is gone.
  • It returns STALLED on an idle transcript, but not while a subagent transcript is still fresh.
  • It falls back to the pid file when there is no transcript.
  • It does not stall while the worker has a sh -c child running.
  • It refuses bad input with exit 2.
  • jq accepts the guard change.

Six mutations confirm that the test is not vacuous. Each one makes the test fail:

  • Forcing busy() false: the busy case prints STALLED while it should still be blocked.
  • Ignoring subagent transcripts: the case with a fresh subagent prints STALLED early.
  • Forcing the live loop off: EXITED comes back while the worker is held alive.
  • Reporting STALLED on the first quiet poll: it arrives inside the first 2s poll.
  • Dropping busy()'s -c test, or its shell-name test: the idle stub's long-lived non-<shell> -c children are counted as busy, as an MCP server would be, and STALLED never arrives.

Not verified: whether a background command's exit actually wakes an idle router session in this environment. A worker cannot test that. It needs the router's own interactive session (see Follow-ups).

    • The live/busy race.
    • A test synchronized by sleep length, which also idled waiting for the stub to exit and never proved the busy case blocked. The stub is now held until a release file appears, and wait runs in the background so the test can check it is still blocked.
  • Commit df67f7a changes three files:
    • scripts/router-worker.sh: the wait mode, and live() shared with the one-live-run check.
    • scripts/router-guard.jq: the wait shape.
    • tests/router.rs, with these additions:
      • New wait_blocks_until_the_worker_exits_or_stalls, which checks:
        • six argument refusals;
        • EXITED comes only after the stub's pid is gone, with a bounded elapsed time;
        • an exited worker returns one line immediately;
        • STALLED on a transcript aged 2 minutes against a 1-minute threshold;
        • no stall while a sh -c child runs (STUB_BUSY);
        • the pid-file fallback when there is no transcript;
        • n.out is left untouched.

    • A panicking test leaked its stub worker forever. Stubs now exit when the test process is gone. A directory-exists guard was tried first and found unreliable, because the launcher's read-only run directories make TempDir cleanup stop partway.
    • The exited-worker check was weak.
    • The two-quiet-polls rule was untested.
    Two nits were fixed with them: since= now names the newest transcript, and the pid-file case reuses worker 3. The waived nits and their reasons are recorded on the cr/v1 note.
  • Review round 3 (cr/v1 FAIL on f8c19c2) found 1 important, fixed in the next code commit: busy()'s exclusion of non-shell children was untested. The idle stub now holds a subshell piped to cut -c. The 3 nits from that round were fixed with it: one batched stat per poll, refusing an empty stall-min, and testing the no-recorded-run refusal.
  • Docs touched: this report and the WU plan.

  2. Confirm the wake-up from the router's interactive session. While the router is idle, arm scripts/router-worker.sh wait <short-worker> with run_in_background: true, then check whether the router takes a turn on its own when the worker exits. If it does not, the plan's Telegram watchdog design is the fallback.
  3. Router skill usage. Document wait in the keel-router skill (rule-bearing). Arm it with a long Bash timeout (at most 2 h). A timeout wakes the router without an EXITED or STALLED line, and the router then re-arms.
  4. Risk: Telegram dual poller. Every headless worker started with the user's plugins loads the Telegram channel plugin. This worker's own process tree has bun run --cwd …/telegram/0.0.7 as a child. Each instance long-polls getUpdates with the same bot token. Telegram allows only one poller per token: the others get 409 Conflict, and whichever poller wins can consume an owner message that was meant for the owner's session. A follow-up WU could start workers with that plugin disabled (a launcher flag or per-worker settings), or allow send-only use. The launcher itself is not changed here.
