E-WSANDBOX · What a worker may do

A review of the limits on background workers: local ports, app packages, websites and the automatic reviewer.

T3 · epic plan · 2026-11-24 · Keel · its data file, 2026-11-24-e-wsandbox-plan.yaml, sits beside this page

The problem

Workers keep stopping on their own limits, and you do the step by hand. They cannot open a port on this machine, so you ran the app's end-to-end test and 14 tests are switched off. They cannot finish installing the app's packages, so you installed them. The automatic reviewer refused 36 worker commands, many of them harmless scratch work. Some limits keep your machine safe; some only cost your time. Nobody has looked at them together.

Terms

WorkerA background session doing one part in its own folder.
SandboxThe fence around a worker's shell: what it may write and which websites it reaches.
ReviewerThe model that approves or refuses each worker command outside its fixed list.
Local portAn address on this machine that a test or the app listens on.
LaneA step you run by hand: one command, one log.

What you decide

#QuestionAnswer, and why
1Should a worker open a local port?Not by default. A part may get one only if W1 shows it stays on this machine and away from the sandbox's own web relay. The plain switch, tried on 2026-11-15, opened every local service.
2Who runs the 14 switched-off tests?You, in a lane, when an epic touches the alert sender. Rewriting them changes a rule file.
3Should a worker install app packages?Yes, locked versions only, into its own folder, if W1 gets past a write block in one package. Adding a package stays yours.
4May the reviewer open a website for one command?No, if the tool allows switching it off. Today it can, so what a worker reads it could send.
5How do we stop harmless refusals?One fixed scratch helper the reviewer no longer judges. Asking you instead leaves a worker waiting.

How you'll know it worked

  • W1's report settles every unchecked fact, with the raw output.
  • Every ruling, "keep as is" too, is recorded with what it exposes and its limit.
  • A fresh worker runs the same probes, and each result matches your ruling.
  • No change gives a worker your keys, the router's powers or open internet.

Not in this epic

  • Tightening the shared git folder (its own backlog row).
  • GitHub's command-line tool in a worker.
  • The router's own limits, and the other host program.
  • Packaging or signing the app.
