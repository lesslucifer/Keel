E-TESTOPT.W4 · Fixtures built once, copied per test — result

A full cargo test went from about 34 s to about 28.5 s in one session, with the same load, because the repos most tests start from are now built once per run.

T3 · WU result · 2026-11-15 · Keel · branch wu/E-TESTOPT/w4-fixtures off epic/E-TESTOPT 5d2ab18 · WU plan · epic E-TESTOPT plan, block W4

What happened

Delivered. The fixtures of verify_dod, mr, close_walk and router are built once per test process as templates and copied into each test with std::fs. Each test still owns its copy. Any file or link in a copy that names its template names the copy instead, so hooks, a remote, linked worktrees and a signing key all point at the copy. A run starts 25,554 git processes instead of 29,524 (−13 %). cargo test passes 362 tests, the 350 from before under the same names plus 12 new, with 0 failures. No test was removed and no test body changed: only the builders did.

Deviations

  • A smaller gain than the epic plan implied. The epic plan said verify_dod and mr hold 72 % of git calls. That is true, but the per-test profile shows most of those calls are keel's own, made by the steps each test checks. Fixture setup is only 4,865 of 29,524 git processes (16 %). Moving all of it could not save more than that. The four converted builders held 4,565; the run now saves 3,970. The difference is one template build per shape, plus the new tests.
  • Templates are removed when the process exits (ca87016). This was not in the plan. Rust never drops a static, so the first version left one template directory per run in the temp directory (about 390 KB each), and under nextest one per test. 549 were found after this WU's own runs and removed. The templates are now removed through the C library's atexit. A killed run's directory is removed by a later run once it is a day old.
  • The git count is per run, not per test, after the change. A test run alone in its own process builds its templates, so a per-test count would hide the saving. Before and after are both counted per whole run. The per-test profile was taken before the change only.
  • The count is higher than the epic baseline (22,617). This WU's shim also counts git calls made inside hooks. git puts its own git-core directory first on PATH for a hook, so a shim that is only first on PATH misses them. This shim gives git itself as that directory (GIT_EXEC_PATH). Both before and after are counted with this shim.
  • Not converted: the builders in cli, init, verify_doc and seed3_e2e, 300 git processes together, about 7 per test. Plan open point 1.

Each shape checked. verify_dod's four shapes and mr's two record core.hooksPath. mr's key shape also records keel.signingkey, whose file stays mode 600. close_walk records hooks and a remote. router's launcher records two linked worktrees, and its watcher an origin. Each file's each_fixture_copy_is_independent_of_its_template_and_its_siblings asserts that no file of a copy names its template, that the hooks are the copy's own, and that a commit in one copy reaches neither the other copy nor the template. close_walk also asserts the origin and a push, and router the worktree list and the origin. git notes and every other recorded fact are content, not paths, and the 252 old tests pass on copies.
