The problem

The epic's review failed. Three bugs block the merge:

  1. With a git older than 2.45, Open fails on every plan and result.
  2. Marking an item sent holds the app's one-at-a-time queue while the list is read again, so settings wait.
  3. Two reads of one broken app file at once can both move it aside: one fails, or a project you just added is lost.

Seven smaller findings: some rules are written out several times, so a later change can miss a copy. Open reads a doc's role more narrowly than keel does. And each list read reruns git questions whose answers have not changed.

What you get

  • Open works with any git the app already accepts.
  • A mark never stalls the app's other requests.
  • App files are read and set aside one at a time, never lost.
  • Each naming rule written once. Open finds every page keel accepts.
  • A quiet minute costs fewer git runs.

How it works

  1. Each bug first gets a test that fails, then the fix.
  2. Open uses the same old-git handling the list reader uses.
  3. A mark writes in the queue, then waits for the read outside it.
  4. Each app file gets its own one-at-a-time line for reads and writes.
  5. Open and keel check a doc's role against one shared table of cases.
  6. The list reader remembers git's answers until a branch or note moves.
