The problem

Setup leaves three gaps on a fresh clone. The evidence is not fetched: you fetch it by hand. A skill file you never edited still asks before each upgrade. And another program named keel on the path breaks the hooks with no clear message.

The work

1 · Notes fetch (B6)

In short: init adds refs/notes/*:refs/notes/* to remote.origin.fetch, with no +, so a fetch never overwrites local evidence.

  • Added once: present already (with or without +) prints unchanged. No remote origin: init says it skipped, and to re-run after adding one.
  • When it adds the refspec, init prints what a rejected note fetch means and the fix line: fetch origin's note ref into refs/keel-remote-notes/<kind>, then git notes --ref=<kind> merge it. The temporary ref sits outside refs/notes/, so the pre-push sync never pushes it.
  • The refspec is git config, not a tree change: the self-hosting "init is a no-op" test accepts that one line.

2 · Skills lock (B7)

In short: .keel/skills.lock holds a SHA-256 per shipped skill file, in shasum -a 256 form. A differing file whose hash equals its entry was written by Keel and never edited: it is upgraded without asking. Anything else asks as today.

  • An entry is set to this build's hash when init creates, upgrades or finds the file equal. A kept file keeps its old entry, so it asks again next time.
  • The lock is written only when init writes a skill file or the lock exists. A project with no lock whose skills all match gets none. This keeps init a no-op on Keel's own tree, whose skills are copied by hand, so no other WU must maintain a lock.
  • Safe by construction: a file is replaced silently only when its bytes are a version Keel itself wrote.
  • -f overwrites as today and records the new hashes.

3 · Another keel on the path (B7)

In short: Keel's keel --version prints the line Keel: merge-gate workflow CLI. A keel that does not print it is someone else's.

  • init: not on PATH → the warning names docs/install.html as well as the build command; on PATH but foreign → a warning naming its path and that the git hooks will refuse.
  • The four git hook shims gain one line after the not-on-PATH guard: run keel --version, refuse with the clash and the install page when the line is missing.
  • The two harness hooks treat a foreign keel like a missing one and exit 0: they are not gates, and a refusing turn-end hook would block every turn for a machine problem.
  • src/main.rs is touched for the shims only (W3 and W4 also edit hooks there).
  • docs/install.html (rule-bearing) updated: the clash is now detected, upgrades ask only for edited files, and a new clone runs keel init to get the notes fetch. Staged for the owner's keel mr commit.

Expected

After init on a clone, git fetch brings origin's notes; a second init adds nothing; a diverged note ref makes the fetch fail with local notes kept, and init's fix line resolves it. An unedited skill file from an older build upgrades with no prompt; an edited one prompts. A fake keel first on PATH makes init warn and git commit refuse, naming the clash.

Test plan

Integration (tests/init.rs, through the built keel init in scratch repos with a bare local remote, no network):

  • a clone set up by init fetches origin's notes with a plain git fetch; a second init prints unchanged and leaves one notes refspec;
  • a diverged note ref fails the fetch, the local note is kept, and the fix line init printed makes the next fetch pass;
  • no remote origin: init says it skipped the notes fetch;
  • an unedited skill file from an older build upgrades with no prompt, an edited one prompts and is kept, and the lock records what was written;
  • no lock is written while every skill matches and none exists;
  • a fake keel first on PATH: init warns, and git commit through the installed hook is refused naming the clash; with Keel first, the commit passes;
  • no keel on PATH: init's warning names docs/install.html.

Unit: lock parse and format; the per-file decision (create, unchanged, upgrade, ask); the version check; the shims' new guard line and its marker, which must equal Keel's own --version line.

Red first: the integration tests are run red against today's code before the code lands.
