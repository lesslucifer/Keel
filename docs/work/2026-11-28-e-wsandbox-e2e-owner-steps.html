The E-WSANDBOX check: your three steps

This proves the epic works for real. A worker gets ports, packages and the sites the reviewer allows, and is still refused your files. A stopped worker comes back remembering its work. The router and the watchdog close what is finished.

T3 · owner steps · 2026-11-28 · Keel

What happens

You set up the probe clone, sign one config change, and start a test router there. That router does the rest with cheap Haiku workers and ends with a plain report of what every step printed. Then you run one last command: it waits for that report, checks two things and cleans up. Use one terminal. Everything goes into one log: ~/keel-wsandbox-e2e.log.

If a step does not show what it should: stop and send your router the last lines of the terminal, or the log.

1 · Set up the probe clone

cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh prepare

It worked when the last lines say ok: built the epic's keel and then NEXT, the owner types this one line with a line under it. That line is step 2. If it says FAIL:, stop and send the output.

2 · Sign the Haiku setting and start the test router

The setup changed one line, so workers in the clone use Haiku. That file needs your signature, so this step is yours.

cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && keel mr commit -m "probe: haiku workers for the E-WSANDBOX e2e" --as vuluu && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh start

It worked when the last line says ok: probe-router runs (session …). If the commit is refused, or a line says FAIL:, stop and send the output.

While you wait

The test router now runs on its own: a worker's probes, a stop and a resume, the two effort levels, the watchdog's list of what to close, and the cleanup command. It waits for the watchdog at least once, so it is not instant. A Claude Code session cannot message your DSH router, so nothing will pop up: the test router's report is its last message, and step 3 waits for it and prints it. The pass/fail table comes after step 3, from one worker your router starts on the evidence file.

3 · Check and clean up

cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh finish

It worked when it prints the test router's report, then two lines starting PASS, then ok: no probe session, worktree or branch left and Done. It waits for the report before it starts, so it can sit for up to 45 minutes, printing a line a minute. A FAIL on one of the two checks is a result, not a stop: the evidence file is written all the same, so tell your router the run finished and point it at the log and ~/keel-wsandbox-e2e-evidence.txt. If it prints FAIL the probe router has not written its report, it stopped before writing or cleaning anything: send your router the log and run the command again later. Say this: "The E-WSANDBOX e2e run finished. Read ~/keel-wsandbox-e2e-evidence.txt and judge it."

One more check, optional, before step 3

This checks something only you can do by hand: an extra folder you allow a worker during its session is gone after a resume. Do it after the test router's report and before step 3, or skip it. First run the wait command below: it returns once the report is written, without checking or cleaning anything.

cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh wait
  1. cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && scripts/router-worker.sh resume probe-w1
    It prints RESUMED name=probe-w1 id=…. Copy that id.
  2. claude attach <that id>, type /add-dir /tmp and accept it, then leave with the detach key the screen shows (not /exit).
  3. cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && scripts/router-worker.sh stop probe-w1 && scripts/router-worker.sh resume probe-w1
    It prints STOPPED …, then RESUMED … id=…. Copy the new id.
  4. claude attach <the new id>, type /permissions, and look at the folder list: /tmp should not be there. Detach, then tell your router what you saw.
