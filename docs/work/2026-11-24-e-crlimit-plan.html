E-CRLIMIT · A code review stops after 3 rounds, and the schedule is yours to set

Your two rulings of 24 November: a shorter review, and its shape in each project's rules file.

T3 · epic plan · 2026-11-24 · Keel · its data file, 2026-11-24-e-crlimit-plan.yaml, sits beside this page

The problem

A review may run 5 rounds today. Rounds 1 and 2 both read the whole work, so one failed round costs two full reviews. A medium finding can still earn rounds 3 and 4. And the shape is fixed in the tool: a project can move only the cap.

Example: a review that needs all 3 rounds

  1. Round 1 reads the whole work and finds a blocker.
  2. The author fixes it. Round 2 reads only that fix and finds another blocker.
  3. Round 3 reads only the next fix and still finds a blocker.
  4. The review stops, recorded as waived with the open finding.
  5. You read it at sign-off and accept the waiver, or not.

Terms

BlockerA finding that must be fixed before merge (high).
Medium findingMust be fixed, but may be fixed without another review.
Rules fileThe project's settings file, as committed on the branch the work merges into.
The three settingsThe most rounds; how many first rounds read the whole work; from which round only a blocker earns another. Defaults: 3, 1, 2.

What you decide

#QuestionAnswer, and why
1Three settings, or fewer?Three. They answer three separate questions; deriving one would tie two rules to one number.
2Is a misspelt setting refused?Yes. A typo would silently give the defaults.
3Does Keel's own rules file set them?No. The defaults are your schedule; nothing must land first. W2 only fixes a wrong comment there.

Two more points, with their answers, are in the data file.

How you'll know it worked

  • Round 2 reads only the fix of round 1.
  • After a round 2 with no blocker, the tool refuses round 3, and the recorded fix merges.
  • A project that sets other values gets that schedule; a bad value is refused at its commit.
  • Work reviewed under the old schedule still merges.
  • The epic test runs both schedules through the real hooks.

Not in this epic

  • What reviewers look for, or how severe a finding is.
  • The waiver and sign-off rules, beyond the rounds they name.
  • Re-reviewing anything already merged.

For agents: the data file holds the settings and their refusals, each part's files and tests, where the old schedule lives, how the tool checks round 3, the end-to-end test and the distillation plan.
