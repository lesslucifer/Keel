What the D2 epic must still enforce

The checklist is a rule a willing router runs. It is not a guard, and the transcript that started this WU is proof that a known rule does not fail a call. D2 owns these, and this WU leaves them where the plugin can find them:

  • A deny at tools/pre-execute, fail-closed, over every call reduced to plain words exactly as scripts/router-guard.jq reduces it: the read tools, writes under .router/briefs/, the worker tools, the project's watch command and the launcher's shapes pass; everything else is denied with the rule and the alternative named. keel mr, merge, push, tag, claude, kill and any other script never pass.
  • Four agent/turn-stopping checks with agent.steer(), the four failures the checklists name: a worker spawned with no brief file written that turn (DISPATCH.1); a closing message with no What you need to do now: (START.7, WAKE.5); live workers with no wake armed (START.6, WAKE.3); a call denied that turn that the closing message does not name (WAKE.4).
  • The DSH fleet wake stays a wake, not a poll: one reminder per fleet, re-armed each time, stopped with the last worker. If the plugin can wake the router on a worker's turn end, the reminder goes and this exception with it.
  • When the plugin lands, the checklist is deleted or demoted. Two guards for one rule is how they drift.
