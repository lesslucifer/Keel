Installing Keel

Keel is one binary, keel. It carries the gate and the rules (the skills). There is no Claude Code plugin or marketplace entry. Unix only (macOS, Linux): the CLI and its hooks use sh and Unix file permissions.

1. Install the binary

Pick one channel (prebuilt binaries for macOS and Linux, arm64 and x86_64; stable releases only, from tags vX.Y.Z):

curl --proto '=https' --tlsv1.2 -LsSf https://github.com/lesslucifer/Keel/releases/latest/download/keel-installer.sh | sh   # shell installer, no Rust or Node needed
npm i -g @lesslucifer/keel                                                                                              # npm, global install
brew install lesslucifer/tap/keel                                                                                       # Homebrew
cargo install --git https://github.com/lesslucifer/Keel                                                                # from source, needs a Rust toolchain

The shell installer puts keel in $CARGO_HOME/bin (default ~/.cargo/bin). If that directory is not already on your PATH, the installer also edits your shell profiles. It adds a line that sources an env script to ~/.profile, ~/.bashrc, ~/.bash_profile, ~/.bash_login, ~/.zshrc and ~/.zshenv, and it writes ~/.config/fish/conf.d/keel.env.fish. To leave your profiles alone, run it as … | INSTALLER_NO_MODIFY_PATH=1 sh and add the directory to PATH yourself. Install npm globally: a project-local npm i -D leaves keel off the PATH that git and Claude Code hooks see. Confirm with keel --version, which prints keel <version> and a line saying it is the merge-gate CLI, not keel.so. Do not run cargo install keel: that is an unrelated crate.

Name clash. The npm package keel (keel.so) also installs a binary called keel. With both installed you get whichever is first on PATH. This is an accepted risk (owner ruling, R25) and is not detected by the check below. If keel init prints something unfamiliar, run which -a keel.

2. Check PATH

Claude Code hooks see the login shell's PATH, so check that one:

sh -lc 'command -v keel'

Without keel on PATH the harness hooks exit 0 silently (they do nothing), and the git hooks refuse and tell you how to install.

3. Adopt a repo

cd your-repo
keel init
keel mr setup --as <identity> [--key <path>]   # the human owner only: writes .keel/mr-allowed
git add .keel AGENTS.md .claude/skills .claude/settings.json .codex .agents .gitignore
git commit --no-verify -m "keel init"   # once, to land the policy and the signer roster on main
keel hooks install                       # once per clone (hooks live in the git dir, untracked)

keel init writes the config, AGENTS.md, the six skills into .claude/skills/keel-*, a project-router template, the shared skill root .agents/skills (see below), .codex/hooks.json, and merges two hooks (PostToolUse Write|Edit and Stop) into .claude/settings.json, keeping every other key. The merged harness hooks call the scripts that hooks install writes into the git common dir, and exit 0 when they are absent, so editing in a clone that never ran hooks install still works. That clone is not gated, though: keel preflight and keel verify-dod wu|epic fail 0·hooks until it runs keel hooks install, and keel check warns. It also adds the worktrees directory ([paths] worktrees in .keel/config.toml, default .claude/worktrees/) to .gitignore.

DeepSeek Harness. keel init plants the shared skill root here: .agents/skills is a relative link to ../.claude/skills. A DeepSeek Harness session lists the six keel-* skills through it, and a git worktree checkout resolves the same link. A .agents/skills that is anything else, a real directory, a file or another link, is kept and reported, never replaced; a symlinked or non-directory .agents gets nothing planted and says why.

The three host plugins are profile packages, never project files, so they install once per DSH profile and never into the repo. The hand-off prints these three lines; run them as printed:

dsh plugin --profile <name> add <path>/dsh-auto-review        # permissions: Always Auto Review decides each call
dsh plugin --profile <name> add <path>/dsh-worker-workspace   # a worker session rooted in one worktree
dsh plugin --profile <name> add <path>/dsh-doc-gate           # the doc check at the write, on a host without shell hooks

Auto Review is the permission preset every Keel DSH session runs under: a medium call runs, a high-risk call is denied, and a denial is final. The worker plugin gives the router a session per worktree whose report is its transcript. The doc-gate plugin runs keel verify-doc on each doc write and at turn end; without it nothing checks doc form in a DSH session. Their contracts are use cases: DeepSeek Harness; the reasons are DEC-53, DEC-54, DEC-55 and DEC-56.

4. Upgrade

Install a newer binary, then re-run keel init in each project and commit the result. For each skill file that differs from the new binary's copy, init asks Overwrite? [y/N] (default no) and says whether the file is committed or has uncommitted changes. Missing files are created without asking. Files you added inside a keel-* directory are left alone and listed as extra.

Pass -f / --force to overwrite every differing skill file without asking. Scripts and CI must pass -f: without it init reads answers from stdin, treats end-of-file as "no", keeps the file and exits 0, so an unattended run never updates anything. -f only touches .claude/skills/keel-*; .keel/config.toml, AGENTS.md, .codex/hooks.json and project-router are project-owned and are never overwritten.

keel init and keel hooks install refuse to replace another hook manager: when core.hooksPath points elsewhere, or is unset and .git/hooks/ holds anything but *.sample files, init writes its files, then exits non-zero with Keel's hooks not installed. Keel runs alone; the owner decides, then runs keel hooks install --force (init's -f does not imply it).

Upgrading across the SHA-256 sign-off format (E-SEED2.W2): an mr/v1 sign-off written by an older keel no longer verifies. A WU or epic signed before the upgrade and not yet merged must be re-signed with keel mr confirm on its tip.
