E-SEED — the Trawler workflow, extracted into a project-agnostic plugin

Keel's first epic: lift Trawler's epic → WU → commit workflow (plans, tests, notes, gates, review, human sign-off, distillation) out of a Rust xtask into a Claude Code plugin plus a language-agnostic CLI that any code project can adopt.

v2 · 2026-11-07 · Keel · T3 epic plan · status: ready, all open questions decided

Intent

Trawler's workflow already does its job: AI agents write all the code, git notes prove that work is done, and a merge hook refuses work that isn't. But it is hard-wired to one repo. It uses cargo for every check, hard-codes Trawler's code paths, and keeps its rules in Trawler's own T1 docs. Keel packages it so that init in any repo, in any language, gives that repo the same discipline. Keel ships the rules in a plugin, a single CLI enforces them, and a small config file fits them to each project.

Why now: the workflow has settled (workflow v19, ~50 DEC records of tuning), and each new project would otherwise copy it by hand, drift, and lose the rationale.

Use-case requirements

Keel has no use-case KB yet. This epic creates docs/use-cases/ with these contracts:

IDContract
UC-INIT-1Running init in a git repo of any language writes the config, the T0 block, the Codex symlinks and the hooks. It is idempotent and never overwrites a file the user edited without asking.
UC-GATE-1A non-merge commit on main is refused with branch guidance.
UC-GATE-2A --no-ff merge of a WU into its epic, or of an epic into main, is refused unless every required note is present, parses, and is bound to the exact diff. On green, a dod/v1 receipt is written.
UC-GATE-3The epic gate walks every first-parent seam again. A fast-forward or a --no-verify merge turns the epic gate red, and only a walk_waivers entry with a reason overrides one seam.
UC-GATE-4Gate 0 runs the configured lint and test commands. It proves every merged tree and every pushed tree, and skips a tree whose content already passed.
UC-GATE-5Diffs that touch only docs or infra are exempt from test, cr and doc evidence. They are never exempt from the human sign-off or the epic's tracked-doc layout.
UC-NOTE-1notes write derives the range, the identity, the doc tiers and the test counts from the tree. It refuses a judgment the diff contradicts.
UC-MR-1Every WU tip and every epic tip needs an mr/v1 note from a listed signer that attests the result report's bytes. The note is signed last: mr confirm refuses while test, doc or cr evidence is missing. A key-backed signer's signature verifies offline.
UC-MR-2A commit that touches a rule-bearing path needs a Reviewed-By trailer from a listed signer.
UC-DOC-1Once a governed doc (plan or result) is marked ready, it is verified against its checklist on every write. A turn cannot end while one is red, and drafts stay silent.
UC-DOC-2Any doc with a relative link that does not resolve is red.
UC-DOC-3At an epic tip, no T3 doc is tracked and every changed doc is accounted for in doc/v1.
UC-REV-1The code review judges only the configured code paths and writes a cr/v1 verdict bound to their diff hash. Verified blockers and importants fail it. Each verified nit is recorded with a disposition and does not fail it.
UC-ROUTE-1A router session coordinates worker sessions. It verifies their claims, stages the owner's commands, and never signs, merges or pushes for the owner.

Expected result

  • Keel's repo holds the plugin (.claude-plugin/plugin.json, skills/, hooks/), the keel CLI with its tests, and a marketplace entry, so it installs with /plugin install.
  • In a fresh Python repo (no Rust anywhere), init, then one epic with one WU, then merge to main works end to end. Each tampering case is refused with a check id and a fix → line.
  • The same flow passes in a second fixture language, which proves the config and adapters are the only per-language surface.
  • Keel gates its own work from the last WU of this epic on.
  • No Trawler file changes in this epic.

Per-WU process — plan review before work starts

No WU starts without a reviewed WU plan. For each working unit below, the router writes (or has a worker write) a short WU plan — scope, approach, files touched, test plan — and presents it to the owner for explicit confirmation before any worker is dispatched to implement it. This applies even though E-SEED itself runs ungated (Q12): the epic plan being accepted does not stand in for per-WU sign-off. A worker is launched only after the owner confirms that WU's plan.

E-SEED.W1 · CLI core, Gate 0, hooks

The keel binary, which loads .keel/config.toml. keel lint and keel gate0 run the configured commands and cache by tree content (DEC-11/54). keel hooks install writes the tracked hooks and sets core.hooksPath. pre-commit makes main merge-only, and post-checkout handles .gitworktreecopy and merge.ff=false.

UC-GATE-1, UC-GATE-4

In a fixture repo, a second gate0 run on an unchanged tree is skipped and a commit on main is refused. Repos with no config get a clear refusal.

none

E-SEED.W2 · Notes

Schemas test/v1, doc/v1, cr/v1, mr/v1, dod/v1, each with the shared identity block. keel notes write derives the range, identity, tiers and counts (DEC-44). Test-count adapters for Rust, TS/JS, Python and Go, plus a config regex fallback.

UC-NOTE-1

Notes written on a fixture tip parse back. A judgment that claims a layer the diff has no tests for is refused.

W1

E-SEED.W3 · Merge gate

keel verify-dod wu|epic|commit|hook|range: checks 1–7 (notes, manifest, review, review base, diff binding, doc note + tier layout, epic walk + walk_waivers), the docs/infra exemption, the dod/v1 receipt, and keel preflight. The pre-merge-commit hook also runs gate0 merge. The pre-push hook runs gate0 push, the range check and the notes sync.

UC-GATE-2, UC-GATE-3, UC-GATE-5, UC-DOC-3

Each check has a red fixture with the expected check id → fix block and a green fixture. A fast-forward-smuggled seam is red at the epic gate.

W2

E-SEED.W4 · Manual review

keel mr setup|commit|confirm, the .mr-allowed trust store (email / username / key tiers, DEC-9/10), the commit-msg Reviewed-By check, an ssh-keygen -Y signature over the change hash plus the report hash, the sign-last refusal (DEC-27), and gate check 8.

UC-MR-1, UC-MR-2

With a test key: confirm → merge is green. A tampered report, an amended tip, an unlisted signer, or a confirm before the cr note are each red.

W3

E-SEED.W5 · Doc governance

keel verify-doc checks the four checklists (epic plan, WU plan, WU result, epic result), collapsed roles, the unknown-tag typo guard, and relative-link resolution. The harness hook scripts (PostToolUse, Stop) read both Claude and Codex edit payloads (DEC-4, DEC-52).

UC-DOC-1, UC-DOC-2

This plan doc, flipped to ready, verifies green. A misspelled tag is reported by name. A Stop on a red doc is refused.

W1

E-SEED.W6 · Skills + init

Skills workflow (levels, sign order, waivers, testing charter), plan, code-review (+ rubric.md universal principles and a project-local rubric file), distill (tiers, KBs, archive), router and the project-router template, and init (config, T0 block, Codex symlinks, docs skeleton, hooks install, mr setup hand-off).

UC-INIT-1, UC-REV-1, UC-ROUTE-1

Running init twice on a fixture repo produces the same tree. Every CLI command a skill names exists, and a test greps the skills for that.

W4, W5

E-SEED.W7 · Packaging + self-hosting

.claude-plugin/plugin.json, hooks/hooks.json, a marketplace entry, the binary distribution path (Q3), and install docs. Keel runs init on itself and its gates turn on.

UC-INIT-1 · all UCs (packaging)

The plugin installs from the local marketplace into a scratch repo, its hooks fire, and Keel's own next commit on main is refused.

W6

E2E test plan

One hermetic e2e per fixture language. Each runs in a temp dir with a throwaway SSH test key and no network. The code-review agent is not run: a test helper writes the cr/v1 note, because the e2e proves the binding, not the judgment.
