E-GHFLOW2.W10 · Result: the sign-off writer signs as itself

A sign-off by approval failed on every GitHub run: the runner has no git identity, so keel stopped before writing the note. The writer now sets its own identity, and a test fails on a Mac the way GitHub did.

Ready v1 · 2026-11-17 · T3 · WU result · Keel · no plan (a one-fix WU, by the router's brief)

Outcome

Delivered, with the fix staged for your commit. scripts/ci-sign-off.sh now sets and exports GIT_AUTHOR_NAME, GIT_AUTHOR_EMAIL, GIT_COMMITTER_NAME and GIT_COMMITTER_EMAIL to keel-sign-off / keel-sign-off@users.noreply.github.com right after export LC_ALL, and the per-command prefix on git notes merge is gone. Before, keel ci sign-off called git var GIT_COMMITTER_IDENT for the note's committer; on Linux git guesses no identity, keel exited 1, and the script posted "Approval not signed: a check before the sign-off is red". So no approval could ever sign on GitHub. keel's own git calls keep these variables: git() in src/main.rs uses no_git_env(…, true), which drops the author and committer variables only for child commands (keep_index false), never for keel's own calls. Also, a keel error that is neither a refusal nor a red check is now named by its own keel: line in the status.

Deviations

No plan doc, and no W10 block in the epic plan (it is archived): the router's brief allowed a plan-less WU for one fix. The optional wording change (brief step 3) was done, with its own test, since it stayed one line.

Evidence

Cause, seen on a Mac. The test runner's clone now has user.useConfigOnly=true and no [user], and EMAIL is unset, so git refuses to guess, as on Linux. With 366a9eb's script the writer printed keel: git var GIT_COMMITTER_IDENT failed: Committer identity unknown … fatal: no email was given and auto-detection is disabled and posted failure "Approval not signed: a check before the sign-off is red".

Red, then green. cargo test --test suite sign_off::the_writer with 366a9eb's script: 7 passed, 5 failed. Four are the ones GitHub fails (…_signs_a_listed_approval…, …_merges_a_notes_ref_that_moved_on_origin…, …_acts_only_on_a_review_run…, …_says_who_signed_an_already_signed_tip…); the fifth is the new wording test. With the staged script: all 35 sign_off:: tests pass. The test harness sets no identity of its own, so it cannot hide the bug.

Tests changed (tests/suite/sign_off.rs): the harness's refusal of a guessed identity; in the_writer_signs_a_listed_approval…, the note's committer and the notes commit's author and committer are exactly keel-sign-off <keel-sign-off@users.noreply.github.com>; new the_writer_names_a_keel_error_in_the_status_never_a_red_check (a stub keel that fails as keel did).

Commits: 927ddc5 (the tests), this report's commit; the script waits for your keel mr commit.
