E-GHFLOW.W2 · The router bot pushes work branches and opens pull requests

One fixed-shape script lets the router push wu/ and epic/ branches and run their pull requests as a GitHub App, never as you.

Ready v1 · 2026-11-15 · T3 · WU plan · Keel · epic plan: 2026-11-15-eghflow-plan.html

The problem

A pull request needs a pushed branch, and today only you push. So every finished WU waits for you at the terminal before GitHub can show or check it. Workers must never hold a GitHub credential, and the router must never push as you: you could not approve a pull request you authored.

What changes for you

WhenTodayAfter W2
A WU is finishedYou push its branchThe router pushes it as the App; the pre-push hook still runs
You want to see the work on GitHubNothing until you pushA draft pull request into its epic, with links to the plan and result and the notes on the tip
A pull request merged on GitHubYou pull by handThe router fast-forwards the local epic branch
Once—You create the App and place its key (the result report gives the exact steps)

You still sign and merge as today. Main never changes from the router.

Example

  1. A worker reports W3 done. The router runs scripts/router-gh.sh push wu/E-GHFLOW/w3-watch; keel check and the range walk run in the pre-push hook, then the branch and the notes reach GitHub.
  2. scripts/router-gh.sh pr-open wu/E-GHFLOW/w3-watch opens a draft pull request into epic/E-GHFLOW. Its body links the plan and result at the tip and lists the notes (test, doc, cr PASS round 2).
  3. The worker writes a status line to .router-gh/review.md in its worktree; scripts/router-gh.sh post 12 review posts it as a comment.
  4. scripts/router-gh.sh pr-ready 12 marks it ready. You sign and merge; scripts/router-gh.sh sync epic/E-GHFLOW fast-forwards your local epic branch.

The work

scripts/router-gh.sh pushes a local wu/<E>/<slug> or epic/<E> branch with its notes (never main, a tag or an unknown branch, never forced), opens or refreshes a draft pull request whose base and body are derived by code from the branch and its docs, marks the bot's own pull request ready, posts a worker-written file as a comment, and fast-forwards a local epic branch to GitHub's; it validates every argument before any other step, reads the App key only from the key dir, and never prints the key, the JWT or the token; the router guard admits exactly these shapes.

E-GHFLOW.W2 (epic plan, W2 card; §4 trust model; open points 1 and 4). Use cases UC-ROUTE-1 and UC-ROUTE-6, amended at the epic close; DEC-46 amended ("the router bot pushes non-main branches").

ShapeWhat it does
push <branch>git push of refs/heads/<branch> and every refs/notes/* ref, no +, to https://github.com/<repo>.git; Keel's pre-push hook runs as on any push. A rejected branch is exit 1; a rejected notes ref is a warning line.
pr-open <branch> [--base <main|epic/E>]Base from the name (wu/E/x → epic/E, epic/E → main). Refuses when GitHub's branch is not the local tip ("push first"). Opens a draft, or refreshes the title and body of the bot's open one for that head.
pr-ready <n>Only a pull request the bot opened, from this repo, whose head is the local tip of a wu/ or epic/ branch; GraphQL markPullRequestReadyForReview.
post <n> <body-name>Posts <worktree of the head branch>/.router-gh/<body-name>.md under a fixed header, then deletes the file. The file is a regular file, at most 60,000 bytes, UTF-8, no control character but tab and newline; @ mentions are made inert.
sync <epic/E>Fetches GitHub's epic/E; fast-forwards the local branch (in its worktree when checked out, which must be clean); refuses anything but a fast-forward.
credential <file> <op>Not a router shape (the guard refuses it): git calls it as the one-shot credential helper. get prints the token once and deletes the file.

Expected

  • On a scratch repo with Keel's hooks and a bare origin, push wu/E/x runs the hook's [check] and lands the branch and its notes on origin; main, a tag, an unknown branch, any argument starting with - and extra words are refused with exit 2, before any network call, origin unchanged.
  • Against the mock API, pr-open sends one draft request with head and base derived from the name and a body naming the tip, the docs and the notes; the JWT is RS256, signed by the key, issued by the App id, and used only to mint the token.
  • No output of any run carries the key, the JWT or the token.
  • The router guard admits the five shapes and denies every other spelling (flags, a third word, credential, .., quotes, an env prefix).

Tests

Integration (tests/suite/router_gh.rs), hermetic: a scratch repo holding a copy of the script and a committed config, Keel's hooks installed, a bare origin as file://, a fake curl as the mock API, a throwaway RSA key made by the test in a temp home (never a real App key):

  • push: the hook's marker [check] ran; origin has the branch at the tip and the notes; a diverged origin branch is refused (exit 1, origin unchanged); main, a tag, an unknown branch are refused with no request sent.
  • pr-open: the token request carries a valid JWT; one POST with head, derived base, draft: true, the plan's title, a body with the tip, doc links and the cr verdict; an existing bot pull request is refreshed by PATCH; GitHub's branch on another sha is refused with no POST.
  • pr-ready: the bot's draft is marked ready through GraphQL with its node id; someone else's pull request, a fork head or a head not at the local tip sends no mutation.
  • post: the file's text, under the header, mentions inert, then the file is gone; a link, an oversized file, a control character or a missing file sends nothing and keeps the file.
  • sync: an origin merge fast-forwards the local epic, its worktree updated; a diverged or dirty case changes nothing.
  • key and failures: a missing key names the file; a group-readable key, a linked key, a key inside a worktree are refused; an HTTP error prints its code and GitHub's message. Every run is checked for the key, the JWT and the token in its output.
  • the credential mode prints the token once, then nothing, and refuses a file outside its own temp dir.
  • the real curl reads the request config (an unreachable host fails as a network error, not a config error).

Guard (tests/suite/router.rs): the five shapes pass; flags, extra words, credential, .., quotes, env prefixes, a tag or main as a push target are denied; a generated corpus of arguments is admitted by the guard exactly when the script's validation accepts it. The worker deny list, the read denies and the file guard cover the script and the key dir; scripts/router-gh.sh is rule-bearing.

Unit (tests/suite/router_gh_args.rs): argument validation per mode, run with no repo state and a recording curl that must stay silent: each malformed branch, number and body name is exit 2 with its reason.

E2E: not this WU's level (the epic test covers it). The live run needs your App; the result report gives the steps.

Details

  • Rule-bearing files this WU changes, committed once through you: scripts/router-gh.sh (new), scripts/router-guard.jq, scripts/router-worker.sh, scripts/router-file-guard.sh, .keel/config.toml ([github] repo, the script in rule_bearing) and, when the sandbox lets no worker write it, .claude/settings.json's allow lines as an owner step.
  • .router-gh/ joins .gitignore, so a worker's comment file is never committed.
  • Tools: sh, git, jq, openssl, curl; nothing new is installed.
