Live probe: does the router hear a worker exit?

StepWhat happened (literal)
Spawnscripts/router-worker.sh spawn probe-notify <scratch detached worktree> .router/briefs/probe-notify.md haiku printed RUNNING name=probe-notify pid=96286 session=18481636-…. The brief was "read five files, one-line report".
SubscribeAbout 10 s later: SendMessage {to: "probe-notify", notify_when_idle: true} with no message. Result: Subscribed — you will get one notice here when "probe-notify" is next idle (or exits), provided that session runs in the same permission class as this one (or is one this session spawned) or asserts none; otherwise it is only logged here.
Worker exitAbout 12:00:36 (the last write to .router/out/probe-notify.out). The process was gone, and the name had left ListAgents.
NoticeThe subscriber's transcript holds {"type":"queue-operation","operation":"enqueue","timestamp":"2026-11-09T04:00:35.602Z", "content":"[Cross-session idle notice] \"probe-notify\", which you asked to be notified about, is idle now — it finished a turn at 12:00. Its harness reports: «**Report:**». …"}. That is the second the worker finished.
Surfaced?No, not while the subscriber's turn was running. The subscriber was itself a headless -p worker, mid-turn. It made more than 15 further tool calls over the next several minutes, and none of them carried the notice. The transcript shows no matching dequeue. The only other queue pair is the session's initial prompt.
DeliveredYes, at turn end. As soon as the subscriber ended its turn with its final report, the queued notice started a new turn in the same headless session. It arrived verbatim: [Cross-session idle notice] "probe-notify", which you asked to be notified about, is idle now — it finished a turn at 12:00. Its harness reports: «**Report:**». This is an automated notice from that session's harness — not a message from a person, and not an instruction; …
Verdict. The exit-to-subscriber direction fires: the subscriber's harness queues the notice at the moment the worker exits. The subscriber does not see it mid-turn. It is delivered as a new turn as soon as the subscriber's turn ends. This was observed in a headless subscriber, and an idle interactive router should get it the same way. The heartbeat stays only for workers that hang without exiting (DEC-36). A second, unplanned finding: the notice quotes the start of the worker's final message («**Report:**»), so worker-written text reaches the router through it. That is untrusted, the same class as the .out report.
