The problem

Agents write docs that are long, dense and hard to read. Nothing tells them how to write. This epic gives them short writing rules, and makes the tool check what it can.

What changes for you

A planLong. Code and ids from line oneShort. Problem and changes first, in plain words

Any other docNo writing rulesThe same rules

The rules

  1. Short. Cut every word you can. A plan's top fits on one screen.
  2. Direct. Short sentences. One idea each. No filler.
  3. Plain words. No code or ids at the top. Define each term once.
  4. Problem first. Then what changes for the reader, then the work.
  5. Questions, answer first. Each open point is a question with its recommendation.
  6. Details last. Mechanics, tests and history go at the end.
  7. Diagram labels in quotes and plain words.
  8. Show by example. Explain a flow with a real case, in numbered steps.
  9. Check before "ready". Can the owner say the problem, the change and the decision from the first screen?

Example: an agent writes a plan

  1. It loads the writing skill.
  2. It writes the problem in three sentences.
  3. It adds a "what changes for you" table.
  4. It lists the work, then questions with answers.
  5. Mechanics go under Details. It marks the plan ready.
  6. The doc check counts the top: under 300 words, it passes.
