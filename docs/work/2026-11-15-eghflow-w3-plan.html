E-GHFLOW.W3 · The router hears you through GitHub

A read-only watch wakes the router when you comment, review, approve or merge on GitHub. Only your account is heard.

Ready v1 · 2026-11-15 · T3 · WU plan · Keel · epic plan: 2026-11-15-eghflow-plan.html

The problem

The router can open a pull request (W2), but it cannot see what you do there. So you still go back to the terminal to tell it you approved, or what to do next. Anyone may comment on a public repo, so the router must never take a stranger's words as yours.

Example

  1. The router marks W4's pull request ready. GitHub asks you to review it.
  2. The router arms scripts/router-gh-watch.sh review 31 and scripts/router-gh-watch.sh comment 30 (the epic's tracking issue).
  3. A stranger comments /keel go on issue 30. Nothing wakes.
  4. You comment /keel answer 2 B and a second line, "keep the old flag". Within a minute the comment watch prints COMMAND issue=30 comment=… from=5499546 verb=answer n=2 choice=B, your second line indented under it, then IGNORED from=other count=1.
  5. The router acts on it and re-arms the watch with since that comment's id.
  6. You approve pull request 31. The review watch prints APPROVED pr=31 sha=… review=….

The work

scripts/router-gh-watch.sh review|comment|merged|checks <n> [since <id>] reads GitHub through scripts/router-gh.sh's token, read-only, checks at once and then about every 60 s, and exits on the first event from a committed commander with one event line plus escaped detail (or TIMEOUT / UNREACHABLE as router-watch.sh does); other accounts print only as a count, edited comments are never read as orders, control characters print as ?, a comment's first line is parsed by the closed grammar /keel go|hold|retry|answer <n> <A|B>, and nothing is kept between runs; router-gh.sh issue keeps one tracking issue per epic with a sub-issue per WU; the router guard admits exactly the new shapes.

The watch

In short: a new script polls one issue or pull request for one kind of event and exits on the first one from you. It never holds the App key or the token: each poll asks router-gh.sh for the facts, through an internal mode the router cannot call.

KindWaits forPrints
review <pr> [since <id>]A commander's submitted review with an id above sinceAPPROVED, CHANGES-REQUESTED, COMMENTED or DISMISSED pr= sha=<reviewed commit> head=<current head> review= from= pending=; the review's text indented
comment <n> [since <id>]A commander's comment above since, on an issue or a pull requestCOMMAND … verb=go|hold|retry|answer [n= choice=], MESSAGE (free text), BADCOMMAND … why= or EDITED (not read); the rest of the text indented
merged <pr>The pull request closedMERGED pr= sha=<merge commit> head= base= by= or CLOSED pr= head= base=
checks <pr>Every check run and status on the head done (at least one run)CHECKS pr= sha= state=success|failure; each check and its result indented
  • Heard: a user id in [github] commanders, account type User. The bot's own comments are skipped. Anyone else: counted, never printed, and never a reason to wake: IGNORED from=other count=N follows the event line.
  • Without since, every comment or review counts; the watch reports the oldest event and pending= the number after it, so the router re-arms with since <id> and reads each once.
  • A commander's comment whose updated_at differs from created_at prints EDITED and no text: the router asks you to post it again. One at or below since is never read again.
  • With [github] free_text = false, only commands reach the router: their further lines are dropped (text=dropped), and a comment that is not a command is counted as IGNORED from=commander … why=free-text-off.
  • Only issues and pull requests the bot opened are read (a pull request's head must be in this repo).
  • Polls: ROUTER_WATCH_POLL (default 60) and ROUTER_WATCH_MAX (default 6600), as router-watch.sh; UNREACHABLE after 5 failed polls in a row; bad arguments exit 2 before any poll.

The command grammar

In short: a closed list, parsed from the comment's first line only, in a jq module (scripts/router-gh-command.jq) so it is tested alone.

  • A first line starting with /keel (any case) is a command or a bad command, never free text. Words split on spaces and tabs.
  • go, hold, retry: no further word. answer <n> <A|B>: n is 1 to 999, no leading zero; the choice A or B, either case, printed upper case.
  • Anything else after /keel is BADCOMMAND with a one-word reason: no-verb, unknown-verb, extra-words, bad-number, bad-choice, not-keel (e.g. /keelgo). W6 and W8 add their verbs here.

The tracking issue

In short: router-gh.sh issue <epic/E|wu/E/slug> opens or refreshes the issue for that branch. Its text is built from git, like a pull request's body: tip, docs, notes, and for the epic a row per WU branch. A WU's issue is a sub-issue of its epic's. It is closed once the branch is merged into its base.

  • Found again by a marker on the body's first line, among the bot's issues (at most 1000 issues and pull requests listed).
  • A WU's issue needs its epic's issue first (refused otherwise).
  • pr-ready now also asks each commander for a review, when it turns a draft ready.

Expected

  • Against the mock API, a commander's approval prints APPROVED pr= sha=; a stranger's comment holding a command prints IGNORED from=other count=1 and never its text; an edited comment is not a new command; control characters print as ?; two runs on the same answers print the same thing and leave no file behind.
  • The grammar's unit tests: each verb, each bad form with its reason, and a generated corpus where no first line without /keel is a command.
  • router-gh.sh issue opens an epic issue, a WU sub-issue linked to it, refreshes both, and closes a merged one.
  • The router guard admits the new shapes and denies every other spelling; workers are denied the watch; both new files are rule-bearing.

Tests

Integration (tests/suite/router_gh_watch.rs), hermetic, W2's fixture: a scratch repo holding copies of the scripts and a committed config, a throwaway key in a temp home, and a fake curl as GitHub's API. The fake curl now serves a sequence of answers per route (one per call, the last repeated), so a poll sees a change without timing. ROUTER_WATCH_POLL=1.

  • review: an approval prints APPROVED pr= sha=; a pending review and a stranger's approval do not end the watch; since skips older reviews; pending= counts later ones.
  • comment: each verb; a message; a bad command; a stranger's /keel go prints only IGNORED from=other count=1; an edited comment prints EDITED without its text; control characters and bidi marks as ?; the bot's own comment is skipped; free_text = false.
  • merged, checks: merged, closed, checks pending then done, a failing check.
  • TIMEOUT, UNREACHABLE after 5 failures, a pull request the bot did not open refused (exit 2), a config not matching HEAD refused.
  • No state: the same run twice prints the same thing; nothing is left in $TMPDIR, the run dir or the checkout; no token or key in any output.

Integration (tests/suite/router_gh.rs): issue opens, refreshes, links the sub-issue, closes a merged branch, refuses a WU before its epic's issue; pr-ready requests a review from each commander; watch-read refuses another account's pull request and a fork.

Guard (tests/suite/router.rs): the new shapes pass; flags, extra words, since on merged, watch-read, quotes and env prefixes are denied; a generated corpus agrees with the scripts' argument checks; workers are denied the watch; both new files are rule-bearing.

Unit (tests/suite/router_gh_watch_args.rs): the watch's argument check, alone and with nothing reaching curl; the grammar through the jq module, with a generated corpus.

E2E: not this WU's level.
