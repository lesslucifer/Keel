  2. Commit the second rule-bearing set (F12).

  3. Regenerate the workflow. The dist config changed, so release.yml is regenerated here rather than hand-edited. Start from a clean tree.
    1. dist --version should print 0.34.0.
    2. Run dist generate. Then git diff .github/ should show only two kinds of change: uses: actions/…@<sha> lines, and runs-on: "ubuntu-24.04" lines.
    3. dist plan should be green, with four targets and the shell, npm and Homebrew installers.
    4. dist plan --tag=v9.9.9 is expected to fail, because no package has version 9.9.9.
    5. Commit the regenerated file. .github/ is neither a code path nor rule-bearing, so this is a plain commit with no trailer: 
      git add .github/workflows/release.yml
git commit -m "ci(E-SEED2.W11): regenerate release.yml (action pins, ubuntu-24.04)"
    6. Check that the committed file matches what dist generates: dist generate --mode=ci && git diff --exit-code .github/ should exit 0.
    7. Optional licence check: dist build --artifacts=local --target=aarch64-apple-darwin, then list the archive under target/distrib/ and look for LICENSE.
  4. Re-gate the new tip. A fresh worker re-writes test/v1 and doc/v1 on the new tip, runs keel preflight wu <tip> --target epic/E-SEED2, and then runs the code review. The router dispatches an independent review of the regenerated .github/ diff, which no gate reviews. Then the owner runs keel mr confirm wu <tip> --as vuluu --target epic/E-SEED2 and merges --no-ff.
  5. GitHub and npm setup before the first stable tag. These are recorded in DEC-38:

    • HOMEBREW_TAP_TOKEN fine-grained, limited to the tap, with Contents read-write only;
