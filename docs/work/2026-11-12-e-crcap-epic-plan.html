E-CRCAP · The review loop is capped, and an owner waiver is recorded on the cr note

Epic plan for backlog B8 and B12 (owner scope ruling of 2026-11-12). A review loop stops after 3 failed rounds and the owner decides from there. A review the owner waives is recorded as a waiver with the owner's reason, never as a PASS, and the gate checks it.

T3 · epic plan · 2026-11-12 · Keel · branch epic/E-CRCAP off main 1f303dc · plan only; no WU starts before the owner's go
This plan replaces the untracked draft docs/work/2026-11-11-e-crcap-epic-plan.html. That draft was never committed and has no comments on the htmldoc server. It also held a deferral rule ("every follow-up names a WU or an epic"), which the owner's scope ruling of 2026-11-12 leaves out (open point 10).

Intent

Bound the keel-code-review loop, and give a waived review a record of its own. Cap (B8): a WU or an epic gets at most 3 failed review rounds. After the third, the review stops and the owner decides what happens next. Finding scope (B8): a missing edge-case test for code that behaves correctly, or a tidy-up of the test harness, is a nit. A nit never fails a review, so it never reopens a WU. Waiver (B12): keel notes write cr can record the owner's waiver and the owner's reason on cr/v1. The gate accepts the waiver and shows it, and the owner's sign-off consents to it. Today such a review is recorded as a bare PASS. Why now: E-ROUTER3.W2 ran 7 FAIL → fix rounds before the owner capped the loop by hand on 2026-11-11. E-SEED2.W12 was capped by hand on 2026-11-10. Three tips carry a PASS that records a waiver, not a review: E-SEED2.W12's last round, the E-SEED2 close (B13) and E-SEED2.W14/W15 (B14). The cap is a rule an agent has to remember, and the note cannot tell a waiver from a review. Keel's premise is that completeness is proven from git notes, never from an agent's word, and today neither fact is.

Expected result

  • keel notes write cr --verdict WAIVED --reason "<the owner's ruling>" writes a cr/v1 note with verdict: WAIVED, the reason, and the code diff hash. Without a reason, or with only whitespace, it is refused. --blockers/--importants may record what the waived round found.
  • keel verify-dod wu <tip> on a tip whose review was waived prints WAIVED 3·review: <reason> and is red only on 8·manual-review. After a code commit, check 5 orphans the waiver just as it orphans a verdict.
  • keel mr confirm wu <tip> --as <id> on that tip prints the waiver and the tip's review rounds, then refuses and names the acceptance flag. With the flag it signs, and the signed payload carries the waiver. If the waiver reason is edited after the signature, or a PASS is turned into a waiver, check 8 turns red.
  • An epic walk passes a WU seam whose review was waived and prints WAIVED for it. An epic tip can carry a waived review of its own (the E-SEED2-close case).
  • On a WU branch whose first-parent history holds 3 cr/v1 FAIL notes, keel preflight wu <tip> exits non-zero with a 0·review-cap block. The block names the count, the cap, and the owner's choices (continue one round, waive, or stop the WU). No finder is spawned. Rounds 1–3 print review round n of 3.
  • An epic counts only its own rounds, the FAIL notes on its first-parent commits. A merged WU's rounds never count against its epic. Re-running a review on the same tip overwrites that tip's note, so it stays one round. A PASS is not a round.
  • With the owner's "continue", given as a flag that carries the ruling text, preflight admits exactly one more round, and that round's note records the ruling. The round after it is refused again. keel notes write cr applies the same count, so a note for a round past the cap cannot be written without the ruling.
  • [review] max_rounds = 5 in the committed .keel/config.toml moves the cap. With the key unset the cap is 3.
  • The keel-code-review rubric and skill name a missing edge-case test for correct code, and a test-harness tidy-up, as nits. The rubric keeps "a failing case the tests miss" a blocker, because that is a bug and not a missing test. skills/ and .claude/skills/ stay byte-identical (the tests/init.rs mirror test).
  • The epic e2e (below) passes through the real merge hook in a scratch repo.

Non-goals

  • The deferral rule from the 2026-11-11 draft (every follow-up names a WU or an epic, checked by verify-doc). It is outside the B8 + B12 scope (open point 10).
  • A gate check on nit dispositions (Trawler's 3·review-nits). DEC-26 rules it out (open point 8).
  • Changing what a finder or a verifier looks for beyond the two named nit cases, adding or removing dimensions, or changing the verifier batching.
  • Rewriting the existing PASS-by-waiver notes (E-SEED2.W12, the E-SEED2 close, E-SEED2.W14/W15) or any archived result report. B12 and B13 keep the history.
  • Fixing B13 or B14 themselves. They stay in E-GATEFIX; this epic only makes their kind of waiver recordable.
  • An owner-run keel mr command for each ruling. The owner's existing keel mr confirm, with an explicit acceptance flag, is the consent (open points 4, 5).
  • A new note schema version. cr/v1 gains one value and optional fields that older readers ignore (open point 6).

E-CRCAP.W1 · A waived review is recorded as WAIVED, accepted at sign-off and checked at the gate B12

Contract: keel notes write cr --verdict WAIVED --reason "<owner's ruling>" [--blockers n] [--importants n] writes cr/v1 with verdict: WAIVED, waiver: <reason> and the usual identity and code_diff_hash. An empty or whitespace-only reason is refused, and so is a reason on PASS or FAIL. Check 3 accepts WAIVED and prints WAIVED 3·review: <reason>. Checks 4 and 5 apply unchanged. The walk passes a waived seam and prints it. The dod/v1 receipt records review: WAIVED. keel mr confirm (and so sign_ready) on a waived tip prints the waiver and every cr round found on the tip's first-parent history, then refuses without the acceptance flag (working name --accept-waiver). With the flag, the signed keel-mr/v2 payload gains a review: WAIVED sha256:<hash of the reason> line. Check 8 rebuilds that line from the current note, so the payload is unchanged for every tip that is not waived, and existing signatures stay valid. Skill text: keel-code-review §5–§7 (who writes a waiver, and only on the owner's ruling) and keel-workflow §3, §4, §5 and §6 (the waiver row, check 3's WAIVED, the acceptance flag). Rule-bearing: skills/ plus the .claude/skills/ mirror, in one owner keel mr commit, staged and printed by the worker. No gate reviews: that skill text, plus this WU's plan and result under docs/work/. Code (src/notes.rs, src/gate.rs, src/mr.rs, tests/) goes through the cr gate.

E-CRCAP.W3 · A missing edge-case test or a harness tidy-up is a nit and never reopens a WU B8 · scope

Contract (text only): the shipped rubric.md severity rows say what a missing test is. If the code behaves correctly on a case no test covers, that is a nit: nothing observable changes. If the code fails on that case, it is a blocker against the code, and a missing test never is one. A test-harness or test-support tidy-up that changes no test's verdict (helpers, duplication between fixtures, hermeticity polish that no test observes) is a nit. Coverage of the WU's stated contract stays the test note's business, judged at the level the charter names. keel-code-review §5 and §7 say a nit never triggers a fix round and is dispositioned on the note. keel-router's triage line and its supplementary-review rule ("re-review security paths until a round finds nothing above low") take the same 3-round cap as text (open point 9). Rule-bearing: skills/ plus the mirror, in one owner keel mr commit. No gate reviews: the whole WU. It touches no code path, so it is exempt from test, cr and doc evidence (UC-GATE-5) but never from check 8. The router's read-only supplementary review covers the text.

E2E plan

Test: epic_e2e_a_capped_review_loop_ends_in_an_owner_waiver_the_gate_accepts, in a new tests/review.rs, added by the last code WU to land (W2). It is one hermetic flow in a scratch repo built by the test: a temp dir, keel init with hooks inside that scratch repo only, a username-tier test signer, and no network.

  1. An epic branch with a plan, and a WU branch with code, tests, a result report, and test and doc notes.
  2. Three review rounds end FAIL, each on a new tip (keel notes write cr --verdict FAIL, which is the only fleet output the gate reads). The fourth keel preflight wu is refused with 0·review-cap.
  3. The owner's "continue": one more round runs, ends FAIL, and records the ruling. The next preflight is refused again.
  4. The owner's "waive": a WAIVED note with the ruling. keel verify-dod wu is red only on check 8 and prints the waiver. keel mr confirm without the flag is refused, and with it signs. The real git merge --no-ff of the WU into the epic passes the pre-merge-commit hook.
  5. The epic: its own review PASS, its walk prints the WU seam as WAIVED, mr confirm epic signs, and the merge into main passes the hook.
  6. A refusal leg: rewording the WU's waiver after signing turns verify-dod wu red on 8·manual-review.

No waiver of the e2e layer is intended. Lesson from E-SEED2.W15: the flow runs the real merge through the real hook, never verify-dod alone.
