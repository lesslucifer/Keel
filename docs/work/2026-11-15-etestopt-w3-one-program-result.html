Deviations

  • The guard does more than the epic plan's "a .rs file directly under tests/". It also fails on a second tests/<dir>/main.rs, a [[test]] table or autotests in Cargo.toml, and a file in tests/suite/ that main.rs does not declare. That last one is new with the suite: such a file compiles into nothing and its tests silently never run. As the WU plan's open point 2 said.
  • Review round 1 failed (1 blocker, 1 important, 5 nits). Blocker: the guard read only the files directly in tests/suite/, so an undeclared directory module (helpers/mod.rs, a slow/main.rs moved in on the guard's own advice, or x/y.rs under a declared x) never built while the guard stayed green. Important: an unparseable Cargo.toml became an empty table, so the [[test]] and autotests checks passed silently. The fix (43954ae) reads every .rs file under tests/ and walks the mod declarations from tests/suite/main.rs by rustc's rules: comments, strings and raw strings skipped; #[path]; inline mod a { … }; pub and pub(crate); #[cfg] judged on this host (unix, windows, test, target_os and the like, any, all, not) and named as a problem when it cannot be judged, such as a feature. Every .rs file under tests/suite/ at any depth that the walk does not reach is named, with the mod to add. A Cargo.toml that does not parse is now a problem. The nits are all in the fix: the declaration forms above; [[example]] and [[bench]] with test = true are flagged; the stray-file advice says to rename first when the name is main, common or already in the suite, and to bring along the file's own modules; a second tests/<dir>/main.rs gets a move that works (the directory into the suite, main.rs renamed to mod.rs); nothing is pub. Round 2 replaced this resolver (next item).
  • Review round 2 failed (6 blockers, 4 importants, 4 nits), all in round 1's resolver. It disagreed with rustc in nine ways: a #[cfg] or #[path] on an inline module was dropped; an inner #![cfg] was dropped; the cfg evaluator could loop forever on a predicate inside a macro; '\'' and r#type were misread, so a string could swallow code; a #[path] file's children, and a lib.rs or main.rs below the root, were looked for in the wrong directory; and cfg_attr(…, path = …) was ignored. Several of these left a never-compiled test file green. Design chosen: the reviewer's option (a), rustc's dep-info (6778540). The test binary finds <its own path>.d, which cargo keeps next to it and which rustc wrote for exactly that build. Every .rs file under tests/suite/, at any depth, that the list leaves out is named with the fix. Why (a): it is right by construction. rustc decided every mod, #[path], #[cfg], cfg_attr, inline module and macro, so all nine defects and the macro nit go away instead of being patched one by one. And it is the smallest: 244 lines with its tests, against 533. Its costs: it relies on cargo keeping the dep-info next to the test binary, which is not a documented contract. It holds for cargo test, --release, a custom CARGO_TARGET_DIR and nextest, the last three per the reviewer's check. When the file cannot be read, or does not list tests/suite/main.rs, the guard fails and says why: it fails closed, never silently green. Option (b), counting only plain mod x; lines, was not taken. It still reads source text, so a mod x; line inside a multi-line comment or string would still count, and tests/common would have to move, which W1's PATH guard depends on. The static checks are kept: stray top-level files, a second tests/<dir>/main.rs, Cargo.toml targets, an unparseable Cargo.toml. The nits: cfg(true) and cfg(false) need no evaluator now; a file a cfg leaves out on this host gets advice that names the cfg; the walk does not enter symlinked directories, so a link loop cannot hang it.
  • Review round 3 failed (1 blocker, 3 nits). Blocker: rustc opens a file reached by mod x; and lists it in the dep-info even when the file's own first line is a false #![cfg(…)]. Its tests vanished and the guard passed. Round 2's plant had covered only that file's children. The fix (339c524) refuses any inner cfg or cfg_attr attribute in any suite file, so a cfg goes on the mod line. Why that closes it: rustc opens a module file only when its mod item survived cfg-stripping. An outer #[cfg_attr(unix, cfg(any()))] mod x; leaves the file unread and unlisted, as the plant below shows, and the dep-info check names it. Once a file is open, the only thing that drops it whole is an inner cfg, written directly or through a cfg_attr, and the check matches both. It ignores whitespace, so spacing and line breaks inside the attribute do not hide it. It also takes a path prefix (#![core::prelude::v1::cfg(…)]) and refuses a comment between #! and [. A false red from the text, such as an inner cfg written inside a string, is loud. What the guard does not claim: single tests inside a compiled file may still carry their own #[cfg]; that gates a test, not a file. The nits are in the same fix. A .rs file read with include_str! or include_bytes! is refused, since rustc lists it as if compiled. Relative dep-info paths resolve from the workspace root, the crate's directory or an ancestor where the listed tests/suite/main.rs is this one, instead of failing closed in a workspace. The stray-file advice sees pub, pub(crate), #[path] and commented mod lines.
  • The epic plan expected about 38 s from its trial. This session measured 33 to 40 s after against 48 to 50 s before; the load ran from 3 to 55 because other workers were testing, so the after figures are a range, not one number.
  • Two comments still name the old paths: scripts/router-guard.jq and scripts/router-worker.sh say tests/router.rs. Both files are rule-bearing, so changing a comment there needs the owner's keel mr commit; left as they are (follow-ups). The comments in src/init.rs and tests/suite/mr.rs were updated.
