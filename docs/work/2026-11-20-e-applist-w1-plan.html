E-APPLIST.W1 · The router's update log

The router writes down what only it knows, one numbered line at a time, so the app can read it.

The problem

The app will alert you and list what waits on you. Some of that only the router knows: a work unit's stage, an open question, an alert. Today it lives in the router's memory and in Telegram. Nothing the app could read.

What you get

How it works

  1. The router starts. It runs the update command's start, with its name. Both files are wiped; a new run begins.
  2. A worker finishes a plan. The router runs the same command's stage, with the work unit, "plan to read" and its commit.
  3. One line lands: the run, the next number, the time, the change. The state now shows that stage.
  4. You answer a question. The router deletes the question's line by its name.

The router may run only these shapes, in plain words. Free text, such as an alert, comes from later parts, never the router.

How you approve

  1. Tests first, written to fail.
  2. Four rule files, staged alone: the update command, the router guard, the settings allow list and the router's persona. You commit them with one typed command.
  3. A fresh worker re-checks those four files and the tests on that commit.
  4. The result report, the code review, then your sign-off and merge.

How you'll know it worked

  • A start, then a stage, leaves two numbered lines and a state showing that stage.
  • Sixteen writers at once leave sixteen lines, numbered without a gap.
  • The 2,001st line starts a fresh log; the state keeps everything.
  • The guard refuses quotes, extra words and alerts from the router.
  • Tests, lint and the doc check are green.
