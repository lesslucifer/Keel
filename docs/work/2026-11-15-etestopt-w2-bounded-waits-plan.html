The watcher test that takes 20 s and fails in a worker's sandbox becomes a 2 s test that passes there.

The problem

watcher_run_is_bounded_when_the_watch_outpolls_its_releases proves that the router tests give up on a watch that is never released. To prove it, it waits out the router tests' one 10-second bound, twice: 20.1 s, the slowest test by four times. Then it lists processes with ps to check the sleep shim exited. The sandbox blocks ps, so the test fails in every worker's sandbox (backlog R43, second half).

The work

The stepped-watch helpers take their bound as an argument, a test that expects a watch never to move passes a short one, and the check that the sleep shim exited reads the shim's own pid file instead of ps, so the watcher test runs under 3 s and passes in a worker's sandbox while still failing when the helpers stop bounding a never-released watch.

Epic E-TESTOPT, its W2 block · backlog R43, second half · testing charter: no sleep as synchronization, fast and isolated.

In a worker's sandbox, with the CLT git first on PATH (W1 fixes the stock path), cargo test --test router watcher_run_is_bounded passes in under 3 s; it is red today (20.1 s, ps: Operation not permitted). Every other router test passes as before. No production script changes.

  • Stepped::at_within(n, bound) and Stepped::output_within(bound); at and output call them with the 10 s BOUND. Watcher::run_within(…, bound); run calls it with BOUND.
  • The watcher test passes a 500 ms bound to the three "never" waits. Before it asks for poll 2 or the output, it waits for poll 1 under the full bound, so the shims it later checks are known to have started.
  • The sleep shim appends its pid to $STEP_DIR/pids. The test reads every pid there and waits, under the full bound, until kill -0 fails for each one.

Test plan

  • Integration (tests/router.rs): the watcher test itself, red first in the sandbox. It asserts each "never" wait fails with its message, takes at least the short bound and less than BOUND, and that the shims it started (at least two pids) all exit. Mutant checks, each run red then restored green: (1) output_within loses its bound: the test must hang or fail, not pass; (2) at_within loses its bound: the same; (3) the shim stops exiting with its caller (kill -0 "$PPID" removed): the shim-exit wait must fail; (4) the shim writes no pid: the at-least-two-pids assertion must fail.
  • Unit: the bound helper is checked by the elapsed-time assertions above (at least the bound passed, under BOUND). A separate unit test would spawn the same watch; the crate has no in-process seam for these helpers.
  • Sweep: the other slow tests in the baseline (the facts block 5.0 s, the launcher 3.8 to 4.5 s, review, close walk, seed3, mr) wait for nothing to its bound. The launcher's own polls (listed 50 × 0.2 s, the busy stop 60 × 0.5 s) already run through an instant sleep (fast_path). No other test catches a bound's panic. Recorded in the result; no change.
  • Observable: the test's time before and after, and cargo test --test router wall time before and after, in the result.
