Subscription denied in practice. On 2026-11-09 the router keel-fb sent SendMessage to a launcher-spawned worker's name with notify_when_idle: true, once with message empty and once without it. The guard denied both calls with "router guard: SendMessage only as a pure subscription: {to, notify_when_idle: true}, no message", although DEC-36 allows that shape. Cause (E-SEED2.W7 plan phase, from the source): that deny text comes only from the SendMessage branch of scripts/router-guard.jq. It fires when that branch's predicate fails: to is not a string, notify_when_idle is not exactly true, message is non-empty, or the input has a key outside the closed set to, notify_when_idle, message, summary. The predicate admits both shapes the router sent: tests/router.rs router_guard_allows_send_message_only_as_a_contentless_idle_subscription and the e2e epic_e2e_router_drives_a_granted_worker_in_a_seeded_worktree_to_its_end assert exactly those inputs, and main's guard is identical to the epic's. The denied calls therefore reached the hook with a different tool_input than the call as written. The likely case is a key that Claude Code adds or normalises before PreToolUse, which the closed key set rejects; the other possibility is notify_when_idle arriving as something other than boolean true. The synthetic test inputs never saw the real payload.
