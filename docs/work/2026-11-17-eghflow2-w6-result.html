Outcome

Delivered against the requirement, with the deviations below. A task branch wu/<E>/<wu>_<task> is read by keel (notes::task_of) and by the scripts: the bot pushes it, opens its pull request into its WU branch only, never turns on auto-merge for it and gives it no issue; sync fetches a WU branch after you merge a task into it; worktree add cuts a task off its WU branch. On a task branch the commit check takes rule text with no code path (by HEAD's committed code_paths) and no .keel/ path without a trailer, and refuses it everywhere else as before. Deviations from the plan

  • The scripts' branch word already allowed _. The plan said no WU name holds one; that is true of every branch here (114 checked), but not of the grammar. So a task is exactly three words without _ ([A-Za-z0-9][A-Za-z0-9.-]*), in keel and in the scripts alike. A name with _ that is not a task (wu/E/x_, wu/E/x_t_u) stays a WU branch, as before, and the commit check treats it as one.
  • pr-open of a WU refuses any --base, its own epic too. The plan said "no --base but its own epic". Refusing them all lets the guard and the script hold one rule, which the generated agreement test checks.
  • sync of a WU branch with commits of its own prints state=diverged and moves nothing; the WU's worker merges the fetched ref. An epic or main that is not a fast-forward is still refused.
  • New output words: automerge=task on pr-ready of a task; the conflict line is CONFLICT pr=<n> head=<sha> base=<branch> at=<time> (the plan said head=… sha=…).
  • sync and issue of a task are refused by the script and by the guard (a lookahead in its WU-branch word), after the security review. A task has no notes, so its push asks for none.
  • The skills are a patch, not staged: .claude/skills is not writable in the worker's sandbox, so both trees' edits and project-router's are in w6-skills.patch at the worktree root (your step 2). git apply --check passes.
  • Test order: for the commit check and the report rule, the tests came first and were red before the change. The two-tasks test and the malformed-names test were green from the start, as expected: they need no new gate code. The approval-writer test and the scripts' tests were written right after their change.
  • The report rule at the epic level is the same helper the WU level uses (check 8 and the writers read it with the range's base and tip). It has no epic-level integration test of its own; the epic test at the close covers it.
