Deviations

  • The pull request's links are a new "Page" column, not a second link in the "Doc" cell, so the existing body assertions hold. The tracking issue shares the table, so it gains the column too.
  • The builder also writes an index page for the site and one per branch. The plan named no index; without one the site's root is a 404.
  • The plan's "refuses a site over 1 GB" became budgets (the security review's F3): a refusal let one branch stop every deploy. A branch whose files cost more than 100 MiB is skipped whole, and so is one that would take the site past 1,000,000,000 bytes. Each file costs its size rounded up to 4 KiB, and branches are taken main first, then epic/, then wu/. The limits are PAGES_BRANCH_BUDGET and PAGES_SITE_BUDGET, test seams the workflow never sets.
  • Only a doc's file types are published (F2, the default of your ruling above); the plan published every regular file under docs/. A path or branch part is capped at 200 bytes (F3): one over a file system's 255 aborted the build. A new --path mode states the path rule, and router-gh.sh's page link follows it (F4), so no link is a dead one.
  • The builder's fix is in your commit, not mine. The commit hook judged scripts/pages-build.sh rule-bearing by the staged .keel/config.toml and refused it without your trailer, so it joined the staged set.
  • tests/suite/keel_gate.rs's four line readers became pub(crate), so the Pages lock test reads its workflow the same way.
