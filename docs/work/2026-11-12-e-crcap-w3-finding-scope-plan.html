E-CRCAP.W3 · What counts as a nit, and repeat findings are refuted

WU plan under the E-CRCAP epic plan (owner go 2026-11-12, open points 1–16 at their defaults). Skill text only.

T3 · WU plan · 2026-11-12 · Keel · branch wu/E-CRCAP/w3-finding-scope off epic/E-CRCAP d957cd6

Requirement

The review skills name two cases as nits (a missing test for a case the code already handles correctly, and a test-harness tidy-up that changes no test's result), keep "the code is wrong on an untested case" a blocker, record every round's verified findings and refuted candidates on its cr note, refute a later round's repeat of an earlier finding unless the verifier shows at the tip that the earlier fix does not hold, and make the router's own extra reviews follow the 5-round schedule.

Test plan

  • Unit: none. No code path changes (code_paths = src/, tests/).
  • Integration: waived. Reason: the WU changes no code and has no behaviour a test can assert; its effect shows in later reviews. The diff is exempt from test, cr and doc evidence; the test note still records the waiver.
  • The jq step is not code that needs a test. It is a shell line in skill text that an agent runs, outside code_paths, of the same shape as the existing nits step, and the gate ignores the fields it adds. A wrong line is not harmless: piped straight into git notes add -F -, bad JSON gives empty input and git removes the note, so the verdict could vanish (independent review round 1, I1). The text therefore builds the note first and writes only on success, and the reader stops on any unreadable note. The router's read-only review is the check on these lines. Smoke check, not a test: run both snippets (the earlier-rounds reader and the note writer) once in a scratch repo and record the output in the result report.
  • Kept green: the mirror test in tests/init.rs and keel check; diff -r of each changed skill against its mirror.
  • Review: no cr note (exempt diff). The router's read-only extra review reads the text; the owner signs off.

4Does the exception apply to a repeat of an earlier refuted or waived finding?They have no fix, so the fix exception does not apply. Revised after independent review round 1 (B1): a repeat of a waived or refuted entry is refuted only while the code it judged is unchanged since that entry's commit; if that code changed, the claim is new. A claim is a repeat only when it is surely the same defect in the same code; in any doubt it is new. This keeps open point 16 (a reworded repeat of the same defect in the same code still fails) without refuting a defect a later commit introduced.
