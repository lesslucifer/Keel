G2 · The live checks owed on GitHub open

Every behaviour of W1 – W3 is proven by hermetic tests against a fake GitHub. None had run against GitHub at the close: the first push, the App and its key are the owner's. Record each result in the next GitHub-flow epic's first result report. The setup steps are in install.html.

  1. The first workflow run (W1). After epic/E-GHFLOW lands on main and is pushed, a push of any work branch shows "Keel gate" with jobs ci, gate, docs; ci green; gate green on checks 1 – 7 with its evidence table and "8·manual-review: waiting"; "Release" does not run. Also check whether GitHub turns an @name or #number written as entities in a note into a mention or a link.
  2. The bot's push and pull request (W2). scripts/router-gh.sh push <branch> prints PUSHED and GitHub shows the bot as pusher; pr-open prints PR number=… and the draft is authored by <slug>[bot]. Four facts only GitHub proves: the token accepted as x-access-token basic auth over https; GET /repos/…/git/ref/heads/wu/E/x taking a branch with slashes; the Pull requests permission letting the App comment; and, from a real worker session with the key in place, ln ~/.config/keel/router-gh/app.pem ./x failing (the sandbox's read deny also blocks hard-linking the key or a token file out of the key directory; the review's nested sandbox could not test it).
  3. The tracking issue and the watch (W3). scripts/router-gh.sh issue epic/<E> prints ISSUE number=… state=opened; ROUTER_WATCH_MAX=600 scripts/router-gh-watch.sh comment <n> (typed by the owner: the guard admits no prefix) prints COMMAND … from=5499546 verb=go pending=0 within a minute of the owner's /keel go; another account's comment prints only IGNORED from=other count=1. Still unverified, each failing safe: that only a body edit moves a comment's updated_at; that an installation token may read GET /user/{id} (a refusal is a WARN line on pr-ready); the sub-issue calls.

Source: E-GHFLOW.W1, W2 and W3 results ("the first live run"); the epic plan's live evidence.

G5 · Test nits W2 and W3 left open open

Test-only nits from the passing code reviews; none changes a result. W2's were waived by its round 2 PASS; W3's round 2 PASS left them "to fix after this PASS", and no fix followed before the close. Take them in whichever WU next touches these files.

  1. W2 · the fixture rebuild. tests/suite/router_gh.rs rebuilds the Gh fixture, an RSA key included, per test (about 0.25 s each; round 1's waiver).
  2. W2 · a fixture HOME under an odd TMPDIR. The fixture and router_gh_args::check use a raw temp dir as the script's HOME, which the script refuses outside [A-Za-z0-9/._-]; under a hand-set TMPDIR with such a character 28 tests fail, naming HOME.
  3. W2 · the dash test proves less than its doc. every_argument_starting_with_a_dash_is_refused_in_every_position skips slot 0 and the --base word and never asserts the reason may not start with -.
  4. W2 · the guard-agreement corpus costs about 7.7 s serial (507 probes), and router_gh_args::check writes a fresh curl stub on each of its 646 calls.

W3 · tests/suite/router_gh_watch.rs harness. watch_env sets ROUTER_WATCH_MAX=30 for single-event cases (a regression polls 30 s); watch_env and watch_raw do not set ROUTER_GH_GIT; watch_raw's doc does not name every check it skips; lines() trims the whole output, so the CRLF case could pass a regression.
