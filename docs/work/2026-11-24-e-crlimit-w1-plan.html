E-CRLIMIT.W1 · The review schedule, set by three settings

Each project sets how its code reviews run. The tool follows the settings.

T3 · WU plan · 2026-11-24 · Keel · its data file, 2026-11-24-e-crlimit-w1-plan.yaml, sits beside this page · the epic plan is here

The problem

The tool counts review rounds by numbers fixed in its code. A project can change only the cap. A wrong cap is found only when a review starts.

What you get

Three settings in the project's rules file decide the schedule:

SettingWhat it decides
The capThe most rounds a review runs. A blocker still open in the last round ends in the cap's waiver, which you accept or not at sign-off.
Whole-work roundsHow many rounds read the whole work. Later rounds read only the last fix.
Blocker-only fromFrom this round on, medium findings are fixed and recorded with no new round. Only a blocker earns another.
  • The rules file used is the one on the branch the work merges into, never the work's own.
  • A setting left out takes its default value. The default values sit in one place in the code.
  • A wrong setting is refused when it is committed and when a review starts. It names itself.

How it works

  1. Tests are written first and fail on today's tool.
  2. Each test runs several schedules: the default values and three others. What it expects is worked out from the settings, never typed for one schedule.
  3. One rule checks the settings, in four places: the review start, the review record, the commit hook and your rule-file commit.
  4. Old review records stay valid. Nothing is rewritten.
  5. The use case and the decision are updated in place.

What it makes

A change in the tool's review code and its tests, the epic's end-to-end test, two use cases and one decision, and this plan and its result. No instruction file changes: that is the next part.

What you decide

QuestionAnswerWhy
Does a wrong setting already landed block your sign-off?No.It blocks the review, which names the fix. Your sign-off then lists rounds by the default values and says so.
How is this part's own review counted?By hand, on the default values.The installed tool still runs the old schedule until you reinstall it.

How you'll know it worked

  • For every schedule tested, reviews run exactly as its three settings say.
  • A project that sets nothing gets the default values.
  • Each wrong setting is refused, and names itself.
  • Reviews recorded under another schedule still pass.
  • Keel's checks pass.
