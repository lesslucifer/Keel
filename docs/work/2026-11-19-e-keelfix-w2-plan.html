E-KEELFIX.W2 · Nothing written unless asked

A gate run can skip its record, help never runs a command, and a mistyped option is refused.

The problem

Asking keel a question can change your repository. A gate run always leaves a pass record. Asking a command for help can run it: help on a sign-off signs, and help on the notes writer writes a note. A misspelt option is ignored, and the command runs as if it were not there.

Example: help on a sign-off

  1. A WU's tip has its notes and its review. You are about to sign.
  2. You add help to the sign-off command to check an option.
  3. Today it signs. After W2 it prints the sign-off's usage and signs nothing.
  4. You run the gate with the new option: every check prints, it is green, and it says no record was written.

The work

keel verify-dod wu|epic <tip> --no-receipt prints the same checks and exit code as without it and writes nothing; --help or -h anywhere on any keel command prints that command's usage on stdout, exits 0 and changes no ref, note, index, file or config; an argument that verify-dod, preflight or notes write does not know is refused, exit 1, before anything is read or written.

Part 1 · The gate's dry run (src/gate.rs)

In short: the gate reads its options with one strict parser. --no-receipt skips the one write a gate run by hand makes. Everything else stays as it is.

  • A new opts(rest, receipt_ok) reads what follows <level> <tip>: --target R once, and --no-receipt once where allowed. Refused, as keel: verify-dod refused - unknown argument '<a>' plus the usage, exit 1: any other flag, --target=R, --target with no value, a second --target, a stray word, and a tip that starts with -.
  • verify_dod's wu|epic arm and preflight_cmd call it first (preflight takes --target only). target_of is unchanged, so mr confirm still reads --target the same way.
  • run() gains receipt: bool. The hook, range and commit callers pass true. On a green, non-exempt wu or epic with false it skips the receipt (and its diff hash) and prints no receipt written (--no-receipt) on stdout, after the green line. Exempt and red runs print nothing new.
  • USAGE gains [--no-receipt] and becomes pub(crate), for help.

Part 2 · Help on every command (new src/help.rs, src/main.rs main())

In short: before keel does anything else, it looks for a --help or -h word. If one is there, it prints the usage of the command the other words name, and exits 0.

  • src/help.rs: usage_for(args) -> Option<&'static str>. Some when any argument is exactly --help or -h. The command is read from the other arguments' leading words, longest match in the table below; an unknown command gets the top usage. --help=x, -hv and -H are not help.
  • src/main.rs: mod help; and, at the top of main(), before run(): print the usage on stdout and exit 0. So help comes before --version, the repository lookup and mr's checkout check. run() itself is not edited (W1's lines, below).
  • One text per command, shared with that command's own usage error: gate::USAGE; notes::{NOTES_USAGE, TEST_USAGE, DOC_USAGE, CR_USAGE}; mr::{MR_USAGE, SETUP_USAGE, COMMIT_USAGE, CONFIRM_USAGE}, lifted from the four literals in src/mr.rs to pub(crate) consts. The top and init texts stay as literals in run(); help.rs holds equal copies, kept equal by a test (open point 2).

Part 3 · Unknown arguments refused by the notes writer (src/notes.rs)

In short: the notes writer checks its arguments against each kind's list before it computes the range or reads stdin.

  • A new known_args(kind, args) is write()'s first line. Each flag takes the next word as its value, as today's readers do.
  • test: --target. doc: --target, --distill (repeatable). cr: --verdict, --blockers, --importants, --findings, --refuted, --nits, --fleet, --fixes, --target.
  • Refused, as keel notes: refused - unknown argument '<a>' with a fix -> line giving the kind's usage: any other flag, a stray word, a flag with no value, any flag but --distill given twice, and an unknown kind.
  • cr with --reason anywhere is left to today's refusal, which names --waive-review (the B18 test keeps its eight cases).
  • No edit inside the doc arm (E-DOCSPLIT's lines).

Details

What you will know when it lands

  • keel verify-dod wu|epic <tip> --no-receipt prints the same check lines and exit code as without it, plus one line on green, and refs/notes/* is unchanged.
  • Any keel command with --help or -h anywhere prints its usage on stdout, exits 0, and changes no ref (notes and HEAD included), index entry, working file, local config or installed hook, in a repository or outside one.
  • keel mr confirm wu <tip> --help on a tip ready to sign writes no mr/v1 note.
  • An unknown argument to verify-dod, preflight or notes write exits 1, names the argument and writes nothing.
  • Every existing test passes unchanged; cargo clippy and keel check are green.
