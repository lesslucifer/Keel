The problem

W1 takes GitHub's flow out of the code. The docs still describe it as the way you work: install tells you to set up the bot, architecture explains the checks, nine decisions, four use cases and a whole backlog page describe it. Once W1 lands, a reader who trusts them is told to approve on GitHub, which no longer signs anything.

After W2, no record describes GitHub's flow: every page reads as it did on 15 November, before the flow, plus only what is still true without it (the five keeps and the local-app records), and no new decision is added.
