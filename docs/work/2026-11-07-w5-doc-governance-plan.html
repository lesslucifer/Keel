E-SEED.W5 — Doc governance

keel verify-doc and the harness hooks that run it, so a governed doc can't drift red without anyone noticing.

Draft v1 · 2026-11-07 · Keel · T2 WU plan · epic: E-SEED · status: draft, awaiting owner sign-off

Requirement

Every governed doc in this workflow (epic plan, WU plan, WU result, epic result — this very doc is a WU plan) has a checklist of required sections. Today nothing enforces that checklist automatically; a doc can be marked "ready" while missing a section, or carry a dangling relative link, and nobody notices until a human happens to look. This WU builds the checker and wires it into the harness so a doc going red blocks the agent's turn instead of quietly shipping.

Builds on E-SEED.W1, already merged to main: the keel binary, config loading, and — specifically — the hooks_install() function and the hook-writing pattern it established (.keel/hooks/<name>, mode 755, core.hooksPath). This WU extends that function, it doesn't replace it.

Note on provenance: a worker already built and tested this WU once, in parallel with W2; it was reverted off main (commits still reachable at 296a9eb) because it merged before this plan doc existed for you to review. This plan describes that same design, including the author's own flagged gaps, so you can approve, amend, or reject it before re-merging.

Scope

  • keel verify-doc [paths...]: with no paths, checks every *.html under docs.root (tracked or untracked, not git-ignored). Exits 1 if any doc is red, printing file: problem lines to stderr.
  • Four checklists, keyed by a doc's data-artifact attribute, shapes taken directly from this repo's own seed-plan doc and Trawler's work-planning.html convention:
    • epic-plan: intent, use-cases, expected, non-goals, wu-summaries, e2e-plan, distillation-plan, open-questions — plus at least one data-wu block, each with non-empty wu-summary, wu-maps-to, wu-expected, wu-deps.
    • wu-plan (this doc's own type): requirement, maps-to, expected, test-plan.
    • wu-result: outcome, deviations, evidence, distillation, follow-ups.
    • epic-result: outcome, wu-rollup, deviations, evidence, distillation, follow-ups.
    A present-but-empty item is red, same as a missing one. An unrecognized data-artifact value is red.
  • Drafts stay silent on the checklist (data-status="draft" or no status) — per UC-DOC-1. Drafts are fully silent: relative-link checking is skipped too (owner decision, differs from Trawler). When W5 is re-implemented this is a one-line change from the original build: verify_doc() must skip link-checking when the doc's status is draft, not only the checklist.
  • Collapsed roles: a doc whose data-artifact lists two types space-separated (e.g. "epic-plan wu-plan", Trawler's convention for small work) must satisfy the union of both checklists; an item shared by both counts once.
  • Typo guard: any data-item value not in the expected-keys list for that doc's artifact type is reported by name, e.g. unknown tag data-item="expcted". data-c values are not guarded (free-form ids, not checklist keys).
  • Relative links (UC-DOC-2): every relative <a href> must resolve to a file that exists on disk, relative to the doc's own directory (#/? stripped before resolving). Absolute URLs (anything with a :) and root-relative paths (leading /) are skipped.
  • Hooks: two new scripts added to the list hooks_install() writes — verify-doc-post (PostToolUse) and verify-doc-stop (Stop). Both need jq and exit 2 with the problem list on stderr when a doc is red, 0 otherwise.
    • verify-doc-post reads the edited file path from Claude Code's hook JSON (tool_input.file_path) or, for Codex, parses *** Add/Update/Delete File: / *** Move to: headers out of tool_input.command (an apply_patch payload) — ported from Trawler's script, not verified against current Codex hook docs (see open points).
    • verify-doc-stop just runs keel verify-doc with no paths (checks everything under docs.root) and blocks the Stop if anything is red.
    • Both fail open if keel isn't on PATH (unlike W1's pre-commit hook, which fails closed) — see open points.

Maps to

UC-DOC-1 ("a governed doc, once ready, is verified against its checklist on every write; a turn cannot end while one is red, and drafts stay silent") and UC-DOC-2 ("any doc with a relative link that does not resolve is red").

Expected result

Per the epic plan: this plan doc (and the epic plan doc, already ready), verify green once flipped to ready. A misspelled tag is reported by name. A Stop on a red doc is refused.

Test plan

  • Seed plan verifies green: point keel verify-doc at docs/work/2026-11-07-seed-plan.html directly (read-only) and assert success.
  • Typo named: a fixture doc with a deliberately misspelled data-item — assert the error names it.
  • Dangling link is red, existing is not: a fixture with one broken and one valid relative link.
  • Collapsed roles need the union: a fixture with data-artifact="epic-plan wu-plan" missing one item from each checklist — assert both are reported.
  • Stop refuses a red doc, Post reads both payload shapes: run the hook scripts against fixture Claude-style and Codex-style JSON payloads naming a red doc, assert exit 2 and the problem text on stderr.
