The problem

The bot's first push failed with router-gh: GitHub returned no usable installation token, from the router and from your own terminal. Since 2026-04-27 GitHub mints installation tokens in a new format, ghs_<app id>_<JWT>: about 520 characters, with dots and dashes. scripts/router-gh.sh took only ghs_ and 36 letters, digits and underscores (at most 255), at the mint and again in git's credential helper. So every token GitHub now sends is refused. The fake GitHub in the tests sent the old shape, so no test caught it.

The bot takes any installation token GitHub mints, legacy or stateless, as an opaque string, and W1's result report records each fact of the epic plan's W1 line as GitHub or the script printed it, pass or fail.

Expected

  • router-gh.sh push epic/E-GHFLOW2 prints PUSHED, with the bot as pusher.
  • A token that is empty, longer than 4096 bytes, or holds a space, quote, backslash, control or non-ASCII byte is still refused, and the error names only the HTTP status and the token's length.
  • The result report lists every line of the epic plan's W1 block (the bot, the four facts only GitHub proves, the Keel gate run, the watch, the observed facts) with what GitHub or the script printed.

The work

  1. The token fix (rule-bearing: your keel mr commit). One check, token_ok: 1 to 4096 bytes of printable ASCII, no space, quote or backslash. Both the mint and the credential mode use it. That set stays inert everywhere the token goes: the curl config's quoted Authorization line, git's password= line and the 0600 token file. A refused mint says (HTTP <status>, a token of <n> bytes), never a byte of the token. The same commit carries the owner's diagnostic, ROUTER_GH_DIAG=mint (open point 2).
  2. The live checks, run by the router (the bot's commands) and by you (anything that needs the key), in the epic plan's order. Each fact goes into the result report. A fact that fails is fixed in this WU, with a test against the fake GitHub that fails before the fix.

Test plan

Integration (tests/suite/router_gh.rs, the fake GitHub). The fake's token is now the stateless shape: 516 characters, two dots, dashes and underscores. Every existing test runs with it, including the credential helper over https and every no-leak assertion. A new test pushes with a legacy 40-character token, the stateless one and a 4096-byte one, and checks that the next API call carries each one unchanged. The diagnostic's test: one token request, the safe facts, exit 0, nothing pushed, and no token, JWT or key in the output. The refusal test sends ten bad answers: a quote, a space, an apostrophe, a backslash, a newline, a non-ASCII byte, 4097 bytes, an empty token, a number and no token. Each must exit 1 with the status and the length only, and push nothing. Before the fix, the stateless fake fails every push test.

Live: the result report records each W1 line from the epic plan. Unit: none; the change is a shell check covered at the script's boundary.
