The problem

The epic's review failed again. One bug blocks the merge:

  • Open skips any data file over 64 KB before it asks keel. Keel accepts data files up to 1 MB. So a result keel checks and you sign can show as "no page" in the app.

Two smaller findings:

  • Which branches count as open is written three times in the list reader, and the copies already disagree. A note or a "since" time can be read for a branch the list does not show, and crowd out one it does.
  • Which branch is a task of a work unit is written three times too, apart from the app's one naming rule. A branch name with two underscores counts as a task in one place and not in another.

What you get

  • Open finds every page keel accepts, whatever the size of its data file.
  • Open's temp files stay small, even with many large data files.
  • One rule for open branches, and one for tasks, in the list reader.

How it works

  1. Each bug first gets a test that fails, then the fix.
  2. Open hands keel every data file. Keel decides if one is too large.
  3. Open writes the files for keel in small batches, each removed before the next.
  4. The notes and times reads ask only about the branches the list shows.
  5. Every task check uses the app's naming rule.

What it makes

Changes in Open and the list reader, their tests, and this plan and its result. Keel itself and the window do not change.
