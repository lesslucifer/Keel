E-SEED2.W12 · The router watches owner actions itself

A committed, read-only probe script that the router runs in the background. It wakes the router with one event line, plus what actually landed, when the owner commits, signs, merges, pushes or tags. The owner never has to reply "done".

T3 · WU plan · 2026-11-10 · Keel · branch wu/E-SEED2/w12-owner-watch off epic/E-SEED2 ef9ee75 · epic plan E-SEED2 W12 · scope flagged owner steps

Scope flag. This WU is router meta-tooling. Like W8, it belongs to E-ROUTER v2 (backlog R7, row 1), and the owner asked for it under E-SEED2 (request of 2026-11-10). Router↔worker messaging is out of scope: it stays deferred to its own epic (backlog R8). W12 covers only one thing: the router detecting owner actions without being told.

Requirement

The router runs scripts/router-watch.sh <kind> <args…> as a background Bash command, which scripts/router-guard.jq allows. For each kind of owner action (commit, signed, merged, pushed, tagged), the script polls git read-only until the action's observable state holds, prints one event line followed by indented lines saying what landed, and exits 0. If the state never holds, it prints TIMEOUT or UNREACHABLE and exits 0. Any argument it cannot validate is refused with exit 2 before the first poll.

Mechanism

sequenceDiagram

  participant R as Router

  R->>O: ask (one task) + "Watching: commit wu/E/x from 1a2b… (3 paths)"
  R->>G: Bash, run_in_background, timeout 7200000
  G-->>R: allowed (watch shape)
  R->>S: scripts/router-watch.sh commit wu/E/x 1a2b… skills/a.md .claude/skills/a.md docs/b.html
  loop every ROUTER_WATCH_POLL s, until state holds or deadline
    S->>S: git rev-parse / log --notes=mr / merge-base / fetch / ls-remote
  end
  O->>O: keel mr commit …
  S-->>R: COMMITTED-PARTIAL … + "  missing docs/b.html"
  R->>O: verdict + next task (terminal + push)
The shell does the polling. The router wakes once, on the event line, with what landed already in hand.

Recommendation: a new committed script, scripts/router-watch.sh, separate from the launcher. It only reads git and never starts claude. One guard alternative and one allow entry admit it. The router arms it in the same turn it stages an owner action and names it in the ask (Watching: …). Nothing is spawned, so a watch costs no worker session, no budget and no launcher name slot. Several watches can run in parallel because the script keeps no state.

Command shapes, probes and event lines

Every invocation is scripts/router-watch.sh <kind> <args…>, run from the router checkout. The first output line is the event: WORD key=value …, the same style as wait's EXITED name=…. Each detail line that follows starts with two spaces. Shas are printed in full.

Owner actionShapeFires whenEvent and what-landed lines
keel mr commit (or any commit the router staged)commit <branch> <old-tip> [<path>…]git rev-parse refs/heads/<branch> ≠ old tip.COMMITTED branch= from= to= commits=<n> expected=<k>/<n>. Then commit <sha> reviewed-by=<trailer value|none> <subject> for each commit in old..new, landed <A|M|D|R> <path> from git diff --name-status old new, and, when paths were given, missing <path> and unexpected <path>. Any missing path changes the event word to COMMITTED-PARTIAL. If the old tip is not an ancestor of the new one, the event is REWRITTEN (an amend or rebase, which AGENTS.md forbids).
keel mr confirm wu|epicsigned <tip>git log -1 --notes=mr --format=%N <tip> is non-empty.SIGNED tip=, followed by the mr note payload verbatim, two-space indented. The router checks the identity, level, target and report it staged against the payload.
git merge --no-ffmerged <tip> <target-branch>git merge-base --is-ancestor <tip> refs/heads/<target>. No MERGE_HEAD check is needed: the target ref only moves once the merge commit exists (after the gate hook), and the MERGE_HEAD of a conflicted merge lives in a worktree the router does not name.MERGED tip= target= at=<target sha> how=no-ff|ff|contained. no-ff means the target tip's second parent is the tip. ff means the target equals the tip, a red flag because the gate requires --no-ff. contained means the tip landed through some other merge.
git pushpushed <tip> <branch>git fetch -q origin -- refs/heads/<b>:refs/remotes/origin/<b> succeeds and git merge-base --is-ancestor <tip> refs/remotes/origin/<b> holds. This is commands.md's PUSHED predicate: ancestry, not equality.PUSHED tip= branch= origin=<sha>
git push origin <tag>tagged <tag> [<sha>]git ls-remote --tags origin refs/tags/<tag> lists the tag. It is read-only and writes no local ref.TAGGED tag= object= commit=<peeled ^{} sha>. If a sha was given and the commit differs, the event is TAGGED-MISMATCH (never move a pushed tag: the router stages a new version instead).

Validation, done before the first poll (exit 2, router-watch: <why> on stderr)

  • The kind must be one of the five. The arg count must be exact for signed, merged, pushed and tagged; commit takes 2 or more args.
  • No argument may start with -. Without this, pushed main --upload-pack=… would hand git an option that executes a command. The guard refuses it too (below); the script refuses it again as defence in depth, and passes -- wherever git accepts it.
  • A branch must pass git check-ref-format --branch and exist as refs/heads/<b>. For pushed, it must exist on origin or locally. A tag must pass git check-ref-format refs/tags/<t>.
  • A sha must match ^[0-9a-f]{7,40}$ and resolve with git rev-parse --verify --quiet <sha>^{commit}. It is printed in full afterwards.
  • A path must not contain .. and must not start with /. Paths are only ever compared as strings, never opened.
  • The remote is always the fixed word origin, never an argument.

Timeouts and re-arm

KnobValueWhy
Poll intervalROUTER_WATCH_POLL: 15 s for local kinds, 60 s for pushed and tagged. When set, the env value overrides both, which the tests use.Local probes are cheap. Network probes should not hammer origin.
Script deadlineROUTER_WATCH_MAX, default 6600 s (110 min), then TIMEOUT.It stays below the 2 h background-command ceiling, so the router always wakes on a line rather than on a silent kill.
Background command timeoutThe router arms with run_in_background: true, timeout: 7200000.The default background timeout is 30 min, which would kill the watch before its own deadline. The skill text names this value.
Already true when armedThe first poll fires at once.The owner may already have acted. Arming the watch doubles as the "check the real state before every ask" step.
Router envThe router cannot set ROUTER_WATCH_*: an X=1 cmd prefix fails the guard's leading-word match.The knobs are test-only. Production uses the defaults.

Re-arm rules for the router. On TIMEOUT: re-read the state (the action may have failed with no state change), re-send the task in full (the skill's "self-contained, every time" rule), and arm the same command again. On a wake with no line (the command was killed, for example at the 30-min default): re-arm. On UNREACHABLE: tell the owner the remote cannot be reached and do not re-arm until they answer. The heartbeat's "re-arm missing watchers" step also covers a watch lost to a router restart.

Expected result

  • In a temp repo with a bare origin, each kind stays silent while its state does not hold, then prints exactly the event and detail lines above and exits 0, within one stepped poll of the change.
  • commit … a b with only a committed prints COMMITTED-PARTIAL … expected=1/2 and missing b. A commit carrying Reviewed-By: username vuluu shows reviewed-by=username vuluu. An amended branch prints REWRITTEN.
  • merged reports how=no-ff for a --no-ff merge and how=ff for a fast-forward. pushed fires only after the push, not after the local merge. tagged with a wrong sha prints TAGGED-MISMATCH.
  • With ROUTER_WATCH_MAX=1 the script prints TIMEOUT. When origin cannot be reached, pushed prints UNREACHABLE after 5 failures.
  • Bad kind, an arg starting with -, a bad ref, an unknown sha or a path containing .. each exit 2 before any poll.
  • The guard allows the five shapes with realistic args and denies pushed main --upload-pack=x, commit -b x y, commit b ../x, X=1 scripts/router-watch.sh … and an unknown kind. The settings test accepts a Bash(scripts/router-watch.sh *) entry.
  • keel-router "Watch, never wait to be told" and worker-ops.md "Watch" describe arming router-watch.sh directly, the timeouts, re-arm and the unobservable table. No text tells a watch worker to run an until loop for an owner action.
