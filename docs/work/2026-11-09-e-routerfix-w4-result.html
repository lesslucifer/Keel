How the two mechanisms split the work (DEC-36, amended). The subscription is free and covers a clean exit, as a notice at the router's next turn end. wait covers both exit and stall, and its end wakes the router as a background command. The heartbeat's per-worker ps check becomes the fallback for a worker with no wait armed.

Live probe: does a background wait wake the session?

W8 left this one item unconfirmed, because a worker cannot test it. Confirmed on 2026-11-09 from an interactive session, with that session idle.

StepWhat happened (literal)
Stub worker/bin/sh -c 'sleep 75; :' stub -n probe-wait --model x started at 07:44:46Z, pid 48986, written to .router/out/probe-wait.pid. A run dir .router/runs/probe-wait-20261109-spawn/ held name, worktree and session. live() recognises the stub through its -n probe-wait argv, so no real claude was spent.
Armscripts/router-worker.sh wait probe-wait 30 run as a background Bash command (run_in_background: true). The session then ended its turn and sat idle, with no further tool calls.
EventThe command printed EXITED name=probe-wait pid=48986 out=…/.router/out/probe-wait.out and exited 0 at 07:46:00Z, which is within one poll of the stub's exit.
WakeA background-task notification ("Background command … completed (exit code 0)") started a new turn in the idle session. The turn's first command logged 07:46:04Z, and ps -p 48986 showed the stub gone.
Verdict. An idle session wakes on its own when a background wait ends. The router can therefore rely on wait to hear of both an exit and a stall without anyone asking it. This used the same harness mechanism the router's Bash tool uses. Not exercised: a STALLED end live (its logic is the hermetic test's), and a router busy mid-turn, where the notification waits for the turn to end, as W2 saw for the subscription.
