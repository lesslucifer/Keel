E-DOCSPLIT · A short doc for you, a data file for agents

Split each plan and result in two, and slim today's docs.

Example of the new epic plan page · a rewrite of the approved epic plan · its data file is shown on the inventory page

The problem

Each plan and result is one HTML file with three readers: you, an agent, and Keel's checks. It serves none of them well. You get long pages full of tags. Agents spend tokens writing HTML. The checks dig facts out of it. The other docs keep history you no longer need.

What changes for you

WhenTodayAfter

A check finds a gapIt names a missing tag in the pageIt names a missing field in the data file
You open the decisions, use cases, backlog or architectureLong, with history and replaced rowsShort: current truth only
You approveThe epic plan, then each part's planThe same, and first a table of where each doc lives

Example: a part's plan after this epic

  1. An agent writes the plan's data file: the requirement, the tests, its epic.
  2. The check reads it and names a missing test plan. The agent adds it.
  3. The agent writes a one-screen page for you, in plain words.
  4. You comment on the page. The agent fixes both.

Terms

Data fileA file of named facts for agents and checks. You never need to read it.
Word capThe most words a kind of page may hold.
DistillMove a finished doc's lasting truth into a permanent doc, then archive it.

What you decide

#QuestionAnswer, and why
1Where does a data file live?In a file beside its page. A plan exists before there is a commit to attach a note to, and your sign-off binds the file.
2Do replaced decisions go?The id and one line stay; the rest goes. Old ids are cited and must still resolve. Git keeps the text.
3May W4 change the rule file?Yes: approving this plan asks for it. One line changes.
4Should a check prove each follow-up names a real backlog row?Not here: a backlog row. It is not part of the split.

Settled with you: a clean cut for old tags; the decision and use-case indexes become data; W1 redesigns the plan pages; every page kind gets a cap.

How you'll know it worked

  • A plan missing a fact is red when written, and the message names the fact.
  • Pages carry no tags.
  • Every slimmed doc is under its cap, and every decision, use case and backlog id still resolves.
  • One test runs the whole flow: plan, check, result, sign-off, archive.

Not in this epic

  • Writing one doc from the other: each is written for its reader.
  • The gate's notes keep their formats.
  • htmldoc, and the skill files' format.
  • E-GHSETUP's GitHub setup.

For agents: the data file holds each part's files and tests, the use cases, the end-to-end test and the distillation plan.
