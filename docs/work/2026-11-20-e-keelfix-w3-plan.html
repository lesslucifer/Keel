The problem

The revert of GitHub's flow left one piece behind on purpose. Keel still reads a GitHub line in the signer list, and a GitHub entry among the accepted signer kinds. Both sign nothing. They were kept until the docs epic reached main. It has, so they can go.

How it works

Keel knows three signer kinds: email, user name and key. Every place that reads the signer list refuses any other kind, with the line number. That covers signing off, rule-file commits and the gate.

  1. A signer list has your user name on line 1 and a GitHub line on line 2.
  2. You run the sign-off as yourself.
  3. Keel refuses: "line 2: expected …". Nothing is written.
  4. The line goes; the sign-off works as before.

Old sign-offs made by GitHub approval stay as written. Fifteen exist, fourteen on main. Nothing checks them again: the gate judges a sign-off only where it merges.
