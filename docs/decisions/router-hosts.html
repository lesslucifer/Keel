Decisions: router hosts and GitHub

The router on DeepSeek Harness, the inbox that wakes it, and the router bot on GitHub.

T2 · decisions · current truth · 2026-11-18 · Keel · DEC-55, DEC-56, DEC-58, DEC-61 – DEC-63

Current truth: each record says what stands today, why, and what was rejected. A later decision that changes one is folded in and named. A record replaced whole keeps its id and one line. Ids are never reused; git keeps the history. The router itself and its Claude Code workers are in router.html.

DeepSeek Harness (DSH)

DEC-55 · A DSH worker is a workspace-rooted session whose report is its transcript

ChoiceA DSH worker is the session worker_spawn starts in the worktree it names: the workspace is the worktree, the prompt is the brief, the name is its handle. Follow-up is one worker_send, queued and taken at the worker's next step. worker_list is the fleet view, worker_status the state (running, idle, ready, stopped), worker_stop the end: idempotent, and a stopped worker is never revived. A worker posts a short report to the inbox and the router's armed watch is the wake (DEC-58); its transcript, read with worker_output at every wake and before every ask, is the evidence, and its claims are verified against git. The persona is the worktree's AGENTS.md and the skills; there is no per-worker preset, so the brief carries the goal, the hard rules and the report protocol in full. These shapes sit in one dated table in keel-router/SKILL.md (a row per mechanism, a column per host). The Claude Code recipe (DEC-44) is unchanged.
WhyOn DSH a session's workspace root is the directory it was created in and never changes, and a subagent inherits its parent's directory: it would work in the router's checkout, and a cd does not carry between Bash calls. So a subagent cannot be a worker.
RejectedA DSH subagent as a worker. A per-host skill fork, or DSH prose in any other skill (a content test asserts no other shipped skill names a DSH tool). A project-scoped agent definition or per-worker preset (DSH presets and settings are user-level).

DEC-56 · A Keel DSH session runs under Always Auto Review

ChoiceEvery Keel DSH session, router and worker, runs under Always Auto Review (0.5.0): the owner's standing decision, and the DSH cell of the transport table's permission row. A worker in a linked git worktree runs danger-full-access, because the git directory lives outside the workspace; one in a plain directory runs workspace-write. A denial is final: surface the exact command to the owner, never retry it, never hand it to another session. The preset is never the owner's approval: keel mr, a merge, a push and a tag stay manual. The router's tool whitelist is unenforced on DSH until a guard plugin exists (backlog D2); the skill is the only guard, and the router says enforcement is missing and never uses the gap to do the work itself. The router template has a "Harness and permissions" block stating the preset.
WhyWith approvals off, a DSH session rejects every call nothing decides, so an unattended agent could not add, commit or mint. Auto Review decides each call itself (a medium call runs, a high-risk call is denied) and offers no prompt. The preset is a session fact; settings are user-level and a project cannot pin its own.
RejectedAsking the owner to approve each call (an unattended session stalls, and the owner is the scarcest resource). A per-worker or per-project preset. Approvals off with no decider.

The inbox

DEC-58 · A worker's report is a post to a file inbox; the router's armed watch is the wake

Choicescripts/router-inbox.sh (POSIX sh) keeps one message per file under <main checkout>/.router/inbox, resolved from the git common dir so a copy in any worktree posts to the main checkout. init makes it and its read/. post <from> <kind> <text|stdin> writes a dotfile, renames it into place and prints POSTED id=<epoch>-<random>. watch <seconds> checks at once, then polls, prints one MSG id=… from=… kind=… age=…s bytes=… line plus the indented body (at most 4,000 bytes and 80 lines, control characters as ?) and exits 0, or prints TIMEOUT kind=inbox and exits 1 at its bound. consume <id> moves the file to read/ (CONSUMED, then CONSUMED-ALREADY); status counts pending, read, orphan and junk files. No verb deletes (the host's auto review denies a script that does). A worker posts a short report (at most 4,000 bytes; the full report stays its final transcript message) and quotes the id; the router arms watch 6600 as a background command (timeout: 7200000), reads and records the message, then consumes it. On Claude Code the router guard admits init|status|watch <seconds>|consume <id> and never post (free text). A message is a regular, never-followed file with a valid id name, a matching id: line, a sender name and one of five kinds; anything else is junk, skipped and counted, never printed. Limits: no authentication (any local process can claim any from); delivery is at-least-once, so a duplicate is possible and a loss is not; .router/ is git-ignored and unbacked. A DSH worker in a plain-directory workspace cannot post, and a Claude Code worker cannot until its sandbox allowWrite adds the inbox, which would weaken DEC-46. A worker that posts nothing wakes nobody (no wedge detection); while a watcher is armed its bound (110 minutes at most) is the longest silence, about 13 wakes a day.
WhyNothing woke the router when a WU finished, and the fleet-wake reminder cost a full model pass every tick, 144 a day at 10 minutes, whether or not anyone had news. A file channel was proven on DSH (the owner approved a probe on 2026-11-14): one wake per post.
RejectedA reminder or timer for reports. A DSH watchdog posting into the inbox (a second model session that only reports the silence the router already sees). A router-side poll loop (the owner's 2026-11-11 ruling). A network or message channel (a dependency and a credential, and DSH has no sender). A .router-ready.<name> marker (the timer again). Sender authentication (the channel trusts the machine).

GitHub

DEC-61 · The router bot pushes work branches and opens pull requests, as a GitHub App

ChoiceScript. scripts/router-gh.sh (rule-bearing), run by the router only, with the shapes push <wu/E/slug | epic/E>, pr-open <branch>, pr-ready <n>, post <n> <body-name>, sync <epic/E> and issue <branch> (DEC-62). It checks every argument first, no word may start with -, and it never pushes main or a tag. Identity. A GitHub App the owner installs on this repository only; each call signs a JWT with the App's key and mints a short-lived installation token (1 to 4096 bytes of printable ASCII). No output, argv, environment or worker-reachable file carries the key, JWT or token; git gets the token from a credential helper that answers only protocol=https host=github.com. The key is ~/.config/keel/router-gh/app.pem (mode 0600 or 0400, one link, in a directory only the user may write), with app.conf beside it (app_id, installation_id, app_slug). Shapes. push: a wu/ tip must carry its own test/v1 note, and an epic/ branch GitHub already holds must pass keel verify-dod range; it pushes the branch and Keel's five notes kinds, with no hook (DEC-63). pr-open: a draft pull request into the epic (a WU, with no --base) or main (an epic), its body built from git; it refuses anyone else's pull request. pr-ready: only the bot's draft at the local tip; it requests the owner's review and, under [github] merge_on_approve, turns on auto-merge (a WU into main is refused; DEC-65, DEC-67). post: a file the worker wrote at <worktree>/.router-gh/<name>.md, read once, mentions made inert, deleted after posting. sync: fetches GitHub's epic (or main) into refs/remotes/origin/…, then fast-forwards the local branch only when no worktree has it checked out; otherwise it prints state=fetched and that worktree's session runs git merge --ff-only. Before its notes push the router takes GitHub's sign-offs add-only (DEC-64). Only the owner merges. The script's checks on git data are policy, not a bound: a worker can write the shared git dir, so CI's gate and the owner's sign-off stay the authority. Workers never push and never touch GitHub: they are denied both GitHub scripts, and the key directory is in their sandbox's read deny and the file guard. ROUTER_GH_DIAG=mint is an owner-only diagnostic. Accepted residual: a worker that forges a worktree entry whole is believed (sync leaves the epic unmoved, post may post that directory's file, inert). Setup is in install.html; the live checks are backlog G2.
WhyA pull request needs a pushed branch, and "the owner pushes" kept the owner at the terminal. GitHub forbids approving your own pull request, so for the owner's approval to be the sign-off the author must not be the owner.
RejectedThe owner keeps pushing. Workers push (a GitHub credential in every sandbox). A second "machine" user (a long-lived token; GitHub's terms unverified). The owner's own token (the owner could not approve). The pre-push hook on the router's push (it runs the pushed branch's code with the router's rights).

DEC-62 · The router hears the owner on GitHub by polling, and only committed commanders by numeric id

ChoiceA poll, not a server. The router arms scripts/router-gh-watch.sh review|comment <n> [since <id>|since latest], merged|checks <n> or conflict <n> (DEC-67) as a background command. It checks at once, then about every 60 s, and exits on the first event from a commander: one line with at= and the text indented, control and invisible characters as ?. Otherwise it ends with TIMEOUT, UNREACHABLE after 5 failed polls, or OVERFLOW … resume=<id>. It keeps no state and holds no secret: each poll asks router-gh.sh watch-read, which reads only an issue or pull request the bot opened. It reads the 10 newest pages (1,000 items); older items are reported with gap=yes or OVERFLOW, never dropped. Who is heard. [github] commanders in .keel/config.toml: numeric user ids of type User (an id cannot be renamed), read from the router checkout's file only while it matches HEAD's; Keel's list is the owner alone, 5499546. [github] free_text decides whether a commander's other text reaches the router or only the commands. Anyone else, an App posting for a commander, and the bot itself are a count, IGNORED from=other count=N: never text, never a wake. Grammar. A comment's first line may be one closed command, /keel go|hold|retry|answer <n> <A|B> (scripts/router-gh-command.jq); the rest is the commander's message, trusted like a chat prompt. A review's text is a message, never a command. An edited comment prints EDITED and no text, and is never an order. The meanings of the four commands were never recorded and the owner questioned them on 2026-11-17 (open, backlog G10). Status board. One tracking issue per epic with a sub-issue per WU, written by the bot from git only (router-gh.sh issue, label keel-tracking). Telegram stays the fallback. Orders arrive up to a minute late and are public text.
WhyThe owner gave every order in the router's chat at the Mac; E-GHFLOW moves orders to GitHub comments and reviews, readable on a phone. A public repository lets anyone comment, so who is heard is the router's front door.
RejectedA self-hosted runner as a doorbell (GitHub warns against them on public repositories). Webhooks to the Mac (a public endpoint). Logins instead of ids. A hard-coded owner. A router-side loop (the owner's 2026-11-11 ruling). Re-reading an edited comment as an order (REST names no editor).

DEC-63 · Scripts the router runs never run worker-controlled code

ChoiceA script the router runs that holds a credential or runs outside the worker sandbox (Keel: scripts/router-gh.sh, scripts/router-gh-watch.sh, the launcher scripts/router-worker.sh) keeps six rules.
  1. No hooks. push runs with --no-verify and does Keel's code-free checks itself. Every git it runs gets no hooks and no fsmonitor (through GIT_CONFIG_COUNT) and GIT_ALLOW_PROTOCOL=https, which overrides any protocol.*.allow.
  2. Pinned git dirs. It pins its own checkout's GIT_DIR and GIT_COMMON_DIR, never runs git inside a worker's worktree, and refuses a commondir file in the main git dir, a config.worktree in the git dir or its own admin dir, and a linked checkout's admin dir not as git makes it. A worktree entry is believed only when it looks as git makes one, and only the first row may be the main checkout.
  3. Config isolation. git reads no global or system config; pushes pass --no-follow-tags; curl -q; set -f; HOME is refused outside [A-Za-z0-9/._-].
  4. Secrets stay in the key dir. The token's run dir is ~/.config/keel/router-gh/run/, which workers cannot read, never the shared $TMPDIR; the exit trap is set before it is made.
  5. Worker files are data. A file a worker wrote is opened once by its real path without following a link, accepted only as a regular file with one link, and handled as a copy.
  6. The launcher guards the shared git dir. The worker sandbox denies writing <git dir>/commondir and config.worktree, and every admin dir's commondir, gitdir and config.worktree, by name and by glob. Every launcher run checks every admin dir under <git dir>/worktrees (a real directory, commondir exactly ../.., no config.worktree, a gitdir naming a .git) and stops every mode on a mismatch before any session starts; the watchdog's facts report it instead.
Remaining: a worktree entry forged whole is believed (DEC-61); keel mr runs git in the owner's checkout without checking that checkout's admin dir (backlog R50); the worker sandbox is a deny list over a writable git dir, not an allow list (R51); the key's hard-link check is a live check (G2). Scripts are outside code_paths, so the code gate never reads them: every new router-run script gets an independent security review against this list.
WhyThe router can read the App key and write its own guard; a worker can write its worktree and the shared git dir. E-GHFLOW's security reviews found the same class five times: the pre-push hook ran the pushed branch's code with the router's rights, sync ran git in a forgeable worktree, the token's run dir sat in shared $TMPDIR, commondir was shell-writable (backlog R33, now fixed), and an earlier worker could write a later worktree's admin dir.
RejectedRunning the pre-push hook on the router's push. -c protocol.allow=never (a repository's own config can widen it; the environment variable wins). Trusting git worktree list as it stands. Denying admin dirs by glob alone (a worker can rename a whole admin dir; the per-run check is the bound).
