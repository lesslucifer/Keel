One expr in the commanders check behaves differently on Linux, so GitHub's runs fail 20 router tests that pass on a Mac.

Ready v1 · 2026-11-16 · T3 · WU plan · Keel · off epic/E-GHFLOW2 6ea4d37

The problem

On GitHub's Ubuntu runner, cargo test fails 20 tests (every router_gh_watch test that reads the config, router_gh::pr_ready_marks_only_the_bots_draft_at_the_local_tip, and the ghflow_e2e epic run) with router-gh: [github] commanders must be a list of GitHub user ids. On macOS they pass. The cause is line 315 of scripts/router-gh.sh, added in 2e973d9 (E-GHFLOW.W3): expr "x…" : 'x\[ … \( *, *[1-9][0-9]\{0,11\}\)* *\]$'. When the pattern has a \( group, expr prints the group's text, not the match length. With one commander the group matches nothing, so it prints an empty line. GNU expr then exits 1, "no match"; BSD expr exits 0.

The commanders check accepts and refuses the same lists under GNU expr as under BSD expr, and a test on macOS fails when it does not.

Maps to

E-GHFLOW2, W9 · DEC-62 (only committed commanders, by numeric id; E-GHFLOW.W3) · UC-GATE-7 (CI on GitHub runs green).

Expected

  • commanders = [5499546] is accepted under GNU expr; two ids still are; [], [0], [1,], a login or a 13-digit number is still refused, on both.
  • The router tests run green with a GNU-semantics expr first on the PATH and dash as sh, and red at 6ea4d37 the same way.

The work

  1. The fix (rule-bearing: your keel mr commit): wrap the whole bracket in one outer group, 'x\(\[ … \]\)$'. A match now prints the list itself, never empty, so both exprs exit 0; no match prints nothing, so both exit 1. Nothing else in the script changes. The other expr calls in scripts/ have no group.
  2. A regression test in tests/suite/router_gh_watch.rs, committed before the fix.

Test plan

Integration: the_commanders_check_holds_under_gnu_expr puts an expr shim with GNU's rule first on the test's PATH (sed reads the group; an empty result exits 1). It checks the shim itself, then that one commander and two are heard and a login is refused. It fails on macOS before the fix. Proof by hand: the router_gh, router_gh_watch and ghflow_e2e tests under a scratch GNU-semantics expr (Python, the full GNU rule) and sh as dash: red before, green after; and natively. Unit: none; the change is one shell check covered at the script's boundary.
