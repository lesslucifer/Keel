E-ROUTER3.W10 · Workers are native background sessions — result

A worker is now a claude --bg session that reports to the router by SendMessage and takes its follow-up tasks as messages. The launcher has three modes (spawn, resume, stop); wait, send and W2's feed and stream machinery are gone.

T3 · WU result · 2026-11-11 · Keel · branch wu/E-ROUTER3/w10-bg-workers off ee34a85 · WU plan · epic plan

Outcome

Delivered, with four probe-driven deviations below. scripts/router-worker.sh spawn runs one claude --bg -n <name> --model --effort --agent worker --allowedTools … --disallowedTools … --permission-mode <mode> "<fixed prompt>" in the worktree, with no print-mode, stream or budget flag, and refuses a name claude agents --json lists. The worker reports to the router by SendMessage; a follow-up task is the router's own message. stop runs claude stop then claude rm on this repository's idle worker by id. wait, send, the inbox, feed, reaper, stream scan and every .router/out/ file are deleted; the guard and the settings admit spawn|resume|stop only. The live run showed the whole flow with a real Opus worker and a guarded router.
