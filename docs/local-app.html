Keel — the local app

A desktop app on your Mac that tells you what waits on you, shows the work, and runs your sign-off and merge on a click you confirm. The first part is built (A3, E-APPLIST): an alert at your desk and one list of what waits on you, read-only. The rest is designed, not built: this page is the next epics' source.

T1 · 2026-11-23 · Keel · distilled from E-LOCALTOOL (the design) and E-APPLIST (A3 as built), each archived at its close · why: DEC-70 · how it is built: DEC-71 – DEC-78 · use cases: use-cases/app.yaml · the epics: backlog/local-app.yaml

Why

What waits on you arrives by Telegram, the router's terminal and GitHub mail. You learn the state of the work by asking the router. GitHub ran the checks, your approval and the merge, and it was heavy, slow and one company's. Its flow is dropped (below). The app takes over the watching and the alerting, and puts your few commands one click away. Keel stays the judge.

Three rules

  1. The app judges nothing. The gate, the notes and the sign-off stay in keel and its git hooks. The app never runs keel verify-dod, keel preflight, keel notes write, a fetch or a push.
  2. It runs only your commands, by a button with a confirm. Three commands, listed under The hand-off. Each shows its full line, asks once, and runs exactly what you would type.
  3. The terminal works without it. Every line the app runs is shown, and works pasted in a terminal. The router, the watchdog and the notes keep working with the app closed.

Of the 39 jobs today's flow does for you, the app takes over four, all watching or alerting: which workers are busy, idle or stuck; the alert at your desk; the list of what waits on you; each epic and its evidence. It gives a button to four: your sign-off, your rule-file commit, the merge, and opening a doc. It leaves sixteen as they are (the gate, the hooks, the notes, the review, the signer list, the launcher, Telegram, releases, your pushes). The fifteen GitHub-flow jobs are dropped. The router's and the workers' own nine jobs (the router guard, the file guard, the sandbox, the watchdog, the inbox, the owner-action watch, the doc hooks, the worker's rules, the comment watch) are untouched: the app must never become a way round them.

  • Closed to workers. No network port, no web server, no link another program can call except the app's own link scheme for alerts. Every branch name, note, commit message, report and brief is a worker's text: shown as text, control characters blanked, never as a page or a command.
  • Fixed commands, no shell. Each program runs with a fixed list of values. keel, git and claude run from paths set in the app, never from a repository; the PATH is filled once from your login shell, because git's hooks call keel by PATH.
  • Locked-down git. No inherited GIT_* settings, -c core.fsmonitor=false, --no-optional-locks, and --no-ext-diff --no-textconv on any diff, as the watchdog's facts do (scripts/router-worker.sh). Notes are read with git log --notes=<kind> --format=%N -1 <tip>.
  • The gate, read-only. What happened is read from the notes on the tip. "Would it pass now?" waits for K2 (a gate run that writes no receipt); keel verify-dod as it is writes one.
  • Cost. A large download; a major Electron upgrade at least every 6 months (a new major every 8 weeks, the latest three supported); a signed app, or alerts fail. Whether a free signature on your Mac is enough is decided at the first build; Apple's paid membership only if not. Packaged with Electron Forge. No automatic updates at first. Windows and Linux later, in their own epic.

Two sources

Every field on every screen has one source.

SourceWhatLives
PersistentDocs, git, keel's notes, the run records under .router/runs/, the inbox's files, the app's own files (project list, alerts shown)Read from disk; survives any restart
RouterA work unit's stage, a question, a conflict, a paused epic, a worker's last report, the live workers, the alertsTold by the router; kept in the app's memory; gone when the router restarts
  • Where it travels. Two files in the main checkout's .router/app/, untracked: log.jsonl, one numbered line per change, and state.json, every value as it stands with the number of the last line folded in. Only scripts/router-app.sh writes them (K14, K15, K10); who runs which of its verbs is use-cases/router.yaml UC-ROUTE-8. The app only reads them.
  • One line, one change. About 200 bytes, never a snapshot. set replaces one key; del removes it; alert carries a headline, one or two lines, an optional work unit and a link (the state keeps the last 20). Keys: router, wu/<id>/stage, wu/<id>/conflict, epic/<id>/paused, question/<id>, worker/<name>, worker/<name>/report, facts. The line's form, a contract between the router and the app: 
    {"run":"keel-1c.20261118-203011","n":104,"at":"2026-11-18T20:39:53+07:00",
 "op":"set","key":"wu/E-LOCALTOOL.W3/stage","value":{"stage":"plan to read","tip":"6834699"}}
  • Applying a line. A new run: drop every router value and read the state. The next number: apply it. A number already seen: skip it. A missing number (the log restarts from the state past 2,000 lines): read the state once. A half-written line or an unknown key: skip it.
  • Refetch. On start the app reads git, then the state once, then follows the log; it asks no one. When the router starts, it wipes both files and begins a new run; the watchdog's next tick writes each live worker, and the router writes each stage it knows.
  • Defaults. A router field the router has not written shows its persistent part, else "not heard", grey: a stage shows what the notes and git prove (signed, merged, waits for your sign-off), else "last run: plan"; questions and conflicts are not shown and the top bar says the router is not heard; after three silent watchdog ticks (15 minutes) live states go grey and Attach is off. A3 built the list's part, and A4 and A5 build on it: the router is heard while its newest line is under 15 minutes old on the app's clock; when it is not, or has not started, the list hides the router's items and a line says why, and what git shows stays. The grey states above are for the screens A4 and A5 add, which show one item's router fields (screens 3 to 5).

The design principles, your comments of 2026-11-18 read as rules for every screen (W3's result, archived):

  1. The router speaks, the app shows. The router words and sends every alert.
  2. Machine checks are badges. The gate, the tests and the reviews sit in one row of badges, never a section.
  3. Fold what you rarely read. Round-by-round detail is closed by default.
  4. Show the work and its history. What it is in one line, then each step with its time and the run that made it.
  5. Docs are links. Each opens in one click.
  6. Actions first. A screen about one thing opens with what you can do now.
  7. Your words reach the worker and stay. A note box; the router passes the note on; it joins the history.
  8. Every path leads into the app. An alert, a Telegram message, any name on any screen opens that thing.
  9. Every thing opens the same way. A work unit, an epic and a worker each have actions, what it is, links, history, docs, folded detail.
  10. Links go both ways. A work unit or epic names its workers; a worker names its work unit and epic.
  11. You can always step in. Every live session has Attach: it opens that session in your terminal.
  12. Two sources: what lasts, and what the router tells. As above.

  1. You click. The window names the item, never a command.
  2. The main part re-reads every value from git and rebuilds the line. If the tip moved, the item is redrawn and nothing runs.
  3. A macOS dialog from the main part shows the folder and the full line. You confirm once.
  4. It runs the program with its values, with no shell, one run at a time per project, with no timeout (a merge stopped half-way leaves git mid-merge).
  5. Keel's words appear under the item as text. The app reads nothing into the exit code; the watcher sees the note or the merge and moves the item on.
  • Values are checked before the button is on. The tip: 40 lowercase hex. A branch: keel's naming shape and git check-ref-format. The folder: listed by git worktree list --porcelain with exactly that branch and nothing uncommitted. The signer id: listed in the target's committed .keel/mr-allowed. The report: under the docs folder, the right role, present at the tip (an epic's: a file in the folder's docs/.archive/). The message: typed by you, starting empty, never starting with -.
  • Open shows the committed bytes. The app copies the tip's docs from git into its own folder and opens the page there, so you read what keel hashes; links between docs and htmldoc's comments still work. Only an epic result opens in place.
  • Code changes is a page the app writes in its folder from git diff --no-ext-diff --no-textconv -M <base> <tip>, every byte escaped and no script allowed, and opens in your browser: the only place a worker's text cannot reach anything that runs.
  • Beside the three commands the app only opens a terminal window on a live session (Attach, claude attach <id>, no confirm: it writes nothing; K13) and posts your note to the router's inbox on your Send (K11).
  • Not designed: signing with a key (no terminal for a passphrase; your username signs) and a sign-off that waives a review (you type --waive-review, then --confirm-waiver, in the terminal); both are A4's.

A3 as built (E-APPLIST)

The app's code is app/ in this repository, under the gate (DEC-78). It is read-only: it runs git's fixed reads, reads your login shell's PATH once at start, opens pages, and writes only its own folder (~/Library/Application Support/Keel: settings, the project list, the alerts shown, the marks, the copies Open makes).

An alert at your desk (n1, UC-APP-1)

One macOS alert per alert line the router's sender writes, before it sends to Telegram, shown once across restarts; a click opens the list on its work unit. The contract is use-cases/app.yaml UC-APP-1, the choices DEC-78.

Your list, Open and Mark sent (n2, UC-APP-2)

Waits on you shows three groups (yours, not yours, sent), every kind in the hand-off table but the rule-file commit, gate failed and merge conflict; Open shows the committed page, and Mark sent holds a plan or a question under Sent. The contract is use-cases/app.yaml UC-APP-2. Screen 6, Projects, holds one project, each tool's path, the test alert, the counts and the last change seen.

The window

React in strict TypeScript, built by Vite through Electron Forge's Vite plugin (DEC-71). It reaches the main part only through one bridge, by nine named requests, each checked in the main part, and two push events. Tailwind 3 on Keel's own closed tokens (DEC-72): a lint helper refuses an off-list class, an arbitrary value or a class built at run time, and a check on the CSS Tailwind emits is the guarantee. Browser mode draws the window on a fake bridge with no Electron (pnpm dev:browser, DEC-74). The design rules, from the look the owner chose on 2026-11-22:

  1. Every value comes from a token; a new size or colour is a token change, never a class or an inline style.
  2. Two worlds, chosen by the Mac: day is light, night is dark; a colour variable flips.
  3. One solid action per card, a black pill by day; every other action an outline pill.
  4. Buttons and badges are pills; cards are white by day and one step up from the canvas by night, on a 1px hairline with 12px corners; no shadow, no gradient.
  5. The screen title and section heads in New York, in sentence case; the system sans for the rest.
  6. A state is a word on a badge whose colour repeats it; a problem is words in the problem colour; nothing by colour alone.
  7. Every text pair reaches 4.5:1 and every button edge 3:1, in both worlds.
  8. Text from the main part is shown as text, never as markup; a path is shown whole, in mono.
  9. One action at a time: every button is off while a request runs, and its outcome is a sentence.
  10. Actions first; what you rarely read is folded.

GitHub

Its flow is dropped: the checks, the sign-off by approval, auto-merge, the bot, the watch, the docs site, the settings check. E-GHREVERT reverts it first, after you switch your GitHub settings off. Two things stay: releases (release.yml on a version tag, with no pull-request run) and your own pushes of main, the epics, the notes and the tags. E-GHSETUP is closed.
