Extend, not a sibling

The existing test is extended in place and keeps its name. It already holds the costly fixture (a self-clone of Keel with the working tree's router files laid over it and keel's hooks installed) and every assertion W7 must keep. A sibling would build that fixture twice and leave the epic with two tests both called its e2e. The name stays because UC-ROUTE-5, backlog R5 and the epic plan cite it.

The test builds a Launcher value over the self-clone (the struct's fields are plain paths: main = the clone, wt = the WU worktree, wt2 = the epic worktree, stub, state). That makes every existing helper usable as it is: Launcher::cmd, sessions, set_sessions, facts, blocks, watchdog_argv, watchdog_hooks, run_hook, argv_of, worker_argv, option, calls, field, brief_copies, run_dir, wired_guard, bounded, hermetic. No new helper is planned.

What the probes do and do not show. "Nothing written outside the temp dir" is bounded evidence: every directory the scripts are given (checkout, HOME, state, decoy) is in the temp dir, every path they print and every CLI call's directory is checked, and the one outside repository they could reach by inheritance is compared byte for byte. It is not a filesystem-wide proof. Determinism: the stub lists a session at once and idle, so no launcher poll sleeps; both watches take one look; no assertion reads a timestamp, a session id's value or a temp path's random part.
