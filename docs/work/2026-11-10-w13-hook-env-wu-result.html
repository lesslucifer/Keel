Outcome

Delivered against the requirement:

  • (1) Product. src/main.rs has GIT_LOCAL_ENV, the 15 names from git rev-parse --local-env-vars, and no_git_env(cmd, keep_index). sh() strips all 15. git() strips all of them except GIT_INDEX_FILE, and its explicit envs are applied after the strip. Because repo_root() goes through git(), keel finds the repository from its working directory. The check_push scratch path now proves the pushed sha, with no code of its own.
  • (2) Tests. tests/common/mod.rs provides GIT_LOCAL_ENV, no_git_env and cmd(). Every spawn in tests/*.rs that can reach git goes through common::cmd; only jq, ps and kill are left as they were. Both git clone calls in init.rs set current_dir.
  • (3) Sign-off. gate::sign_ready now returns (tip, base, target). mr::landed refuses when tip == base, before any report lookup, hash, signature or write.

Deviations

  • Commit order. The plan's c1/c2/c3 code commits landed as one code commit, db3e2a5, followed by the audit commit. Why: the test files carry both the helper conversion and the new tests, so any split would have left an intermediate commit red.
  • Test helper shape. The plan named common::no_git_env. Tests call common::cmd(prog), a Command that is already stripped, and no_git_env stays available for W12. The calls are fully qualified (common::cmd) in five files, because local variables named cmd would otherwise shadow the helper.
  • Scope grew through the audit. Four more product spawns bypassed git(): notes::hash_blob (git hash-object), mr::report_hash (git cat-file), keel mr commit (git commit) and init's sh -c "command -v keel". All four now go through no_git_env. A second source-scan test, every_keel_spawn_strips_gits_env, guards src/ just as the plan's scan guards tests/.
  • Stronger regression test. The check regression test also points GIT_INDEX_FILE at B's index, and its test command runs git add -A. Without these, the mutant "sh() keeps the index" survived.
  • Code review r1 fix round. Review r1 found no blockers and no importants. Three nits were verified, all in the source scans: the test scan exempted any line that contained "jq", "ps" or "kill" anywhere; the src scan accepted no_git_env on the next line or anywhere on the line; and the src scan carried a test-only "x" exemption. Six candidates were refuted. Fix (1129619): no_git_env now takes the Command by value, so every spawn reads no_git_env(Command::new(..), ..) on one line. Both scans now judge each occurrence: only the exact programs jq, ps and kill (tests) and ssh-keygen (src) are exempt. Two mutants that slipped past the old matching, a raw spawn commented "ps" and a raw spawn commented no_git_env, are now both caught.
  • Red evidence for the epic-level refusal. On unfixed code, the epic case of the landed-tip test was refused for another reason (no report named), so only the WU case shows the incident's overwrite. After the fix, both cases assert the "already contained" text.
