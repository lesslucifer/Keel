Deviations

  • The guard does more than the epic plan's "a .rs file directly under tests/". It also fails on a second tests/<dir>/main.rs, a [[test]] table or autotests in Cargo.toml, and a file in tests/suite/ that main.rs does not declare. That last one is new with the suite: such a file compiles into nothing and its tests silently never run. As the WU plan's open point 2 said.
  • The epic plan expected about 38 s from its trial. This session measured 33 to 40 s after against 48 to 50 s before; the load ran from 3 to 55 because other workers were testing, so the after figures are a range, not one number.
  • Two comments still name the old paths: scripts/router-guard.jq and scripts/router-worker.sh say tests/router.rs. Both files are rule-bearing, so changing a comment there needs the owner's keel mr commit; left as they are (follow-ups). The comments in src/init.rs and tests/suite/mr.rs were updated.

The thread cap. The rule was: cap at 8 only if 8 threads beats the default by 10 % or more in every pair. It did not: 38.2 against 33.4 s (slower), 36.2 against 40.0 s (9.5 % faster, with the load at 55), 48.4 against 33.2 s (slower). Before the move, 8 threads was 2 to 3 % faster, within noise. So no .cargo/config.toml. The epic's trial saw 8 threads win (29.2 against 35.1 s) with the watcher test skipped; W1 and W2 since cut the git cost per spawn and the 20 s watcher wait, which is the likely reason the gap closed. W5 re-checks it after W4, as the epic plan says.

Same tests, same names. cargo test -- --list before the move gave 334 names. After it, the unit tests list 98 and suite 238. With the module prefix dropped from the suite names, the 236 integration names before and the 238 after differ by exactly the two new tests. No test body changed; each file's mod common; became use crate::common;. Nothing in tests/ sets environment variables or the working directory, so sharing one process reaches no other test.
