E-SEED2.W12 · The router watches owner actions itself — result

The router arms scripts/router-watch.sh as a background command for each staged owner action and wakes on its event line. The owner no longer has to reply "done".

T3 · WU result · 2026-11-10 · Keel · branch wu/E-SEED2/w12-owner-watch off epic/E-SEED2 ef9ee75 · W12 plan

Outcome

Delivered against the requirement, which comes from the owner's request of 2026-11-10: the router must detect owner actions itself and never wait for "done". The plan was approved with D1–D6 as recommended. scripts/router-watch.sh handles the five kinds (commit, signed, merged, pushed, tagged). For each kind it polls git read-only, prints one event line followed by two-space detail lines, and exits 0. On no change it prints TIMEOUT, and on a failing origin UNREACHABLE. Arguments it cannot validate are refused with exit 2 before any poll. scripts/router-guard.jq admits exactly the five shapes. The owner's commits add the allow entries (router-watch.sh and the missing wait), the posture bullet and the skill text. That text tells the router to arm a watch for every staged owner action and to ask only for what cannot be observed.

  • Code-review fix round. keel-code-review over ef9ee75..ab9d66e returned FAIL with one blocker and one important finding. The blocker: pushed on a branch that exists only locally counted the missing remote ref as a network failure, so after five polls it printed a false UNREACHABLE. Now ls-remote runs first, and a branch that origin does not have is "not pushed yet": the watch stays silent and the failure count resets. The important finding: Watcher::run in the tests had no deadline, so a watch that polled more often than the test released it could hang cargo test. It now kills the watch after 10 s and fails the test. Review r2 lows N1 and N2 are fixed in the same commit, d9bd7da. N1: the fetch now runs with followRemoteHEAD=never. The audit of the other kinds found no expected "not yet" state that is misread as an error or as a final event.
  • Code-review fix round 2. keel-code-review over ef9ee75..e3c6f69 returned FAIL with two important findings. V1: when the target branch of a merged watch was deleted, the watch logged a fatal on every poll until TIMEOUT. Under the owner's ruling (option A), merged now prints DELETED target=<b> at once and exits. It reads the target once per poll, so the ancestry check and at= see the same sha. V2: the tag tests depended on the user's global tag.gpgSign. Every git a test runs, including git inside the scripts under test, now goes through hermetic(), which sets GIT_CONFIG_GLOBAL=/dev/null and GIT_CONFIG_NOSYSTEM=1. Nits:
    • Fixed: check_commit runs one diff, not two.
    • Fixed: pushed skips the fetch when origin/<b> already has the sha that ls-remote reported.
    • Fixed: clean() also masks UTF-8 C1 (U+0080–009F), U+2028–202E and U+2066–2069. This closes the earlier N3.
    • Fixed: the sleep shim exits when its caller is gone. Watcher::run and Stepped::line reap the child they killed; without that, the zombie kept kill -0 true.
    • Fixed: all the harness waits share one BOUND constant (10 s).
    • Kept: the ls-remote/fetch race. If the branch is deleted on origin between the two calls, the fetch fails and counts once. The next poll finds the branch missing, which resets the count, so the race cannot produce a false UNREACHABLE.
    One regression was caught while fixing: moving the count reset ahead of the fetch would have left a fetch that always fails, behind a working ls-remote, polling to TIMEOUT. A new stepped test pins it. A mechanical mutant sweep was run over every changed branch in the script and the test harness (32 mutants), and tests were added until no non-equivalent mutant survived. Same-class audit: no other watch polls to TIMEOUT on a vanished ref. commit prints DELETED. signed watches a sha. For pushed and tagged, a ref missing on origin means "not yet" by design. Two git calls in older tests (the PUSHED probe and the e2e worktree add) also go through hermetic() now.
