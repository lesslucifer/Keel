What happened

Step 1 is done: the tool, its tests and the use-case and decision records. A review now reads the settings of its level: the WU settings when the work merges into an epic, the epic settings when it merges into main. Each setting falls back to the shared one, then to the default. A new setting, off unless set, lets a round's blockers get a recorded fix with no new round and no waiver. A project that sets nothing new runs exactly as before. Steps 2 to 5 are yours.

The main case, as the tests run it

The epic sets the WU level to one round, with blockers fixed from round 1.

  1. WU H's round 1 finds a blocker. The tool says: fix it and record the fix.
  2. The author asks for the cap's waiver. The tool refuses: this blocker gets a fix, not a waiver.
  3. The author fixes it. A second round is refused, naming the recorded fix.
  4. The fix is recorded. The merge check reads it as a pass.
  5. At sign-off you see the fix, the blocker it answers and the file it changed. You sign with no waiver to accept.
  6. The epic's own review then follows main's epic settings, not the WU ones.

These steps run through the real tool and hooks. A hand run in a scratch folder was blocked by this session's permission check.

Differences from the plan

  • The tool learns the main branch's name from the rules file each command already reads, so the level and the merge target always agree.
  • A bad value at one level refuses the whole rules file, for both levels.
  • A level cannot switch off the blocker fix setting when the shared settings turn it on. Keel sets it for WUs only, so the epic keeps its waiver.
  • The waived-review use case was updated too, as the plan's records list says.
