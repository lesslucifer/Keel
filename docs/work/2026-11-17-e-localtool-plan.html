E-LOCALTOOL · A desktop app for your flow, in place of GitHub's

Ideas and draft screens only. No code.

T3 · epic plan · v3 · 2026-11-18 · your comments and answers of 2026-11-17 applied · Keel · off main 6cf3127

The problem

GitHub now runs part of your flow: the checks, your approval, the merge. Its setup is heavy. It ties the flow to one company's rules, prices and outages. Each step waits on a push, a check run and a web page. And its pull-request page is not where you want to read and approve. This epic decides what a local desktop app should do instead, and drafts its screens. It builds nothing.

The target: a sign-off with the app

  1. A worker finishes its part. Your Mac shows: "W2 waits on you".
  2. The app shows the review and the checks, all green.
  3. You click the result. It opens in your browser, as docs do today.
  4. You run the sign-off command the app shows, in your terminal. Both the sign-off and the merge run on your Mac.

W2 · The Electron app, and how it talks to keel, git and the sessions

In short: you chose Electron. Sketch the app's parts, and how each reads keel's state and runs keel. Name what Electron costs and how to keep that small.

  • The parts: the main process (runs commands, watches files, sends alerts) and the window (the screens). Packaging and signing on macOS; size; Windows and Linux later.
  • Talking to keel: run the CLI and read its output (a JSON output mode would be new), or a Node binding of keel's Rust code. Recommend one. Talking to git: the git CLI, watching refs/notes/* and branch refs instead of polling.
  • Talking to the sessions: the router's inbox, claude --bg sessions (what Claude Code exposes: list, status, send), the watchdog's facts; DeepSeek Harness's worker tools as a second host.
  • Alerts: macOS notifications at the desk; Telegram (notify-owner.py) kept for when you are away.
  • Safety: the app runs on your account, so it must not become a door for a worker (the router guard and the file guard stay as they are).
