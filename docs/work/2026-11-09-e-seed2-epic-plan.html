Epic plan for epic/E-SEED2: absorbs backlog E-SEED v2 (B1–B7) plus two owner additions of 2026-11-09 (opus-only worker policy, worker watchdog).

T3 · epic plan · 2026-11-09 · Keel · branch epic/E-SEED2 off main 296fa97

Intent

Finish what E-SEED deferred so Keel can be installed without a Rust toolchain and its gate is complete: ship the parked release pipeline (prebuilt binaries via GitHub Releases, npm, Homebrew), make the human sign-off's report requirement configurable and found by role rather than path, stop Keel's hooks silently fighting other hook managers, prove the whole workflow with an epic-level e2e on a non-Rust fixture, write the missing T1 architecture doc and the remaining Trawler decision records, and close the small init/hook follow-ups. Two router-operations items ride along by owner request: every headless worker runs on opus (owner ruling 2026-11-09), and a watchdog pushes worker status to the owner instead of the router waiting to be asked. Why now: E-SEED and E-ROUTER are both on main (296fa97); the W10 branch is drifting further from main with every merge, and the router has started running multi-worker fleets where unwatched workers are the main source of lost time.

Expected result

  • A maintainer-pushed tag produces a GitHub Release with four Unix binaries and a shell installer, an npm package and a Homebrew formula in lesslucifer/homebrew-tap; keel --version prints Keel's version in a directory that is not a git repo.
  • With [mr] report = "none" a WU without a result doc signs and merges green; with the default "required" a WU missing its wu-result doc is refused at mr confirm and at the merge with a named failure; a result doc with any filename is found by role.
  • keel hooks install over a foreign core.hooksPath refuses without --force; keel preflight/verify-dod refuse when another tool reset core.hooksPath.
  • cargo test includes a hermetic e2e that drives a Python-only scratch repo through init → epic → WU → notes → preflight → cr → mr confirm → merges, and the four named refusals.
  • docs/architecture.html exists (T1) and verify-doc is green over all docs; every Trawler DEC named in backlog B5 resolves to a Keel record by lineage.
  • A fresh clone after keel init fetches notes with a plain git fetch.
  • project-router and the router decision record state opus-only workers with medium/high effort; the launcher refuses any other model.
  • With a watchdog running, the owner gets a Telegram message within one poll interval of a watched worker exiting or its .out going stale, without asking the router.
  • Backlog e-seed-v2.html has every row struck or re-pointed.

Non-goals

  • crates.io publishing, Windows builds, code signing / notarization (B1 scope, unchanged).
  • A second fixture language for the e2e (B3 says "then a second language"; Python first, the second is a follow-up).
  • Chaining other tools' git hooks (rejected in the W9 plan: re-imports branch-controlled code).
  • The E-ROUTER v2 backlog (R1–R6) other than what the watchdog needs; native SSH signing (B7) unless W6 finds it small — default: stays backlog.
  • Agents tagging releases or pushing: the owner tags and pushes.

E-SEED2.W8 · Worker watchdog with Telegram push scope flagged done

Status: done. Delivered on epic/E-SEED2 by the WU merge 1941842 (design deviated to router-worker.sh wait; see the W8 result). Carried unchanged to main by E-ROUTERFIX.W4 (0dad93f) and synced back into this epic by W10.

A watchdog headless worker that watches other running workers' .router/runs/ .pid and .router/out/<name>.out files on an interval and pushes a proactive update to the owner when a watched worker finishes (pid gone) or stalls (.out unchanged past a threshold). Polling is a cheap shell loop (scripts/router-watch.sh) so the model wakes only on an event; the push goes through the already-configured Telegram channel's reply tool, never by reading the bot token. Scope flag: this is router meta-tooling that belongs with E-ROUTER v2; tracked here by explicit owner request.
