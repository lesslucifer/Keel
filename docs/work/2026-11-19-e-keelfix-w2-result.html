Deviations from the plan

  • The strict option reader lives in src/notes.rs (notes::args_problem), shared by gate::opts and notes::known_args. The plan gave the gate its own parser. The existing guard cli::the_target_grammar_is_written_once_in_notes refuses the --target form outside src/notes.rs, so the gate's first version failed it. gate::opts now returns only whether to write the receipt; the target is still read by target_of, unchanged.
  • One line in main(), not two: help::exit_if_asked(); reads the arguments, prints and exits. src/main.rs changes by that line and mod help; only.
  • The notes writer's refusal reads keel notes: refused - notes write doc: unknown argument '--distil', with the kind's usage on its fix -> line. The plan wrote unknown argument '<a>' for notes write <kind>; same content.
  • A test fixed before green: no_receipt_runs_the_whole_gate_and_writes_nothing expected the dry run's output to be the gate's plus one line. The gate prints wrote refs/notes/dod on … last, so the dry run's output is the gate's with that line replaced by no receipt written (--no-receipt). The test now asserts that.
  • Open point 6 reversed (review round 1, B1): help on the hook commands is limited to keel hook alone (or with help before hook). Git runs keel hook pre-push "$1" with the remote's name, and a remote may be named -h or --help; reading that as help skipped the whole push gate. Every word after a hook's name is now git's.
  • A flag's value is never another known flag (review round 1, I2). notes write doc --distill --target --target epic/x passed the strict check, then the flag-by-flag readers took --target as the target. notes::args_problem now refuses such a value, so both readings agree.
  • A guard that each dispatched command has its own usage (review rounds 1 and 2, I1 and I2): every_dispatched_command_has_its_own_usage reads every slice pattern that leads with a literal word, in every module main.rs declares (match arms, let and if let patterns, alternatives). It places each under its dispatcher (run(), gate::verify_dod, gate::preflight_cmd, mr::run, notes::write's kinds). It fails on a pattern outside them and on a module it does not read. Each dispatched command must have its own help row; a parent usage that names it no longer counts. Each row must lead to a dispatched command. So the help table gained eight rows: hooks install, the three hook names, notes write, and verify-dod commit|hook|range. One command list that drives both dispatch and help was the review's preferred fix; it would mean rewriting run(), which W1 and E-DOCSPLIT edit and which the plan leaves alone.
  • Open point 2: W1 had not landed in epic/E-KEELFIX when W2 was built, so run()'s top and init usage lines stay literals; src/help.rs holds equal copies, kept equal by each_usage_error_prints_the_help_text.
