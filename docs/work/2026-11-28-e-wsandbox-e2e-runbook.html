Your commands

Use one terminal. Each command logs to $HOME/keel-wsandbox-e2e.log. The setup script runs only in the probe clone and refuses to run anywhere else. It is safe to re-run: each run first removes what an earlier run left.

  1. Prepare. The script removes leftovers and checks the clone is clean. It checks out this epic's tip detached, builds its keel, and stages worker_model = "haiku". 
    cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh prepare
    Expect: ok: detached on the epic tip: …, the five [router] lines with worker_model = "haiku", ok: built the epic's keel, then the exact line for step 2. Failure: any FAIL: line; stop and send the log.
  2. Your signature, then start. .keel/ is rule-bearing, so the commit is yours. The script prints this line and never runs keel mr. 
    cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && keel mr commit -m "probe: haiku workers for the E-WSANDBOX e2e" --as vuluu && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh start
    Then start does the following:
    • checks that HEAD is the tip plus that one line;
    • installs the epic's hooks, so C5's turn-end script is checked;
    • makes epic/E-PROBE and wu/E-PROBE/{work,plan,done,gone}, each with a commit of its own, and merges done and work into the epic. Plumbing makes these commits: no checkout and no hook, in the clone only;
    • adds the four worktrees through the launcher and deletes the gone folder;
    • writes the two briefs, and an untracked red doc docs/work/probe-red.yaml;
    • starts the probe router: claude --bg -n probe-router --agent router --model haiku "Read …/docs/work/2026-11-28-e-wsandbox-e2e-probe-router.md in full and do exactly what it says."
    Expect: ok: probe-router runs (session …). Failure: the commit refused, or a FAIL: line.
  3. Finish, after your router relays "E-WSANDBOX e2e probe run finished". 
    cd /Users/nguyenvanluong/Documents/proj/misc/Keel-probe && bash /Users/nguyenvanluong/Documents/proj/misc/Keel-E-WSANDBOX/docs/work/2026-11-28-e-wsandbox-e2e-setup.sh finish
    It appends the probe router's full report to the log and runs the two checks the router's guard cannot run. First, status probe-w1 against a jq sum of the transcript's last and peak usage: PASS status matches the transcript. Second, the router's red-doc messages: at least one router message, none in the worker wording, agentSetting=router and the red doc unchanged, giving PASS the router was told and did not edit the doc. Then it cleans up and ends ok: no probe session, worktree or branch left and Done. A FAIL check line is a result: send the log either way. The clone stays detached on the policy commit, and the next prepare moves it.
