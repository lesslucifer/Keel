Decisions: the local app's build

How the local app's window is built, styled, tested and developed, and what E-APPLIST leaves out. Why the app exists and what it may do is DEC-70.

T2 · decisions · current truth · 2026-11-23 · Keel · DEC-71 – DEC-78 · the design: local-app.html

Current truth: each record says what stands today, why, and what was rejected. A later decision that changes one is folded in and named. Ids are never reused. The owner ruled on DEC-71 – DEC-77 on 2026-11-20, after he paused E-APPLIST ("we ran too fast on the app") and studied Trawler, a Tauri app whose window is React, Tailwind and Vite. Keel's app stays Electron (DEC-70). DEC-78 records the rest of E-APPLIST's choices at its close.

The window

DEC-71 · The window is React with Vite; Trawler's patterns, not its look

ChoiceThe window is React in strict TypeScript, built by Vite through Electron Forge's Vite plugin, which also builds the main part and the preload. It reuses Trawler's logic patterns: the main part is reached through one injectable bridge object, state lives in hooks and context, and stores are small. It does not reuse Trawler's design, look or components: Keel draws its own. This replaces the superseded W4 plan's default of a plain TypeScript window built with textContent.
WhyThe six screens hold lists that change live from two sources, folded detail and actions per item. Trawler's patterns keep such a window testable without its back end: a test injects a stub bridge and renders a screen. Its components belong to a different app.
RejectedThe W4 plan's plain DOM window. Trawler's components or look, as they are.

DEC-72 · Tailwind with Keel's own closed tokens, held by a lint rule

ChoiceThe window is styled with Tailwind on a closed token config of Keel's own: its palette, spacing and type scale replace Tailwind's defaults, so no other value exists. A lint rule, modelled on Trawler's ui/eslint-rules, refuses any class outside the config, any arbitrary value (such as p-[13px]) and any class built at run time from fragments. Light and dark follow the Mac's setting. The font is the system's: no font file ships, so the content policy needs no font source.
WhyTailwind drops an unknown class silently, so a closed config alone shows nothing; the lint rule is the alarm, as in Trawler. A closed set stops agents, who draw most of the window, from inventing a size or a colour per screen. The system font keeps the content policy as tight as the W4 plan had it.
RejectedTrawler's palette and fonts. Tailwind's default scales.

DEC-73 · Window tests run on Vitest, by hand; keel check keeps node --test for the main part

ChoiceThe window's tests use Vitest with jsdom and Testing Library, the bridge injected as a stub. Workers and reviewers run them by hand and record the run in the result. keel check does not run them: it runs cargo test and node --test over the main part's tests, which need no package installed.
WhyVitest needs npm packages, and keel check runs on every push and installs nothing. To be revisited: backlog local-app L6.
RejectedVitest inside keel check now.

DEC-74 · The window is developed without packaging the app

ChoiceTwo loops. electron-forge start runs the whole app unpackaged, with live reload. A browser mode serves the window alone from Vite against a fake window.keel built from fixtures, so a screen is drawn and checked in a browser with no Electron and no main part. The fake exists only in the dev build: the shipped app adds no port and no server. A packaged, signed build is made and checked live only at the close of the app-shell WU and at the epic's close, never per UI change.
WhyPackaging is slow, and the alert check needs the owner's Mac; a UI change needs neither. Trawler draws its window against a headless core, but Keel's window has no port to reach: the main part answers only through the preload, so the browser mode's stand-in is a fake bridge, not a server.
RejectedA dev-only Vite middleware over the real main-part handlers, now: backlog local-app L7, added if the fixtures prove too thin. A packaged build per change.

DEC-75 · The window's end-to-end test is Playwright on an unpackaged build

ChoiceThe epic test drives the real window with Playwright's Electron launcher (_electron.launch) on an unpackaged build, on temp repos with the real router scripts. It is part of E-APPLIST's epic test, a must, never a backlog item. What no test reaches (the macOS alert on a signed build, its click, Launch Services) is checked live at the epic's close and recorded in its result.
WhyThe window is where the owner sees every item. A test of the main part alone, the old plan's epic test, never shows that a router line reaches the screen. The Electron launcher drives the app with no package built.
RejectedTrawler's WebdriverIO run on a built app. An epic test with no window.

E-APPLIST's scope

DEC-76 · W4's code is dropped; W1 stays

ChoiceThe work on wu/E-APPLIST/w4-app-frame (tip 83fdd8f) is discarded as work: never merged, never signed. Its branch stays in git as reference. The new app-shell WU (E-APPLIST.W7) may re-derive its main part, bridge, handlers and tests, red first, and assumes none of it is reused. W4's [check] commit 717f2b9 was never on the epic. W4's plan, merged on the epic, is superseded by W7's and archived. The id W4 is not reused. W1 (the router's update log, scripts/router-app.sh, on wu/E-APPLIST/w1-update-log) is unchanged and goes on to its sign-off.
WhyThe app ran ahead of its design. W4 built a plain DOM window and a bridge with requests only. The window now needs React, Keel's tokens and a push channel, by which the main part tells the window that something changed; these reshape the bridge and the window. W1 is the router's side, and none of this touches it.
RejectedMerging W4's code and reshaping it in later WUs.

DEC-77 · No tray, menu or login item in E-APPLIST

ChoiceE-APPLIST builds no tray (menu-bar) icon, no menu of its own and no start at login. The app keeps running when its window is closed, so alerts still come.
WhyAn alert needs only the app running, with no window open. The three are conveniences: backlog local-app L9.
RejectedBuilding them in this epic.

How E-APPLIST built it

DEC-78 · The app lives in this repo under the gate; the router's lines reach it first

ChoiceThe app's code is app/ in Keel's repository, a code path of the gate. Its main part is tested by Node's own runner inside keel check, with no package installed; its window by Vitest and the epic by Playwright, both by hand (DEC-73, DEC-75). The router tells the app what only it knows through one update log (UC-ROUTE-8). The sender writes the alert line before it sends to Telegram. A question travels on the alert's body; the router deletes its line once answered. Only the packaged app claims keel://, and it opens only keel://wu/<id>. Four file seams (KEEL_APP_ALERT_SINK, KEEL_APP_OPEN_SINK, KEEL_APP_SILENCE_MS, KEEL_APP_DIR) let the epic test drive the unpackaged app; the packaged app ignores them.
WhyOne repository gives one review and one gate, and the app only reads keel's CLI and git. Tests that need no install keep keel check fast and whole. A Telegram failure must never lose the desk alert. A question on the alert's body adds no free-text path past the router's guard. A development run must never make Electron the owner of the link. Seams that only an unpackaged app reads cannot change what the owner's app does.
RejectedA separate repository for the app. The window's tests or the epic test inside keel check (backlog L6). A new free-text channel for questions. keel:// claimed by every run. Test hooks compiled into the packaged app.
