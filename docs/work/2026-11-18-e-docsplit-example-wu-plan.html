The problem

The epic splits each plan and result into a short page for you and a data file for agents. It also slims today's long docs. Nobody has listed which docs that touches, what each keeps, or how short "short" is. The rest of the epic builds on that list.

How you approve

  1. You open the inventory page: the table first, then the caps and the page shapes.
  2. You compare the two examples with the pages you already read.
  3. You comment. The worker fixes each point.
  4. You tell the router "approved". The decision is written, and you approve the pull request.

What this part makes

  • The table: every doc Keel writes or reads, its reader, what goes on its page and in its data file.
  • The data file's fields, named after today's tags.
  • A shape for the epic and part plan pages, with two real examples.
  • A word cap per kind of page, and what each slimmed doc drops.
  • After your approval, one new decision recording it.

How you'll know it worked

  • A scan of the code finds no doc without a row.
  • Every tag today's check reads has a field.
  • Each example page is under its cap.
  • The decision's number is used on no branch.
