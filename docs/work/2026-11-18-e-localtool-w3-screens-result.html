Two sources: what lasts, and what the router tells

In short: 68 fields are read from disk and git, and survive any restart. 36 are told by the router: a work unit's stage, a question, a live worker, an alert. The app keeps them in memory. When the app starts, it reads the router's current state once. After that, the router sends one small line per change, numbered, so the app can tell when it missed one.

The app reads persistent data itself. Router data comes as lines in an update log, and a current state the same command keeps. Both live in the main checkout's .router/app/ (untracked) and only for one router run. The app never writes there.

Terms

Update logOne line per change, each with its run and its number. Only the router's command and its watchdog add lines.
Current stateEvery router value as it stands, with the number of the last line folded in. The same command keeps it, so the router does no extra work.
RunOne router's life, from its start to its end. A new router starts a new run and wipes both files.
DefaultWhat a router field shows when the router has not written it: its persistent part, else "not heard". Never blank or broken.

Updates: one line, one change

One line is one change to one thing, about 200 bytes. Never a full snapshot:

{"run":"keel-1c.20261118-203011","n":104,"at":"2026-11-18T20:39:53+07:00",
 "op":"set","key":"wu/E-LOCALTOOL.W3/stage","value":{"stage":"plan to read","tip":"6834699"}}
setOne key's new value replaces the old one. Keys: router, wu/<id>/stage, wu/<id>/conflict, epic/<id>/paused, question/<id>, worker/<name>, worker/<name>/report, facts
delThe key is gone: a question answered, a conflict fixed, a worker stopped
alertHeadline, lines, work unit, link. Shown once. The state keeps the last 20, so an app that was closed still shows the ones it never showed

How the app applies a line:

  1. A new run: drop every router value, read the current state, go on after its number.
  2. The next number: apply it.
  3. A number already seen: skip it.
  4. A number missing: read the current state once, go on after its number. This happens when the log is cut short (past 2,000 lines it starts again from the state), or the app slept through a cut.
  5. A half-written line, or a key the app does not know: skip it. The app reads only whole lines.

A question's text and a report come from a session: the app shows them as text, never as a page or a command (W2 Q7).
