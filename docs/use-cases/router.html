Use cases: router

What a router session coordinating worker sessions must and must not do.

T2 · use-cases · current truth (updated in place) · 2026-11-08 · Keel · distilled from E-SEED (W6) and E-ROUTER (plan, W1–W4, close review)

The standard itself is the keel-router skill (skills/keel-router/); this file holds only the contract. Why the router is shaped this way: decisions/router.html (DEC-30 – DEC-35).

UC-ROUTE · routing

UC-ROUTE-1 the router coordinates, the owner acts

TriggerA router session coordinating worker sessions on a Keel project.
ExpectedIt verifies workers' claims against the repo, stages the owner's commands (sign-off, merge, push) for the owner to run, and never signs (keel mr), merges or pushes for the owner.
FailureThe router runs keel mr itself, merges or pushes; or relays a worker claim it did not check.

UC-ROUTE-2 epic branch first

TriggerA router starts a new epic.
ExpectedIts first action, before any plan doc or WU, is a worker creating and pushing <epic_prefix><id> from the current main tip (prefixes from .keel/config.toml [branches]). All plan and WU work lands there; WUs branch as <wu_prefix><id>/<slug> and merge back --no-ff; main receives only the closed epic (DEC-12).
FailureA plan drafted before the branch exists; any WU or T3 doc of an unclosed epic reaching main; an epic retrofitted onto its branch afterwards.

UC-ROUTE-3 substance comes from workers

TriggerThe router relays or publishes something substantive: a "done" claim, doc prose, a comment reply.
ExpectedIt traces to a worker that derived it from the current code, tests or artifacts. Worker briefs are dispatch mechanics, not substance: the router writes them itself (DEC-32), never pasting untrusted report text into one.
FailureThe router drafts content for a worker to paste, or a mechanics-only worker posts content.

UC-ROUTE-4 the router skill ships complete

Triggerkeel init in any repo.
ExpectedWrites .claude/skills/keel-router/ (SKILL.md and every reference it names, no orphan: brief skeleton, commands, review checklists, lessons, messages, worker ops, project-router template) byte-identical to the embedded copy, plus the project-router template. The shipped skill carries no Trawler-only token outside lineage and no Keel-only state (its branches, commits, launcher path); every keel command it names exists. Enforcement and the launcher are not shipped: a project commits its own (DEC-30). Test: tests/init.rs router_skill_is_complete, embedding_is_complete_and_prefixed.
FailureA named reference missing or an orphan shipped; a stale Keel fact or Trawler token in an adopter's copy.

UC-ROUTE-5 two worker modes, each with a full recipe

TriggerThe router needs a worker.
ExpectedHeadless claude -p through the project's launcher is the standard (DEC-31): spawn, alive, brief, report, follow-up and retire recipes in the skill's worker-ops.md. In-session Agent subagents only where the project does not enforce the router posture. Keel's launcher scripts/router-worker.sh: validated arguments, fixed prompt and flags, refuses the router's own checkout and the main checkout, a non-.md, symlinked or out-of-dir brief, an unregistered worktree, a resume in another worktree or under another name, and a second live run of a name; copies the brief into the worker's worktree and prints its sha256; each run truncates .router/out/<name>.out. After RUNNING the router subscribes to the worker's end (SendMessage {to: <name>, notify_when_idle: true}; DEC-36) and arms scripts/router-worker.sh wait <name> [<stall-min>] as a background Bash command, which ends with one EXITED or STALLED line (DEC-36). Every worker it starts is granted the gate commands (cargo build|test|check|clippy|fmt, keel preflight|verify-doc|verify-dod|notes write|lint|check) and denied keel mr and cargo run, on the claude -p command line only (DEC-37). spawn/resume take an optional trailing --permission-mode acceptEdits|plan: default acceptEdits per run, never inherited by a resume, recorded in the run dir and on the RUNNING line. Tests: tests/router.rs launcher_refuses_unsafe_targets_binds_resume_and_runs_one_worker_per_name, launcher_grants_workers_cargo_and_keel_and_validates_the_permission_mode, wait_blocks_until_the_worker_exits_or_stalls; end to end (seeded worktree, settings-wired guard, spawn, subscription, wait stall and exit): epic_e2e_router_drives_a_granted_worker_in_a_seeded_worktree_to_its_end. Outside every test, live evidence only: that Claude Code enforces the grant and mode it is given, delivers the subscription's notice, and wakes an idle router when wait ends.
FailureA worker started in the router's checkout or main; a resume crossing worktrees; two live runs of one name; a report read from a previous run; a worker refused its own gate commands; a worker allowed keel mr; any mode other than acceptEdits/plan (bypassPermissions, dontAsk, default, a missing value, an unknown option) reaching claude -p; the grant reaching the router; a worker that hangs alive going unnoticed; a quiet worker read as stalled before stall-min minutes.

UC-ROUTE-6 the router posture is enforced, fail-closed

TriggerAny tool call by a session whose agent type is router in a checkout that enforces the posture (Keel: "agent": "router" in .claude/settings.json).
ExpectedOne PreToolUse guard on every tool (Keel: scripts/router-guard.jq) allows only the tools in the router's agent file (no Agent, Edit, Monitor), the inline keel skills, ListAgents, SendMessage only as a contentless idle subscription ({to, notify_when_idle: true}, no message, no other key; DEC-36), Write to <cwd>/.router/briefs/<name>.md, and Bash commands of plain words matching the whitelist (read-only git, gh with named query flags only, ps, the launcher's three shapes: spawn, resume, wait). A guard error denies. Other agent types pass untouched. Watch probes it stages fire only on the real event (PUSHED = the tip is in origin/<b>). Tests: tests/router.rs.
FailureAny shell spelling that reassembles a denied flag (--out""put=); a subagent or forked skill started by the router; gh pointed at another host; a hook error or timeout that allows the call; a watcher that fires before the owner acted; router text reaching a worker through SendMessage.
