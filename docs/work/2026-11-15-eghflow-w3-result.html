Delivered and tested against a mock of GitHub. It goes live once your App has three more permissions: the steps are below.

Ready v3 · 2026-11-15 · T3 · WU result · Keel · plan: 2026-11-15-eghflow-w3-plan.html

Outcome

Delivered. scripts/router-gh-watch.sh watches one issue or pull request for a review, a comment, a merge or finished checks. It checks at once, then about once a minute, and exits on the first event from a commander: one event line, the text indented, control characters as ?. Anyone else is a count, never text, and never wakes the router. An edited comment is never read as an order. A comment's first line is parsed by the closed grammar /keel go|hold|retry|answer <n> <A|B>. The watch keeps no state and holds no secret: each poll asks router-gh.sh, which mints the token, reads only the bot's own issues and pull requests, and hands back plain data. router-gh.sh issue keeps a tracking issue per epic with a sub-issue per WU. pr-ready now asks you for a review. The commanders are committed: you alone, user id 5499546 (read from the public API). The guard admits exactly the new shapes; workers are denied the watch. Against GitHub itself it is unproven until your App has the new permissions.

Deviations

  • The tracking issue's text comes from git only: tip, docs, notes, WU rows. It has no "waiting on you" section yet (W8 adds it) and no link to the pull request.
  • Done here, not in the plan's card: W2's follow-up, the review request on pr-ready; and the parts of pr-open's body code that the issue reuses moved into functions (behaviour unchanged, W2's tests unchanged but the READY line).
  • Still unverified, each failing safe: that only a body edit moves a comment's updated_at (a false EDITED asks you to repost); that an installation token may read GET /user/{id} (a refusal is a WARN line; the pull request is still marked ready); the sub-issue and permission facts come from GitHub's docs, read 2026-11-15, not a live call.
  • The security review found no blocker in W3. Its findings, each fixed in this WU:
    • P1, backlog R33, older than this WU: a worker could write the shared git dir's commondir, and every git in your checkout would then read another repository's config. Now: (a) the launcher's sandbox denies writing <git dir>/commondir and every other worktree's admin commondir and gitdir, and the launcher refuses to run while a main git dir holds a commondir file. A worker's own git use is untouched: commit and notes never write these files. A worktree added after a worker started was not in that worker's list. Your own unsandboxed git in that later worktree, keel mr commit included, could then run a worker's hook. Round 2 closed that (F1, below). (b) router-gh.sh pins its own checkout's git dir (GIT_DIR, GIT_COMMON_DIR) and refuses a commondir file in the main git dir, or a linked checkout's admin dir not as git makes it. (c) Every git it runs gets no hooks and no fsmonitor (GIT_CONFIG_COUNT), and GIT_ALLOW_PROTOCOL=https. That env var overrides any protocol.*.allow in the repository's config, which -c protocol.allow=never would not. R33's backlog row is left for the epic close, where the epic plan updates the backlog.
    • I1: more than 1000 items no longer stops anything. issue lists only issues with the bot's keel-tracking label, which it creates first if missing; GitHub's docs say an unknown label is dropped. The watches read the 10 newest pages, found by the Link header's last page. When since lies before them, the watch prints OVERFLOW … since= oldest= and exits 0.
    • I2: every event line carries at=, GitHub's time, and since latest skips everything present at the first poll. The guard admits it.
    • Round 2 (no blocker; it called the WU ready):
      • F1, older than W3: a worker spawned earlier could write the admin dir of a worktree made later, and your git there ran its hook (reproduced by the review). Now every launcher run checks every admin dir under <git dir>/worktrees: a real directory, commondir exactly ../.., no config.worktree, a gitdir naming a .git. Any mismatch stops every mode before any session starts. The watchdog's facts, which never fail, report it to the router instead. The sandbox also denies the globs <git dir>/worktrees/*/commondir, */gitdir and */config.worktree. A glob does not stop a worker renaming a whole admin dir, so the per-run check is the real one. Not done, for the router's backlog: keel mr checking its own checkout's admin dir (a keel source change), and an allow-list sandbox.
      • config.worktree: the sandbox denies it in the git dir and in every admin dir. The launcher refuses one in the main git dir. router-gh.sh refuses one in the git dir or its own admin dir: git reads it even under the pins, and a url.insteadOf or core.askPass there reroutes git or runs code. Your .git/config holds no include today, so no included file is reachable.
      • F2: OVERFLOW used to hide a commander's comment inside the pages it had read. Now those items are judged all the same. An event among them carries gap=yes oldest=<id>. With none, OVERFLOW … resume=<newest id read>, and the router re-arms with since <resume>. The reviewer's resume=<oldest − 1> would loop, since that since still lies before every item read.
      • Nits: N-a the further invisible characters print as ?. N-b the header says N2 covers comments only. N-c a full first page with no Link header fails the read. N-d a deletion mid-read is documented in the header. N-e the launcher checks the resolved git dir's commondir too. N-f: no admin dir is skipped any more, and each is denied by name. A name outside [A-Za-z0-9._-] is not refused: git names an admin dir after its checkout, and a test makes o'd-d.
    • N1: zero-width characters, the BOM and tag characters print as ?; check names and status contexts are cut at 100 characters. N2: a comment an App posted for a commander counts as anyone else's. Never store a commander's own token as a repository secret: GitHub would show its comments as theirs. N3, N4: documented in the watch's header. DISMISSED names the review's author, not who dismissed it, and REST shows no edit of a review's text. N5: the tests below.
