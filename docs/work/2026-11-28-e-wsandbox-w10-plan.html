The problem

The e2e run showed that a worker cannot install the app's packages. The install failed. Package files landed inside the worktree, which the run was meant to prevent. The probe router still marked both steps PASS.

Two causes, read from the code and the records:

  1. The launcher links the app's package folder at a folder it never creates.
  2. The launcher hands pnpm its settings through its own environment. A background session does not get that environment. A background service starts the session and forwards one chosen variable only.

The e2e also left three points for you, and its own check miscounted.
