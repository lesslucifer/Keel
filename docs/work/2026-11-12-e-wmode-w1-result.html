Outcome

Delivered against the requirement. scripts/router-worker.sh spawn starts every worker in [router] worker_permission_mode as committed at the router checkout's HEAD (acceptEdits when the key is absent). --permission-mode may only narrow that mode (plan < acceptEdits < auto). A committed or requested mode outside plan|acceptEdits|auto, and a requested mode wider than the committed one, are refused before any run dir, lock, brief copy or start. Keel's .keel/config.toml sets worker_permission_mode = "auto". After review round 2 (owner ruling option A), every worker carries a file guard: a fail-closed PreToolUse hook. Its file tools edit only its worktree, never that worktree's .git or settings files, and read neither ~/.ssh nor ~/.claude/channels, judged on the resolved path. The launcher and the watchdog run no git in a worktree whose .git link a worker changed. The shell writes only the parts of ~/.cargo cargo writes. Every open point was built on its stated default (plan, open points 1-10), except open point 7, which was tightened by the router's decision in round 1. Not proven: whether the installed Claude Code accepts --permission-mode auto on a background launch, runs the guard hook from --settings under --bg, and lets cargo create its cache files under the narrowed allowWrite. The router's first spawn after the merge is the live check (open point 9).
