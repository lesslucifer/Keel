The problem

Small gaps from earlier epics wait in the backlog. Two hurt now. After an epic closes, pushing its branch is refused. And when a fix follows the epic review, you rewrite evidence by hand from a separate checkout. The rest are gaps in setup, the commit check and the review tool. This epic fixes them all, then writes the architecture doc.

W2 · The push and the walk know the epic close

In short: two walks judge a close commit as a plain commit and reject its epic-wide evidence. The push walk does it to the epic's last commit. The epic gate's walk does it to the archive commit once a review fix follows it. Both should judge such a commit by the epic evidence it carries.

  • New row B23: a plain commit already on main is not re-judged when its epic branch is pushed; it landed through a gated epic merge.
  • B23: a plain commit whose test and doc notes were written for the epic range is judged on those notes over that range (checks 1, 2 and 6, as the epic gate reads them), when it is the pushed tip. Review and sign-off stay at the merge into main (open point 8).
  • B20: in both walks, an inner commit that changes no code and carries epic-range notes (the archive commit) is judged the same way, not as a standalone commit. A commit that changes code stays a commit.
  • DEC-18 is amended: today it says only the epic gate's own tip is skipped.

Backlog B23 (new, owner 2026-11-13) and B20 · UC-GATE-3 (the walk) amended · DEC-18 amended.

Integration: in a scratch repo with a remote, after an epic merges into main, git push origin epic/<E> passes the real pre-push hook; an archive commit followed by a review fix passes keel verify-dod epic with no note rewritten; a code commit carrying epic notes is still red as a commit; a plain commit with no notes is still red. Unit: the rule that tells an epic-range note from a commit's.
